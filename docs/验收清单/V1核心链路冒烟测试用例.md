## 场景1：登录认证与Token刷新

**测试目标**：验证登录、Token获取、Token刷新全链路

### 步骤

| 序号 | 操作 | 预期结果 |
|------|------|---------|
| 1.1 | POST /v1/auth/login，body: `{"username":"admin","password":"Admin@123"}` | 返回200，包含accessToken、refreshToken、userInfo |
| 1.2 | 记录accessToken，GET /v1/users，Header: `Authorization: Bearer <accessToken>` | 返回200，用户列表 |
| 1.3 | POST /v1/auth/refresh，body: `{"refreshToken":"<refreshToken>"}` | 返回200，包含新的accessToken |
| 1.4 | 使用新accessToken重复步骤1.2 | 返回200 |
| 1.5 | POST /v1/auth/logout，Header: `Authorization: Bearer <accessToken>` | 返回200，旧Token失效 |
| 1.6 | 使用旧accessToken重复步骤1.2 | 返回401 |

### 验证命令

```bash
# 1. 登录
TOKEN=$(curl -s -X POST http://localhost:8081/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@123"}' | python -c "import sys,json; print(json.load(sys.stdin)['data']['accessToken'])")

# 2. 验证Token
curl -s http://localhost:8081/api/v1/users -H "Authorization: Bearer $TOKEN" | python -c "import sys,json; d=json.load(sys.stdin); print(f'用户数: {len(d[\"data\"][\"records\"])}')"

# 3. 登出
curl -s -X POST http://localhost:8081/api/v1/auth/logout -H "Authorization: Bearer $TOKEN"
```

### 通过标准
- ✅ 登录返回Token和用户信息
- ✅ Token可用于访问受保护接口
- ✅ RefreshToken可刷新Token
- ✅ 登出后旧Token失效

## 场景2：采购入库全流程（采购→库存→财务）

**测试目标**：验证采购订单创建→入库确认→库存增加→应付账款创建的完整链路

### 前置条件
- 已存在供应商（supplierId）
- 已存在物料（materialId）
- 已存在仓库（warehouseId）

### 步骤

| 序号 | 操作 | 预期结果 |
|------|------|---------|
| 2.1 | POST /v1/purchase-orders，创建采购订单（含物料明细） | 返回201，订单状态=1（待审核） |
| 2.2 | PUT /v1/purchase-orders/{orderId}/approve，审核通过 | 返回200，订单状态=2（已审核） |
| 2.3 | POST /v1/purchase-stockin，创建入库单（关联采购订单） | 返回201，入库单状态=1（待确认） |
| 2.4 | PUT /v1/purchase-stockin/{stockinId}/confirm，确认入库 | 返回200，入库单状态=2（已入库） |
| 2.5 | GET /v1/inventory?warehouseId={warehouseId}&materialId={materialId}，查询仓库库存 | 库存数量增加 |
| 2.6 | GET /v1/store-inventory/list?storeId={storeId}，查询门店库存 | 门店库存数量增加（新store_inventory表） |
| 2.7 | GET /v1/finance/payables?purchaseOrderId={orderId}，查询应付账款 | 返回201，存在应付记录 |

### 验证命令

```bash
# 创建采购订单
ORDER_ID=$(curl -s -X POST http://localhost:8081/api/v1/purchase-orders \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"supplierId":1,"warehouseId":1,"items":[{"materialId":1,"quantity":100,"unitPrice":10}]}' \
  | python -c "import sys,json; print(json.load(sys.stdin)['data']['orderId'])")

# 审核通过
curl -s -X PUT "http://localhost:8081/api/v1/purchase-orders/$ORDER_ID/approve" -H "Authorization: Bearer $TOKEN"

# 查询库存变化
curl -s "http://localhost:8081/api/v1/inventory?warehouseId=1&materialId=1" -H "Authorization: Bearer $TOKEN"
```

### 通过标准
- ✅ 采购订单创建并审核成功
- ✅ 入库确认后仓库库存增加
- ✅ 门店库存同步增加（store_inventory表）
- ✅ 应付账款自动创建

### 验证SQL

```sql
-- 验证store_inventory表存在且有数据
SELECT COUNT(*) FROM store_inventory;

-- 验证门店库存与仓库库存独立
SELECT si.store_id, si.material_name, si.current_stock as store_stock,
       i.warehouse_id, i.current_stock as warehouse_stock
FROM store_inventory si
LEFT JOIN inventory i ON si.material_id = i.material_id
WHERE si.store_id = '1';
```

- ✅ 门店库存查询、汇总、调整功能正常

| 4.4 | 验证考勤记录的schedule_plan_id、schedule_entry_id字段已填充 | 考勤记录关联排班信息 |

### 验证SQL

```sql
-- 验证排班发布后考勤记录自动创建
SELECT ar.attendance_id, ar.employee_id, ar.attendance_date,
       ar.schedule_plan_id, ar.schedule_entry_id, ar.status
FROM attendance_record ar
WHERE ar.schedule_plan_id IS NOT NULL
ORDER BY ar.create_time DESC
LIMIT 5;
```
