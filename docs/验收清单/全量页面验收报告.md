### 3.2 各轮次修复详情

#### 第 1 轮：JWT token 过大与权限基础（84→89，本会话之前已基本完成）

**问题：**
- admin JWT token 中存储 160+ 权限码，导致 token 长度达 9722 字符，超过 Tomcat 8KB header 限制，所有 API 返回 400 Bad Request

**修复：**
- 新建 [AdminPermissions.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/security/constants/AdminPermissions.java) 集中管理权限码，admin JWT 只存 `*` 通配符
- 修改 [SecurityUser.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/security/model/SecurityUser.java) `getAuthorities()` 在运行时将 `*` 展开为完整权限集
- 修改 [AuthServiceImpl.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/service/impl/AuthServiceImpl.java) 新增 `expandPermissionsForFrontend()`，前端响应仍返回完整权限列表

**效果：** JWT token 从 9722 字符降至 476 字符

---

#### 第 2 轮：@RequiresPermission 双权限路径（89→100，本会话之前已基本完成）

**问题：**
- `@RequiresPermission` 注解走自定义 PermissionVerifyService，而非 Spring Security 的 SecurityContext
- Redis 不可用时（开发环境默认禁用）catch 块直接返回空 set，导致 403
- PermissionAspect 中 `authentication.getName()` 返回 username（"admin"）而非 userId（"1"），Long.parseLong 失败

**修复：**
- 修改 [PermissionVerifyServiceImpl.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/service/impl/PermissionVerifyServiceImpl.java)：
  - catch 块改为降级到数据库直查
  - `loadPermissionsFromDatabase()` 添加 admin 用户 `*` 通配符
  - 新增 `isAdminUser()` 方法
- 修改 [PermissionAspect.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/aspect/PermissionAspect.java) 从 SecurityUser principal 提取 userId

- [RoleService.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/service/RoleService.java) `getRolePage()` status 参数 Integer → String
- [RoleServiceImpl.java](file:///p:/my-new-project/backend/src/main/java/com/foodtraceability/service/impl/RoleServiceImpl.java) `createRole()` 默认 status 改为 `"active"`，`getActiveRoles()` 调用 `findByStatus("active")`
