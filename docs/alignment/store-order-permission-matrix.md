# 门店运营 / 订单 / 销售 / 产品中心权限/角色矩阵

> 范围：门店档案、门店证件、门店库存、门店要货、待办任务、日结对账、桌台/排队、订单查询、退款管理、预约管理、菜品管理、套餐管理、分类管理
> 用途：梳理菜单级角色可见性、按钮级权限码、数据范围及权限缺失
> 生成日期：2026-07-30

---

## 矩阵字段说明

| 字段 | 说明 |
|-----|------|
| 模块/页面 | 功能模块及对应 Vue 文件 |
| 操作 | 用户可执行动作 |
| 按钮级权限码（v-permission） | 控件级权限标识，为空表示未做按钮级控制 |
| 菜单可见角色 | 在 `modules/*/menu.ts` 中配置的 `visibleRoles` |
| 推荐数据范围 | 动作应限制的数据可见范围 |
| 当前控制方式 | 菜单过滤 / 按钮权限 / 数据范围 / 未控制 |
| 实现状态 | 已实现 / 部分实现 / 未实现 |
| 备注 / 问题 | 用 `[待修复]` 标注权限缺失、角色覆盖不全、数据范围未隔离等问题 |

## 1. 角色与数据范围定义

### 1.1 系统角色（`src/stores/permission.ts`）

| 角色编码 | 角色名称 | 典型数据范围 |
|---------|---------|------------|
| `owner` | 超级管理员/老板 | 全部数据（`ALL`） |
| `admin` | 系统管理员 | 全部数据（`ALL`） |
| `ops_director` | 运营总监 | 本公司数据（`COMPANY`） |
| `region_manager` | 区域经理 | 本区域 / 指定门店（`STORES`） |
| `store_manager` | 店长/门店经理 | 本门店数据（`STORE`） |
| `team_leader` | 组长/团队负责人 | 本门店数据（`STORE`） |
| `employee` | 普通员工 | 仅本人数据（`SELF`） |
| `finance_director` | 财务总监 | 本公司数据（`COMPANY`） |
| `hr_director` | HR 总监 | 本公司数据（`COMPANY`） |

### 1.2 数据范围枚举（`src/stores/permission.ts`）

| 数据范围 | 含义 |
|---------|------|
| `ALL` | 全部数据 |
| `COMPANY` | 本公司数据 |
| `DEPARTMENT` | 本部门数据 |
| `STORE` | 本门店数据 |
| `STORES` | 指定门店 |
| `SELF` | 仅本人数据 |

## 7. [待修复] 权限矩阵问题汇总

1. `[待修复]` **订单管理、产品中心菜单未配置 `visibleRoles`**，当前所有登录角色均可见，不符合最小权限原则。
2. `[待修复]` **门店运营模块（store-ops）几乎所有操作列/工具栏按钮均未绑定 `v-permission`**，仅依赖菜单级角色过滤，存在越权风险。
3. `[待修复]` **门店证件续期费用审批流程使用前端内存角色模拟**（`currentRole`），未对接真实 RBAC，刷新即丢失权限上下文。
4. `[待修复]` **门店要货审核权限未区分角色**：当前店长/员工均可审核，应由采购部/店长/区域经理分级审批。
5. `[待修复]` **日结对账菜单对财务角色不可见**，但财务总监应至少拥有查看/审核本公司门店日结的权限。
6. `[待修复]` **订单查询/退款/预约页面无按钮级权限控制**，取消订单、审核退款、确认预约等敏感操作未做角色隔离。
7. `[待修复]` **退款审核应由财务/店长执行**，当前页面未限制，普通员工可点击审核按钮。
8. `[待修复]` **产品中心菜品管理未按规范绑定 `product:food:create/update/delete` 权限码**，套餐/分类管理也仅新增按钮绑定权限。
9. `[待修复]` **系统权限常量与实际页面权限码不一致**：`utils/permissions.ts` 中 `product:add/edit/delete` 与页面 `product:food:*/combo:*/category:*` 未对齐。
10. `[待修复]` **数据范围隔离未落实**：门店运营模块未按 `CURRENT_STORE_ID` 强制过滤（除部分 API 外），区域经理/店长/员工的数据边界不清晰。
11. `[待修复]` **开发环境 `v-permission` 降级为 `['*']`**，导致本地测试难以发现权限缺失，建议增加显式角色切换工具或测试模式。
12. `[待修复]` **缺少权限审计日志**：敏感操作（删除门店、审核退款、调整库存、删除菜品）未记录操作人、操作前/后状态及数据范围。
