# 第十轮：取单窗口重做为「一行一单」的高密度列表

> 反馈：取单窗口上次只是"改成能滚"，挂单多时仍难用——每张卡片 250px 高，一屏只能看 2 张，找单全靠滚。
> 目标：对齐行业收银系统（美团/客如云/KFC POS）的取单交互。
> 验证：九套 E2E 共 **149 项断言全绿**（含 1440×900 / 1280×720 / 深色三种场景）。

---

## 一、旧版为什么难用（量化）

| 指标 | 旧版 | 新版 |
|---|---|---|
| 单张挂单占高 | ≈250px（时间一行 + 3 个菜品标签 + 分隔线 + 金额） | **64px** |
| 一屏可见（900 高） | 2 张 | **7 张** |
| 一屏可见（720 高） | 1.5 张 | **5 张** |
| 找一张 3 小时前的挂单 | 反复滚动 + 逐卡读 | 输入菜品名/备注直接筛 |
| 键盘操作 | 无 | 上下键选择、Enter 取单 |

## 二、新结构

```
┌ 取单  12                                        ✕ ┐
├ 搜索菜品/备注                共 12 张 · 合计 ¥570.00 ┤  ← 工具条常驻
├──────────────────────────────────────────────────┤
│ 10:00   QA-链路复验菜×1 菜1×2        3 件  ¥20.00 › │  ← 64px 一行一单
│ 10-28   客人取钱                                    │
│ 11:07   菜1×1 菜2×2                 3 件  ¥25.00 › │
│ …                                                   │  ← 仅此区域滚动
├──────────────────────────────────────────────────┤
│ ↑↓ 选择 · Enter 取单        [取消] [清空全部]        │  ← 页脚常驻
└──────────────────────────────────────────────────┘
```

行内四段信息（按收银员扫读顺序）：**时间**（HH:mm + 月-日）→ **菜品摘要**（前 2 项 + 「+N」，有备注时第二行显示备注）→ **件数**（数量之和，不是"项数"）→ **金额**（17px DIN 数字）。

### 交互

- **搜索**：按菜品名或备注过滤，边打边筛；无结果时给"没有匹配的挂单"空态；
- **键盘流**：上下键移动高亮行（自动滚入视野），Enter 直接取单；搜索框内的 Enter 也走同一入口；
- **鼠标**：悬停即高亮（mouseenter 同步 activeIndex），点击取单；
- **安全**：仍保留"替换购物车？"二次确认 + 覆盖前自动挂起（第五轮的护栏没动）。
