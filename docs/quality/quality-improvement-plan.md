# 食品溯源系统质量提升计划

> 编制日期：2026-07-22
> 适用范围：采购、仓储、财务、人事、库存等核心模块
> 目标：将系统品质从"可用"提升至"成品交付"标准

---

## 一、背景与目标

### 1.1 当前现状

系统在核心业务流程（采购→到货→收货确认→库存入库）中存在数据中断、表结构不一致、前后端数据不匹配等问题，导致关键功能无法完整跑通。本次围绕"收货确认"和"采购计划"两条主线进行疏通后，已验证收货确认端到端链路可正常运行，但仍有大量模块存在类似隐患。

### 1.2 阶段目标

| 阶段 | 周期 | 目标 | 验收标准 |
|------|------|------|----------|
| 第一阶段：止血与核心链路贯通 | 1-2 周 | 修复阻断性 Bug，确保采购-仓储-库存主链路可完整运行 | E2E 脚本 100% 通过；P0 用例无阻断缺陷 |
| 第二阶段：模块功能补齐 | 2-3 周 | 各模块增删改查、状态流转、数据联动正常 | 模块测试清单通过率 ≥ 90% |
| 第三阶段：数据一致性与稳定性 | 2 周 | 统一数据库字段命名，消除实体-表结构差异 | Schema-Entity 差异扫描差异数为 0 |
| 第四阶段：验收与文档沉淀 | 1 周 | 形成可交付的测试报告、操作手册、运维手册 | 验收清单全部通过 |

### 4.3 验证要求

1. **每个 P0/P1 问题修复后必须提供**：问题根因、修改文件、验证命令/截图。
2. **回归测试**：修复问题后，必须重新执行该模块对应的 E2E/接口测试。
3. **每日站会**：同步问题清单进展，阻塞问题 2 小时内升级。

## 五、质量门禁

### 5.1 代码提交门禁

- `mvn compile` 通过
- `npm run build` 通过
- 无新增 TypeScript 类型错误
- 无未使用变量/导入
- 单元测试通过率 ≥ 80%

### 5.2 发布门禁

- P0/P1 问题全部关闭
- 核心 E2E 用例 100% 通过
- 数据库 Schema 与实体差异数为 0
- 安全扫描无高危漏洞
