# Project Context

这是本项目的持久化状态入口，用于跨会话恢复项目治理与执行上下文。

## 目的

本目录不保存聊天记录，也不保存过程性废话。只保存能够影响后续判断、执行或审查的稳定信息：
- 当前项目状态与边界
- 已确认的 Owner 决策
- Frozen Governance 状态
- 已完成实施及独立审查结果
- 当前限制、阻塞与待办
- 下一会话应从哪里继续

## 新会话启动顺序

1. 先阅读 `STATE.md`
2. 再按 STATE 中的“Primary References”读取对应项目治理文件
3. 只有在 STATE 明确指向后，才继续执行新任务
4. 不根据旧聊天内容自行恢复已被标记为 SUPERSEDED 的方案

## 当前状态文件规则

- `STATE.md` 是本目录唯一的当前状态源
- Git 历史负责保存状态演进，不额外维护冗长聊天日志
- 只记录“已经决定 / 已验证 / 当前待处理”的内容
- `PROVISIONAL` / `BLOCKED` / `PENDING` 等状态必须保留，不得为了简洁而抹平不确定性
- Frozen 文档的 substantive content 不得通过本目录自行改写

## 核心治理原则

> **决策有 ID、有状态、有证据、有 Owner、有溯源**

角色：
- `BUSINESS_OWNER`：Owner；提供业务判断并作正式决策
- `GPT`：主写手 / 主控；负责全局判断、治理记录、状态一致性、任务编排与最终裁决
- `OPEN`：执行代理；按 GPT 指令执行代码、测试、证据采集并报告
- `DeepSeek / DS`：独立 Reviewer；审查结构、证据与治理边界，不作为执行者
