# 前端数据对齐治理计划

> 目标：解决“对话框字段与表格列不匹配、数据不能继承流转、上下游关系不明”的问题，覆盖全部前端模块，不留边角。
> 治理顺序：**先做前端字段对齐 → 再梳理上下游状态机 → 最后校准后端/数据库。**

---

## 一、问题定义

### 1.1 当前现象

| 问题 | 影响 | 示例 |
|------|------|------|
| 表格有字段，对话框没有 | 用户无法查看/编辑完整信息 | 采购订单表格有“付款状态”，但部分表单未展示 |
| 对话框有字段，表格没有 | 列表页信息密度不足，无法快速判断 | 详情有“拒绝原因”，列表不可见 |
| 字段命名不一致 | 同一概念多个名字，增加理解成本 | “供应商” vs “供货商” vs “supplierName” |
| 状态映射不一致 | 同一状态在不同页面显示不同 | “待审核” vs “pending” vs “审批中” |
| 数据不回写/不刷新 | 操作后下游页面数据滞后 | 审批通过后列表未同步刷新 |
| 上下游 ID 不关联 | 无法跳转追溯 | 收货单未显示关联采购订单号 |

### 1.2 治理目标

1. **表格 ↔ 对话框字段一一对应**：表格中展示的字段，对话框必须能查看/编辑；对话框中的字段，表格应能反映关键摘要。
2. **字段命名统一**：同一业务概念在表格、对话框、API、数据库中名称一致。
3. **状态机统一**：同一状态在不同页面使用相同标签、颜色、操作按钮规则。
4. **操作后数据同步**：任何增删改操作后，相关列表/详情/统计立即刷新。
5. **上下游可跳转**：存在业务关联的单据之间可通过单号/链接跳转。

## 三、治理方法：四维对照法

对每个页面建立一张**字段血缘对照表**：

| 序号 | 字段名（中文） | 表格列 | 对话框字段 | API 字段 | 数据库字段 | 来源 | 回写 API | 可见角色 | 备注 |
|------|---------------|--------|-----------|----------|-----------|------|---------|---------|------|
| 1 | 订单编号 | ✅ | ✅ | `orderNo` | `purchase_order.order_no` | 后端生成 | 不可改 | 全部 | 唯一 |
| 2 | 供应商 | ✅ | ✅ | `supplierName` | `supplier_archive.name` | 供应商档案 | 选择带入 supplierId | 全部 | 关键关联 |
| 3 | 订单状态 | ✅ | ✅ | `status` | `purchase_order.status` | 状态机 | 操作后变更 | 全部 | StatusTag |
| 4 | 来源采购申请 | ✅ | ✅ | `requestNo` | `purchase_request.request_no` | 采购申请 | 转单时继承 | 全部 | 上游 ID |
| 5 | 总金额 | ✅ | ✅ | `totalAmount` | `purchase_order.total_amount` | 明细汇总 | 随明细重算 | 全部 | 元/分转换 |
| 6 | 拒绝原因 | ❌ | ✅ | `rejectReason` | `purchase_order.reject_reason` | 审批操作 | 审批驳回时写入 | 审批人/管理员 | 表格待补 |
| 7 | 删除操作 | ✅ | ❌ | - | - | - | DELETE /v1/... | OWNER/ADMIN | 列表有、详情无 |

### 3.1 检查规则

- **R1 必填对齐**：表格中展示的字段，对话框必须能查看；对话框中可编辑的字段，表格应能反映其值或状态。
- **R2 命名对齐**：同一字段在表格列标题、对话框 label、代码变量、API 字段中语义一致。
- **R3 类型对齐**：日期用日期选择器、金额显示两位小数、状态用 StatusTag、ID 不外露只显示名称。
- **R4 状态对齐**：状态枚举、标签文字、颜色、可执行操作在列表页和详情页完全一致。
- **R5 操作对齐**：列表页操作按钮与详情页操作按钮权限、可见性、触发逻辑一致。
- **R6 刷新对齐**：任何写操作成功后，必须刷新当前列表、当前详情、相关统计卡片。
- **R7 权限/角色对齐**：同一页面/操作在不同角色（OWNER / STORE_MANAGER / HR_STAFF / STAFF / ADMIN）下的可见性、可操作性完全一致；列表、详情、按钮、路由守卫使用同一套权限判定逻辑。

### 3.2 权限 / 角色定位对齐

每个字段、每个操作都需要回答三个问题：

1. **谁可见**：字段/按钮对哪些角色可见？是否与表格列可见性一致？
2. **谁可操作**：按钮在哪些角色下可用？列表页与详情页是否一致？
3. **数据权限**：角色是只能看自己门店/部门的数据，还是可以跨门店/跨域查看？

**权限矩阵模板**：

| 操作 | OWNER | ADMIN | STORE_MANAGER | HR_STAFF | STAFF | 数据范围 | 前端实现方式 |
|------|-------|-------|---------------|----------|-------|---------|-------------|
| 查看采购订单 | ✅ | ✅ | ✅ | ❌ | ❌ | 全部门店/本门店 | `v-permission` / 路由守卫 |
| 创建采购订单 | ✅ | ✅ | ✅ | ❌ | ❌ | 本门店 | `v-permission` |
| 审批采购订单 | ✅ | ✅ | ❌ | ❌ | ❌ | 全部 | `v-permission` + 后端校验 |
| 删除采购订单 | ✅ | ❌ | ❌ | ❌ | ❌ | 全部 | `v-permission` |

**常见权限不一致问题**：

- 列表页有“删除”按钮，详情页没有；
- 路由守卫允许进入页面，但页面内按钮全部被隐藏；
- HR_STAFF 在 A 页面可操作，在 B 页面同名操作被禁用；
- 数据范围不一致：列表页显示全部数据，详情页因接口权限报错。

## 四、执行顺序

### Phase 1：采购管理链路（优先级最高）

采购链路是核心业务流程，且当前正在优化采购订单详情设计，优先对齐。

执行顺序：

1. **采购申请**（PurchaseRequest）
2. **采购计划**（PurchasePlan）
3. **采购订单**（PurchaseOrder）【含链路追溯对话框】
4. **采购收货**（PurchaseStockin）
5. **采购入库**（与仓储库存关联）
6. **采购结算**（PurchaseSettlement）
7. **供应商档案**（SupplierArchive）
8. **商品档案/物资分类/物资需求**（基础数据）

> 注：原独立页面「采购链路追溯」已改造为从采购订单页直接打开的 `PurchaseTraceDialog.vue` 对话框，不再作为单独路由页面存在。

### Phase 2：门店运营链路

1. 门店档案 → 桌台使用 → 排队历史 → 门店库存 → 门店物资申请
2. 班次管理 → 门店招聘 → 门店证件 → 门店待办
3. 门店日结

### Phase 3：订单/销售链路

1. 订单查询 → 订单统计 → 订单退款 → 订单预订
2. 产品中心：菜品管理、分类管理、套餐管理、库存、定价、成本分析

### Phase 4：仓储/库存链路

1. 仓储总览 → 门店库存 → 入库 → 出库 → 调拨 → 盘点 → 报损 → 库存预警 → 库存追溯

### Phase 5：人事/资产/设备/会员/系统/溯源

按模块逐个完成。
