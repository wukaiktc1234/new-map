## 二、排班管理模块优化规格

### 2.1 排班方案操作列优化

**文件**: `src/views/Schedule/SchedulePlans.vue`

**问题**: 操作列采用2×2网格布局(`.action-grid`)，按钮排列为3行（第二行、第三行各一个按钮），视觉效果差。

**解决方案**: 改为水平平铺排列，所有按钮在同一行展示。

**实现规格**:

```
修改前：
  操作列 min-width: 180px
  按钮布局：2×2网格（.action-grid CSS类）
  视觉效果：3行排列，第二/三行各一个按钮

修改后：
  操作列 min-width: 220px
  按钮布局：水平平铺（删除.action-grid CSS类）
  视觉效果：所有按钮在同一行，间距一致
```

**操作列按钮规范**:
- 使用 `<el-button link type="primary" size="small">` 纯文字按钮
- 禁止使用图标+文字组合
- 禁止使用 `el-button text` 类型（text是旧版API）
- 按钮顺序：查看 → 编辑 → 发布 → 删除（按操作频率排列）

### 2.2 排班模板下载格式改造

**文件**: `src/utils/scheduleExcel.ts`

**问题**: 原模板为长格式（每行一条记录：日期+员工+班次），与排班表格视图（员工×日期矩阵）不一致，用户理解成本高。

**解决方案**: 改为矩阵格式，与表格视图完全一致。

**矩阵模板规格**:

```
Sheet 1: 排班数据
  ┌──────────┬──────┬──────┬──────┬─────┬──────┐
  │ 员工姓名  │ 1日  │ 2日  │ 3日  │ ... │ 31日 │
  ├──────────┼──────┼──────┼──────┼─────┼──────┤
  │ 张三     │ 早   │ 全   │ 休   │ ... │ 中   │
  │ 李四     │ 中   │ 休   │ 早   │ ... │ 全   │
  └──────────┴──────┴──────┴──────┴─────┴──────┘

  填写方式（三种均支持）：
    缩写：早/中/晚/全/休
    编码：morning/noon/evening/full/off
    全名：早班/中班/晚班/全天班/休息

Sheet 2: 班次对照表
  ┌──────┬────────┬──────┬──────┐
  │ 编码  │ 名称   │ 开始  │ 结束  │
  ├──────┼────────┼──────┼──────┤
  │ morning │ 早班  │ 06:00 │ 14:00 │
  │ noon    │ 中班  │ 11:00 │ 19:00 │
  │ evening │ 晚班  │ 16:00 │ 24:00 │
  │ full    │ 全天班 │ 06:00 │ 22:00 │
  │ off     │ 休息  │ -     │ -     │
  └──────┴────────┴──────┴──────┘

Sheet 3: 填写说明
  1. 每个单元格填写班次缩写/编码/全名均可
  2. 不填或填"休"表示休息
  3. 不识别的内容将报错
  4. 请勿修改表头和员工姓名列
```

**函数签名**:

```typescript

  shiftTypes?: ShiftTypeDef[],
  yearMonth?: string,        // 格式 YYYY-MM，默认当前月
  employeeNames?: string[]   // 员工姓名列表
): void
```

**调用方式**（ScheduleMonthCalendar.vue）:


### 2.3 排班模板导入支持矩阵格式

**文件**: `src/utils/scheduleExcel.ts`

**功能**: 导入时自动检测格式（矩阵/长格式），分别解析。

**格式检测逻辑** (`detectMatrixFormat()`):

```typescript
function detectMatrixFormat(sheet: XLSX.WorkSheet): boolean {
  // 矩阵格式特征：
  // 1. 第一行表头包含"员工姓名"和"1日"/"1号"等日期列
  // 2. 数据行第一列为员工姓名，后续列为班次
  // 3. 列数 = 1(姓名) + 当月天数
  const header = XLSX.utils.sheet_to_json(sheet, { header: 1 })[0] as string[]
  const hasEmployeeCol = header[0]?.includes('员工') || header[0]?.includes('姓名')
  const hasDateCols = header.some(h => /^\d{1,2}[日号]$/.test(String(h).trim()))
  return hasEmployeeCol && hasDateCols
}
```

**矩阵格式解析** (`parseMatrixFormat()`):

```typescript
function parseMatrixFormat(
  sheet: XLSX.WorkSheet,
  yearMonth: string
): ScheduleImportRow[] {
  // 1. 解析表头获取日期列映射
  // 2. 逐行读取员工姓名
  // 3. 逐列读取班次值（支持缩写/编码/全名三种格式）
  // 4. 班次值映射：缩写→编码、全名→编码
  // 5. 生成标准 ScheduleImportRow 数组
}
```

**长格式兼容** (`parseLongFormat()`):

保留原有长格式解析逻辑，确保向后兼容。

**函数签名**:


### 2.6 排班打印仅打印表格内容

**文件**: `src/views/store-ops/ShiftManagement.vue`

**问题**: `window.print()` 会打印整个页面，包括导航栏、侧边栏等无关内容。

**解决方案**: iframe打印方案。

```typescript
function handlePrint() {
  const tableEl = tableRef.value?.$el
  if (!tableEl) return

  const iframe = document.createElement('iframe')
  iframe.style.position = 'fixed'
  iframe.style.right = '0'
  iframe.style.bottom = '0'
  iframe.style.width = '0'
  iframe.style.height = '0'
  iframe.style.border = 'none'
  document.body.appendChild(iframe)

  const doc = iframe.contentDocument
  if (!doc) return

  // 复制样式
  const styles = document.querySelectorAll('style, link[rel="stylesheet"]')
  styles.forEach(style => doc.head.appendChild(style.cloneNode(true)))

  // 写入表格内容
  doc.body.innerHTML = tableEl.outerHTML

  // 打印增强样式
  const printStyle = doc.createElement('style')
  printStyle.textContent = `
    @page { size: landscape; margin: 10mm; }
    body { margin: 0; padding: 10px; }
    .el-table { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
  `
  doc.head.appendChild(printStyle)

  iframe.contentWindow?.focus()
  iframe.contentWindow?.print()

  // 清理
  setTimeout(() => document.body.removeChild(iframe), 1000)
}
```

### 2.11 换班管理拖拽修复

**文件**: `src/views/Schedule/ScheduleSwapManagement.vue`

**问题**: 表格鼠标指针已变成小手掌，但无法拖拽水平移动。

**根因**: 直接操作DOM `scrollLeft` 属性无法同步 el-table 的固定列（fixed列）滚动位置。

**解决方案**: 使用 el-table 官方API `setScrollLeft()`。

```typescript
// 修改前（错误）
function handleDragMove(e: MouseEvent) {
  const tableBody = tableRef.value?.$el.querySelector('.el-table__body-wrapper')
  if (tableBody) {
    tableBody.scrollLeft = newScrollLeft  // 仅滚动主表体，fixed列不同步
  }
}

// 修改后（正确）
function handleDragMove(e: MouseEvent) {
  tableRef.value?.setScrollLeft(newScrollLeft)  // 主表体和fixed列同步滚动
}
```

**关键认知**: el-table 的固定列（fixed）是独立的DOM结构，直接操作 `scrollLeft` 只影响主表体。`setScrollLeft()` 是官方API，确保主表体和固定列同步。

```typescript
function getHolidayInfo(date: string): HolidayInfo | null {
  const year = date.substring(0, 4)

  // 优先级1：政府公布日期表（权威来源）
  const govHolidays = GOVERNMENT_HOLIDAY_DATES[year]
  if (govHolidays) {
    const found = govHolidays.find(h => h.date === date)
    if (found) return found
  }

  // 优先级2：农历动态计算（兜底，可能存在偏差）
  return calculateHolidayFromLunar(date)
}
```

**维护规则**:
- 每年国务院公布放假安排后，必须更新 `GOVERNMENT_HOLIDAY_DATES`
- 政府日期表包含调休安排（如周末上班），农历计算无法覆盖
- 新增年份时，只需在 `GOVERNMENT_HOLIDAY_DATES` 中添加对应年份数据

### 4.1 采购闭环流程

#### 4.1.1 完整链路

```
需求产生 → 采购申请(PR) → 采购计划 → 采购订单(PO) → [合同签订] → 收货/入库(GR) → 对账 → 发票校验 → 付款结算 → 绩效评估
```

#### 4.1.2 各环节关联关系

| 环节 | 上游输入 | 下游输出 | 关联方式 |
|------|---------|---------|---------|
| 采购申请 | 店铺/部门物资需求提报 | 审批后的需求清单 | PR编号关联PO |
| 采购计划 | 多个PR汇总 | 计划明细 | 合并相同物料需求 |
| 采购订单 | 采购计划+供应商选择 | 正式PO | PO编号贯穿收货/结算 |
| 合同 | 寻源结果/框架协议 | 合同编号 | 合同关联合同下的所有PO |
| 收货 | PO+送货单 | 入库单(GRN) | GRN关联PO行项目 |
| 对账 | GRN+退货单 | 对账确认单 | 按周期汇总 |
| 发票校验 | PO+GRN+发票 | 校验结果 | 三单匹配 |
| 付款 | 校验通过的发票 | 付款凭证 | 付款关联发票 |

#### 4.1.3 必须环节 vs 可选环节

**必须环节（任何规模企业）**：
- 采购申请 → 采购订单 → 收货入库 → 付款

**可选环节（按企业规模/场景）**：

| 环节 | 小型餐饮(1-3店) | 中型餐饮(4-20店) | 连锁餐饮(20+店) |
|------|:---:|:---:|:---:|
| 采购计划 | 可省略 | 建议启用 | 必须启用 |
| 寻源/比价 | 口头比价 | 至少3家比价 | 正式招投标 |
| 合同管理 | 小额免合同 | 核心物料签合同 | 全部签合同 |
| 对账环节 | 随货对账 | 月度对账 | SRM在线对账 |
| 发票校验 | 手工校验 | 系统辅助三单匹配 | 自动三单匹配+容差 |

### 4.3 供应商档案（新增核心实体）

#### 4.3.1 为什么需要供应商档案

供应商是采购的核心实体。当前系统中供应商信息分散在各页面的mock数据中（仅存储supplierId+supplierName），缺少统一的供应商管理。导致：

#### 4.3.3 供应商评估体系

**评估维度与权重**：

| 评估维度 | 权重 | 核心指标 | 数据来源 |
|---------|------|---------|---------|
| 质量 | 30% | 商品合格率、退货率、质检不合格次数 | 收货质检记录 |
| 交期 | 25% | 准时交货率、平均交货周期 | 订单vs收货时间 |
| 价格 | 25% | 价格竞争力（vs市场均价）、价格稳定性 | 历史采购价格库 |
| 服务 | 20% | 响应速度、问题解决率、配合度 | 人工评分+系统记录 |

**评估结果处理**：
- A级（≥90分）：战略供应商，优先合作
- B级（75-89分）：合格供应商，正常合作
- C级（60-74分）：需改进，减少份额
- D级（<60分）：淘汰，冻结新订单

**评估周期**：月度自动评分 + 季度综合评估 + 年度战略评审

## 五、全局修复规格

### 5.1 下拉菜单定位偏移修复（核心修复）

**涉及文件**:
- `src/plugins/fixed-popper.ts`（新建）
- `src/main.ts`（修改：注册插件）
- `src/styles/global/_base.scss`（修改：移除CSS hack）

#### 5.1.1 问题描述

Element Plus 默认使用 Popper.js 的 `strategy: 'absolute'`，当页面存在自定义滚动容器时，下拉菜单在滚动过程中会与触发元素分离错位。

#### 5.1.2 修复历程

**第1轮尝试（CSS hack — 失败）**:

```css
/* _base.scss 中添加 */
.el-popper {
  position: fixed !important;
}
```

**失败原因**：Popper.js 内部按 `strategy: 'absolute'` 计算 top/left 坐标（相对文档），CSS 强制 `position: fixed` 后，这些坐标变成了相对 viewport 的值，两者差 `window.scrollY`，导致下拉菜单跟随背景页面滚动。

**第2轮尝试（Vue插件方案 — 成功）**:

通过 Vue 插件全局包装 Element Plus 组件，正确注入 `popperOptions: { strategy: 'fixed' }`，让 Popper.js 在 fixed 模式下正确计算坐标。

#### 5.1.3 最终方案

**插件代码** (`src/plugins/fixed-popper.ts`):

```typescript
import type { App, DefineComponent } from 'vue'
import { defineComponent, h } from 'vue'

/** 全局固定定位 Popper 配置 */
export const FIXED_POPPER_OPTIONS = {
  strategy: 'fixed' as const,
  modifiers: [
    { name: 'flip', options: { fallbackPlacements: ['bottom-start', 'top-start'] as const } },
    { name: 'preventOverflow', options: { boundary: 'viewport' as const } },
  ],
}

/**
 * 包装 Element Plus 组件，自动注入 fixed popperOptions
 * 保留组件原有功能，仅默认添加 strategy: 'fixed'
 * 如果使用时显式传入 popperOptions，会与默认值合并（显式传入优先）
 */
function withFixedPopper(WrappedComponent: DefineComponent<Record<string, unknown>>, componentName: string) {
  return defineComponent({
    name: `Fixed${componentName}`,
    inheritAttrs: false,
    setup(_props, { attrs, slots }) {
      return () =>
        h(WrappedComponent, {
          ...attrs,
          popperOptions: {
            ...FIXED_POPPER_OPTIONS,
            ...(attrs.popperOptions as Record<string, unknown> || {}),
          },
        }, slots)
    },
  })
}

/**
 * 安装插件：全局替换以下组件使其默认使用 strategy: 'fixed'
 * - ElSelect / ElSelectV2
 * - ElDatePicker / ElTimePicker
 * - ElCascader
 */
export default {
  install(app: App) {
    const componentsToWrap = [
      'ElSelect',
      'ElSelectV2',
      'ElDatePicker',
      'ElTimePicker',
      'ElCascader',
    ]

    for (const name of componentsToWrap) {
      const original = app.component(name)
      if (original) {
        app.component(name, withFixedPopper(original as DefineComponent<Record<string, unknown>>, name))
      }
    }
  },
}
```

**注册方式** (`src/main.ts`):

```typescript
import fixedPopperPlugin from './plugins/fixed-popper'

// 在 Element Plus 注册之后注册
app.use(ElementPlus, { locale: zhCn, lockScroll: false })
app.use(fixedPopperPlugin)  // 全局 Popper fixed 定位策略
```

#### 5.1.4 关键认知

| 方案 | 原理 | 结果 |
|------|------|------|
| CSS `position: fixed !important` | CSS层面强制覆盖定位方式 | **失败** — Popper.js内部按absolute计算坐标，CSS强制fixed后坐标不匹配 |
| Vue插件注入 `strategy: 'fixed'` | 让Popper.js在fixed模式下正确计算坐标 | **成功** — 坐标计算与定位方式一致 |

**禁止事项**：
- **禁止**通过CSS `position: fixed !important` 强制覆盖Popper定位
- **禁止**移除 `fixed-popper.ts` 插件或其注册
- 如需为特定组件自定义popperOptions，显式传入即可，会与默认值合并

### 5.2 overflow-x 裁剪修复

**涉及文件**:
- `src/styles/global/_modern-page.scss`
- `src/views/product/Inventory.vue`
- `src/views/product/FoodManagement.vue`

**问题**: `overflow-x: hidden` 会隐式创建滚动容器，Popper.js 为其添加 scroll 监听导致频繁重算定位。

**解决方案**: `overflow-x: hidden` → `overflow-x: clip`

**原理**:
- `overflow-x: hidden/auto`: 隐式创建滚动容器，Popper.js 添加 scroll 监听
- `overflow-x: clip`: 裁剪溢出内容但不创建滚动容器，Popper.js 不会添加 scroll 监听

**兼容性**: Chrome 90+, Firefox 81+, Safari 16+, Edge 90+

### 5.3 侧边栏过渡优化

**文件**: `src/components/layout/SidebarMenu.vue`

**问题**: `transition: all 0.4s` 导致侧边栏折叠/展开时，所有CSS属性都参与过渡动画，可能产生闪烁。

**解决方案**: `transition: all 0.4s` → `transition: width 0.4s`

**原理**: 仅对 `width` 属性应用过渡动画，避免其他属性（如 background、border 等）参与过渡。

## 六、审批流程系统设计

### 6.1 设计原则

1. **与权限模板联动**：审批流程与权限中心的4个模板（大型连锁/标准连锁/集中式单店/完全自定义）关联，不同模板对应不同的默认审批规则
2. **用户可自定义**：提供自定义空间，用户的审批流程不是千篇一律的
3. **业务-审批分离**：审批引擎只操作流程相关字段，不侵入业务逻辑
4. **条件路由**：审批路径由条件决定（金额/类型/部门），不硬编码

### 6.2 数据结构

```typescript
/** 审批流程定义 */
interface ApprovalWorkflow {
  workflowId: string
  workflowName: string             // 如"采购申请审批"
  businessType: string             // purchase_request | purchase_order | contract | payment
  templateCode: string             // 关联权限模板：enterprise-chain | standard-chain | centralized-single | custom
  enabled: boolean
  nodes: ApprovalNode[]            // 审批节点列表（有序）
  conditions: ApprovalCondition[]  // 条件分支规则
}

/** 审批节点 */
interface ApprovalNode {
  nodeId: string
  nodeName: string                 // 如"店长审批"
  nodeOrder: number                // 顺序：1=一级, 2=二级...
  approverType: 'role' | 'superior' | 'form_field' | 'specific_user'
  approverValue: string            // 角色代码/上级关系/表单字段/用户ID
  approveMode: 'or' | 'and'       // 或签(任一通过)/会签(全部通过)
  timeoutHours: number             // 超时时间（小时），0=不限
  timeoutAction: 'auto_pass' | 'auto_reject' | 'escalate'  // 超时处理
}

/** 条件分支 */
interface ApprovalCondition {
  conditionId: string
  field: string                    // 如 'totalAmount' | 'purchaseType' | 'supplierLevel'
  operator: 'lt' | 'gte' | 'eq' | 'in'
  value: number | string | string[]
  targetNodeIds: string[]          // 满足条件时跳转到哪些节点
}

/** 审批记录 */
interface ApprovalAuditLog {
  logId: string
  workflowId: string
  businessId: string               // 业务单据ID
  businessType: string
  nodeId: string
  nodeName: string
  approverType: string
  approverName: string
  action: 'approve' | 'reject' | 'withdraw' | 'delegate' | 'timeout'
  opinion: string                  // 审批意见
  operateTime: string
}
```

## 七、技术实现规范

### 7.1 组件规范

- 状态字段必须使用 `<StatusTag :status="xxx" />`，禁止使用 `el-tag`
- 操作列按钮必须使用 `<el-button link type="primary/danger" size="small">` 纯文字按钮
- 金额以元为单位展示，使用 `formatAmount()` 格式化为两位小数
- 禁止硬编码颜色值，使用 `--fts-*` CSS变量
- 禁止使用 `!important`（el-table内联样式覆盖等特殊场景除外，需注释说明）
- 使用 `useStandardPage` composable 管理分页和搜索
- 使用 DataConverter 在API边界处做状态映射，禁止在组件中直接映射
- 每个页面代码行数控制在500行以内（预警线），硬上限1500行

### 7.2 Popper定位策略

全局通过 `fixed-popper.ts` 插件配置 `strategy: 'fixed'`，确保下拉菜单在页面滚动时不会偏移。

**禁止**：
- 通过CSS `position: fixed !important` 强制覆盖
- 移除 `fixed-popper.ts` 插件或其注册

**允许**：
- 为特定组件显式传入 `popperOptions`，会与默认值合并

### 7.3 节假日日期表

节假日使用政府公布日期表（`GOVERNMENT_HOLIDAY_DATES`）优先于农历动态计算，确保日期准确。

**维护规则**：
- 每年国务院公布放假安排后，必须更新 `GOVERNMENT_HOLIDAY_DATES`
- 政府日期表包含调休安排，农历计算无法覆盖
- 新增年份只需在表中添加对应年份数据

### 7.4 el-table滚动操作

**禁止**直接操作DOM `scrollLeft` 属性来滚动el-table，必须使用官方API：

```typescript
// 禁止
tableBody.scrollLeft = newValue

// 正确
tableRef.value?.setScrollLeft(newValue)
```

**原因**: el-table的固定列（fixed）是独立的DOM结构，直接操作`scrollLeft`只影响主表体，`setScrollLeft()`确保主表体和固定列同步。

### 7.5 overflow-x处理

在需要裁剪水平溢出但不创建滚动容器的场景，使用 `overflow-x: clip` 而非 `overflow-x: hidden`。

**原因**: `hidden/auto` 会隐式创建滚动容器，Popper.js为其添加scroll监听导致频繁重算定位。`clip` 裁剪溢出但不创建滚动容器。

### 7.6 打印方案

- 使用iframe打印方案，仅打印目标表格内容
- 打印样式必须包含 `-webkit-print-color-adjust: exact`
- 使用 `@page { size: landscape }` 设置横向打印
- el-table打印需设置 `border-collapse: separate` 和 `table-layout: auto`

### 7.7 排班模板格式

- 下载模板：矩阵格式（员工×日期），与表格视图一致
- 导入模板：自动检测格式（矩阵/长格式），矩阵格式必须传入yearMonth参数
- 班次填写支持三种方式：缩写（早/中/晚/全/休）、编码（morning/noon/evening/full/off）、全名（早班/中班/晚班/全天班/休息）

## 十、已知问题与约束

### 10.1 当前约束

1. **纯前端Mock**：所有数据均为前端Mock，无真实后端API。后端接入后需替换所有API调用
2. **供应商信息分散**：各页面Mock数据中供应商信息独立维护，无统一来源。供应商档案建立后需统一
3. **金额单位**：前端以元为单位展示，后端接入后需按项目规范以分为单位存储，通过DataConverter转换
4. **采购订单目录不一致**：PurchaseOrder.vue位于views/product/而非views/purchase/
5. **排班打印边框**：31日的日历仍可能出现右侧边框截断，需持续关注
6. **节假日数据维护**：GOVERNMENT_HOLIDAY_DATES需要每年更新，否则会回退到农历计算（可能有偏差）
7. **证件管理审批未统一**：StoreCertificate.vue使用自建审批流程，未对接ApprovalDialog组件，需第四阶段统一
8. **三单匹配容差为前端硬编码**：容差配置（数量±2%/±5件，单价±1%/±5元）写在前端代码中，后端接入后应改为后端配置
9. **供应商评估数据为Mock**：4维度评分数据为前端硬编码，后端接入后需实现自动评分算法

## 十一、设计决策记录

> 以下记录了所有关键设计决策，包括选择方案、备选方案和决策理由。后续开发不得随意推翻这些决策，如需变更必须先修改本文档并经用户确认。

### 11.1 排班管理

| 决策 | 选择 | 备选方案 | 理由 |
|------|------|---------|------|
| 排班日历窄屏 | 水平滚动 | 缩小日历 | 7列日历缩小后内容不可读 |
| 排班模板格式 | 矩阵格式 | 长格式 | 与表格视图一致，用户理解成本低 |
| 排班方案操作列 | 水平平铺 | 2×2网格 | 网格布局导致3行排列，视觉效果差 |
| 排班打印方案 | iframe打印 | window.print() | window.print()打印整个页面含导航栏 |
| 换班拖拽滚动 | setScrollLeft() | DOM scrollLeft | el-table固定列是独立DOM，直接操作scrollLeft不同步 |
| 节假日数据 | 政府公布日期表 | 农历动态计算 | 农历算法有偏差，政府公告是权威来源 |

### 11.2 采购管理

| 决策 | 选择 | 备选方案 | 理由 |
|------|------|---------|------|
| 临时物料处理 | 快速通道 | 严格申请流程 | 餐饮行业新品频出，严格流程拖慢效率 |
| 审批系统架构 | 动态审批矩阵 | BPM引擎 | 轻量级，适合中小餐饮，不引入重型依赖 |
| 收货方式 | 配置项 | 硬编码 | 不同企业收货流程不同，必须可配置 |
| 付款权限 | 采购提交+财务审核 | 采购直接打款 | 采购模块不应有直接打款权限 |
| 供应商评估 | 多维度加权评分 | 单一评分 | 质量/交期/价格/服务四维度更全面 |
| 三单匹配 | 容差机制 | 严格匹配 | 实际业务中存在合理差异，严格匹配会导致大量人工介入 |
| 电子合同安全 | 自建CA+时间戳+区块链存证 | 仅简单签署 | 电子合同法律效力依赖三重存证，简单签署不合规 |
| 采购动线 | 物资需求提报→采购申请→订单 | 合并为单一入口 | 门店员工与采购部角色不同，分离入口更清晰 |
| 采购报表分析 | 独立弹窗+按钮入口 | 页面内嵌 | 报表页面以数据表格为主，图表分析按需打开避免页面臃肿 |
| 详情弹窗宽度 | 860-960px | 720px统一 | B端管理工具含大量数据，宽弹窗提升可读性 |

### 11.3 全局修复

| 决策 | 选择 | 备选方案 | 理由 |
|------|------|---------|------|
| Popper定位 | strategy:fixed插件 | CSS hack | CSS强制fixed后坐标不匹配，必须通过Popper.js选项配置 |
| overflow-x | clip | hidden | hidden创建滚动容器导致Popper频繁重算 |
| 侧边栏过渡 | width only | all | all导致非目标属性参与过渡产生闪烁 |

### 11.4 审批流程

| 决策 | 选择 | 备选方案 | 理由 |
|------|------|---------|------|
| 审批与权限模板 | 联动+可自定义 | 完全独立 | 4个模板提供合理默认值，自定义满足差异化需求 |
| 审批人类型 | 多种(角色/上级/表单字段/指定人) | 仅角色 | 不同场景需要不同的审批人确定方式 |
| 条件路由 | 数据驱动 | 硬编码 | 金额/类型/部门等条件可能变化，数据驱动更灵活 |
| 超时处理 | 可配置(自动通过/驳回/升级) | 仅升级 | 不同审批节点对超时的容忍度不同 |
