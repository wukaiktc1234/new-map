# 组件与样式规范

## 一、组件设计原则

### 1.1 单一职责

每个组件只负责一个明确的功能，避免将多个不相关的逻辑混合在同一个组件中。

- 页面级组件仅负责布局和组件组合，不包含具体业务逻辑
- 功能组件围绕单一功能点进行封装
- 当组件承担的职责超过两个时，应考虑拆分

### 1.2 高内聚低耦合

相关代码紧密组织，不相关代码分离。

- 组件内部的模板、逻辑、样式保持高度相关
- 组件之间通过明确的 Props 和 Events 通信，避免直接操作其他组件内部状态
- 跨组件状态共享通过 Pinia Store 管理，而非组件间直接引用

### 1.3 可复用性

提取通用 UI 元素为独立组件，避免重复编写相似代码。

- 识别在多个页面中重复出现的 UI 模式，提取为公共组件
- 公共组件通过 Props 配置差异化行为，通过 Events 暴露交互
- 公共组件按层级放置于 `src/components/core/`（基础层）和 `src/components/business/`（业务层）目录

### 1.4 可维护性

代码结构清晰，易于理解和修改。

- 组件文件结构统一：`<template>` → `<script setup>` → `<style scoped>`
- 为复杂逻辑添加清晰的中文注释
- 使用 TypeScript 严格模式，确保类型安全
- 遵循统一的命名规范和文件组织方式

## 二、组件命名规范

### 2.1 命名规则总览

| 类型 | 规范 | 示例 |
|------|------|------|
| 组件名 | PascalCase | `FinanceReportHeader` |
| 文件名 | 与组件名一致 | `FinanceReportHeader.vue` |
| 状态管理 | kebab-case | `finance-report.ts` |
| 工具函数 | kebab-case | `report-form.ts` |
| CSS 类名 | kebab-case | `content-card` |

### 2.2 组件名构成

组件名由业务域和功能描述两部分组成，采用 `{Domain}{Function}` 的格式：

```
FinanceReportHeader   → 域: Finance, 功能: ReportHeader
HREmployeeList        → 域: HR, 功能: EmployeeList
TraceFoodDetail       → 域: Trace, 功能: FoodDetail
```

### 2.3 文件名与组件名对应关系

文件名必须与组件名完全一致，便于自动导入和代码检索：

```
FinanceReportHeader.vue → 导出组件 FinanceReportHeader
HREmployeeList.vue      → 导出组件 HREmployeeList
```

## 三、公共组件清单

公共组件按层级放置：
- **core层**（`src/components/core/`）：与业务无关的纯UI组件，如 StatusTag, StatCard, PageHeader, DataTable, ContentCard, StatusSwitch, SearchPanel, Breadcrumb, EmptyState, Skeleton, Toolbar, StandardPage, TableActionBar
- **business层**（`src/components/business/`）：跨模块共享的业务组件，如 CollapsibleSearchPanel, ActionButtons, ApplicantDetailDrawer

### 3.1 组件列表

| 组件名 | 功能说明 | 典型用法 |
|--------|---------|---------|
| `PageHeader` | 页面标题栏，包含标题、描述、操作按钮区域 | 所有页面的顶部标题区域 |
| `ContentCard` | 统一内容卡片容器，提供一致的卡片外观 | 页面内容区块的包裹容器 |
| `DataTable` | 数据表格，封装分页、排序功能 | 数据列表展示（禁止直接使用el-table） |
| `SearchPanel` | 通用搜索面板，封装搜索/重置逻辑 | 列表页搜索区域 |
| `CollapsibleSearchPanel` | 可折叠高级搜索面板（business层） | 需要展开/收起的高级搜索场景 |
| `StatusTag` | 状态标签，支持28种业务状态自动映射 | 状态字段显示（禁止使用el-tag显示状态） |
| `StatCard` | 统计卡片，展示关键指标 | 数据概览区域 |
| `StandardPage` | 标准页面布局容器 | 统一页面结构 |
| `Toolbar` | 工具栏组件 | 页面操作区域 |
| `TableActionBar` | 表格操作栏 | 表格上方操作按钮区域 |
| `Breadcrumb` | 面包屑导航 | 页面导航路径 |
| `EmptyState` | 空状态占位，无数据时展示 | 列表为空、详情无数据等场景 |
| `Skeleton` | 骨架屏加载 | 数据加载中的占位展示 |
| `StatusSwitch` | 状态开关 | 启用/禁用状态切换 |

### 3.2 组件导入方式

core层和business层组件按需导入使用，无需全局注册：

```typescript
// core层组件按需导入使用，无需全局注册
import DataTable from '@/components/core/DataTable.vue'
import PageHeader from '@/components/core/PageHeader.vue'
import SearchPanel from '@/components/core/SearchPanel.vue'
import StatusTag from '@/components/core/StatusTag.vue'
import StatCard from '@/components/core/StatCard.vue'
import StandardPage from '@/components/core/StandardPage.vue'
import ContentCard from '@/components/core/ContentCard.vue'
import Toolbar from '@/components/core/Toolbar.vue'
import TableActionBar from '@/components/core/TableActionBar.vue'
import Breadcrumb from '@/components/core/Breadcrumb.vue'
import EmptyState from '@/components/core/EmptyState.vue'
import Skeleton from '@/components/core/Skeleton.vue'
import StatusSwitch from '@/components/core/StatusSwitch.vue'

// business层组件按需导入
import CollapsibleSearchPanel from '@/components/business/CollapsibleSearchPanel.vue'
```

### 3.3 公共组件设计要求

- 必须通过 Props 配置差异化行为，提供合理的默认值
- 必须通过 Events 暴露交互，不直接修改父组件状态
- 必须支持插槽（Slots）以允许内容自定义
- 必须包含 TypeScript 类型定义，禁止使用 any 类型
- 必须使用 scoped 样式，避免样式污染

## 四、业务组件规范

### 4.1 按业务域组织

业务组件按业务域（模块）组织目录结构：

```
src/components/
├── common/              # 公共组件
├── Finance/             # 财务模块
│   ├── FinanceReportDialog.vue
│   ├── FinanceReportList.vue
│   ├── FinanceReportForm.vue
│   └── FinanceReportDetail.vue
├── HR/                  # 人力资源模块
│   ├── HREmployeeDialog.vue
│   ├── HREmployeeList.vue
│   ├── HREmployeeForm.vue
│   └── HREmployeeDetail.vue
└── Trace/               # 溯源模块
    ├── TraceFoodDialog.vue
    ├── TraceFoodList.vue
    ├── TraceFoodForm.vue
    └── TraceFoodDetail.vue
```

### 4.2 组件类型命名

| 组件类型 | 命名格式 | 说明 |
|---------|---------|------|
| 对话框组件 | `{Entity}Dialog.vue` | 弹窗交互，如新增、编辑、查看详情 |
| 列表组件 | `{Entity}List.vue` | 数据列表展示，含搜索、分页 |
| 表单组件 | `{Entity}Form.vue` | 表单录入，含验证逻辑 |
| 详情组件 | `{Entity}Detail.vue` | 数据详情展示，只读视图 |

### 4.3 业务组件与页面组件的关系

```
页面组件（views/）
  └── 负责布局和组件组合，不包含具体业务逻辑
       ├── PageHeader       → 页面标题
       ├── EntityList       → 数据列表
       ├── EntityDialog     → 新增/编辑弹窗
       └── EntityDetail     → 详情展示
```

页面组件仅负责将业务组件组合在一起，通过 Pinia Store 或 Props/Events 协调各业务组件之间的数据流。

## 六、样式文件组织

### 6.1 目录结构

```
src/styles/
├── index.scss                        # 全局样式入口（ITCSS架构）
├── global/
│   ├── _tokens.scss                  # Layer 1: Settings — 设计令牌（唯一权威来源）
│   ├── _base.scss                    # Layer 2: Generic — 基础重置与全局规则
│   ├── _element-overrides.scss       # Layer 3: Elements — Element Plus组件覆盖
│   ├── _layout.scss                  # Layer 4: Objects — 布局模式与容器
│   ├── _modern-page.scss             # Layer 5: Components — 黄金标准页面模式
│   └── _dark-mode.scss               # Layer 6: Trumps — 深色/色弱模式覆盖
```

### 6.2 各文件职责

| 文件 | 层级 | 职责 |
|------|------|------|
| `_tokens.scss` | Settings | 定义所有CSS变量（色彩/间距/字体/阴影/动画/层级），样式的唯一权威来源 |
| `_base.scss` | Generic | CSS重置、View Transition动画、滚动条、字体、动画控制、compact模式、色弱模式 |
| `_element-overrides.scss` | Elements | Element Plus组件库样式统一覆盖（Tabs/Button/Input/Tag/Pagination等） |
| `_layout.scss` | Objects | 页级布局容器（.modern-page / .fts-toolbar / .fts-table-card等） |
| `_modern-page.scss` | Components | 黄金标准页面模式（.modern-page/ stats-section/ advanced-search-panel/ table-section/ pagination-wrapper） |
| `_dark-mode.scss` | Trumps | 深色模式与色弱模式CSS变量覆盖 + Element Plus组件深色适配 |

### 6.3 入口文件导入顺序（ITCSS架构）

```scss
// styles/index.scss — 按特异性递增加载
// Layer 1: Settings     → _tokens.scss       设计令牌（CSS变量，最先加载）
// Layer 2: Generic      → _base.scss          CSS重置、全局规则、动画控制
// Layer 3: Elements     → _element-overrides.scss  Element Plus 组件覆盖
// Layer 4: Objects      → _layout.scss        页级容器、工具栏、表格卡片
// Layer 5: Components   → _modern-page.scss   黄金标准页面模式（stats-section等）
// Layer 6: Trumps       → _dark-mode.scss     深色/色弱模式覆盖（最后加载，最高优先级）

@use 'global/tokens';
@use 'global/base';
@use 'global/element-overrides';
@use 'global/layout';
@use 'global/modern-page';
@use 'global/dark-mode';
```

### 6.4 组件样式使用 scoped 属性

所有 Vue 组件的 `<style>` 标签必须添加 `scoped` 属性，防止样式污染：

```vue
<style scoped lang="scss">
.content-card {
  background: var(--fts-bg-card);
  border-radius: 8px;
  box-shadow: var(--fts-shadow-sm);
}
</style>
```

## 八、组件样式规范

### 8.1 使用 CSS 变量统一样式

所有样式值必须使用 CSS 变量，禁止硬编码颜色值、间距值等：

```scss
// 正确
.button {
  background: var(--fts-primary);
  color: var(--fts-text-inverse);
  padding: var(--fts-space-2) var(--fts-space-4);
  font-size: var(--fts-font-size-base);
  border-radius: 4px;
  transition: background var(--fts-duration-fast) var(--fts-easing-default);
}

// 错误
.button {
  background: #409eff;       // 禁止硬编码颜色
  color: #ffffff;            // 禁止硬编码颜色
  padding: 8px 16px;         // 禁止硬编码间距
  font-size: 14px;           // 禁止硬编码字号
}
```

### 8.2 统一卡片样式

**新页面首选模式（黄金标准）**：使用 `.modern-page` + `PageHeader` + `.stats-section` + `.advanced-search-panel` + `.table-section` 模式。参见 `FoodManagement.vue` 及 `_modern-page.scss`。

**兼容模式**：对于未迁移的旧页面，仍可使用 `content-card` 类：

```html
<div class="content-card">

      <!-- 操作按钮 -->

  </div>

    <!-- 卡片内容 -->
  </div>
</div>
```

### 8.3 禁止事项

| 禁止项 | 说明 | 替代方案 |
|--------|------|---------|
| `!important` | 破坏样式优先级，难以维护 | 提高选择器特异性或重构样式结构 |
| 硬编码颜色值 | 无法适配主题切换 | 使用 CSS 变量 |
| 硬编码间距值 | 无法保持一致性 | 使用 `--fts-space-*` 变量 |
| 硬编码字号 | 无法保持一致性 | 使用 `--fts-font-size-*` 变量 |
| 嵌套超过 3 层 | 选择器过于具体，难以覆盖 | 扁平化选择器，使用 BEM 或单一类名 |

### 8.4 响应式设计

使用 CSS 变量和媒体查询实现响应式布局：

```scss
.container {
  padding: var(--fts-space-4);

  @media (min-width: 768px) {
    padding: var(--fts-space-6);
  }

  @media (min-width: 1200px) {
    padding: var(--fts-space-8);
  }
}
```

### 8.5 动画与过渡

使用统一的动画变量，确保交互体验一致：

```scss
.element {
  transition: all var(--fts-duration-normal) var(--fts-easing-default);

  &:hover {
    transform: translateY(-2px);
    box-shadow: var(--fts-shadow-md);
  }
}
```

尊重用户的无障碍偏好设置：

```scss
.element {
  transition: all var(--fts-duration-normal) var(--fts-easing-default);

  @media (prefers-reduced-motion: reduce) {
    transition: none;
  }
}
```

  </section>

    <el-pagination ... />
  </div>

```

**日期选择器规范**：
| 类型 | 推荐宽度 | 说明 |
|------|---------|------|
| `el-date-picker type="daterange"` | `240px` | 日期范围选择器，统一宽度 |
| `el-date-picker type="date"` | `160px` | 单个日期选择 |
| 必须设置 | `placement="bottom-start"` | 防止弹窗偏移到选择器左侧 |

**表格列宽设置规范**（`table-layout="fixed"` 模式下）：

| 列内容类型 | 使用属性 | 推荐值范围 | 示例 |
|-----------|---------|-----------|------|
| 单号/编码（长文本） | `width` | 180-195px | 订单号、退款单号 |
| 日期时间 | `width` | 160-170px | 下单时间、申请时间 |
| 名称/描述（中文短文本） | `width` | 160-180px | 菜品名称、退款原因 |
| 状态标签 | `width` | 100-110px | 订单状态 |
| 联系方式/支付方式 | `width` | 100-140px | 电话、支付方式 |
| 金额（含¥符号） | `width` | 85-110px | 退款金额 |
| 数字/计数 | `width` | 65-100px | 数量、人数 |
| 短标识（人/桌） | `width` | 70-95px | 顾客名、桌号 |

**列宽核心原则**：
- **优先使用 `width`**：`table-layout="fixed"` 下 `minWidth` 列会吸收全部剩余空间，1 个 `minWidth` 列可能膨胀到 400-600px+，造成视觉不适
- **固定宽度为主**：全部使用 `width` 固定值，列宽保持比例均衡，宽屏时出现右余白（可接受）远好于某列极宽（不可接受）
- **值匹配内容**：`width` 值按列中最长典型内容计算，确保不截断
- 仅在确需弹性时（如自由文本备注列），慎重使用 `minWidth`，且必须至少搭配 1 个其他 `minWidth` 列分摊剩余空间

## 九、代码长度限制

### 9.1 限制标准

| 文件类型 | 最大行数 | 超出时处理方式 |
|---------|---------|---------------|
| Vue 组件 | 1000 行 | 拆分为子组件 |
| JavaScript/TypeScript | 800 行 | 拆分为多个模块 |
| SCSS/CSS | 600 行 | 拆分为多个样式文件 |
| 函数/方法 | 100 行 | 提取为多个子函数 |

### 9.2 超限处理策略

当文件接近或超过限制时，应按以下策略处理：

**Vue 组件超限：**

1. 将模板中的重复区块提取为子组件
2. 将复杂逻辑提取到 composable 或 utils 中
3. 将大段样式提取到独立的 SCSS 文件中，通过 `@use` 引入

**TypeScript 文件超限：**

1. 按功能职责拆分为多个模块
2. 将类型定义提取到 `types/` 目录
3. 将工具函数提取到 `utils/` 目录

**函数超限：**

1. 识别函数中的独立逻辑块
2. 将独立逻辑块提取为命名清晰的子函数
3. 主函数仅负责编排子函数的调用顺序

## 十、代码分割规则

### 10.1 组件层级划分

| 层级 | 职责 | 示例 |
|------|------|------|
| 页面级组件 | 仅负责布局和组件组合 | `FinanceReport.vue` |
| 功能组件 | 将复杂功能拆分为子组件 | `FinanceReportList.vue` |
| 复用组件 | 提取通用 UI 元素 | `ContentCard.vue` |
| 基础组件 | 最小粒度的 UI 单元 | `StatusTag.vue` |

### 10.2 状态管理分割

复杂状态使用 Pinia Store 管理，避免组件内部状态过于庞大：

```
stores/
├── finance-report.ts     # 财务报表状态
├── hr-employee.ts        # 员工管理状态
└── trace-food.ts         # 食品溯源状态
```

Store 设计原则：

- 每个 Store 对应一个业务域
- Store 内部按功能分区（数据、表单、UI 状态）
- 异步操作通过 actions 处理
- 派生状态通过 getters 计算

### 10.3 工具函数提取

将业务逻辑从组件中提取到 `utils/` 目录，按功能分类组织：

```
utils/
├── finance/
│   ├── report-form.ts        # 表单验证和处理逻辑
│   ├── report-templates.ts   # 报表模板管理
│   ├── report-charts.ts      # 图表生成逻辑
│   └── report-relationships.ts  # 关联数据处理
├── hr/
│   ├── employee-form.ts      # 员工表单逻辑
│   └── employee-export.ts    # 员工数据导出
└── trace/
    ├── food-form.ts          # 食品表单逻辑
    └── food-trace.ts         # 溯源链路逻辑
```

### 10.4 组件拆分示例

以财务报表页面为例，展示从单一组件到拆分后的结构：

**拆分前（不推荐）：**

```

**拆分后（推荐）：**

### 10.5 拆分判断标准

当出现以下情况时，应考虑拆分组件：

- 组件文件超过 500 行（预警线）
- 模板中存在大段可独立的功能区块
- 同一组件中存在多个不相关的数据流
- 组件的 Props 超过 10 个
- 组件中存在大量条件渲染逻辑（v-if/v-else-if 超过 3 个分支）
