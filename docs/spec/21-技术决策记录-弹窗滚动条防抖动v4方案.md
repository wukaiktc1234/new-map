# 技术决策记录：弹窗/抽屉滚动条防抖动方案

> **状态**: ✅ 已验证通过 (2026-05-04)
> **版本**: v4 - 保留滚动条方案
> **影响范围**: 所有使用 Element Plus Dialog/Drawer 组件的页面

---

## 一、问题描述

### 1.1 现象
当页面中打开弹窗（Dialog）或抽屉（Drawer）时：
1. 右侧垂直滚动条**消失**
2. 页面内容区域**自动加宽**填补滚动条空间（约17px）
3. 导致**整个页面布局发生偏移/抖动**
4. el-table（table-layout: fixed）检测到容器宽度变化，**重新分配列宽**
5. 用户看到表格列宽"跳动"、文字位置偏移等视觉抖动

### 1.2 影响范围
- 所有包含 Element Plus `el-dialog` / `el-drawer` 的页面
- 特别是有数据表格（el-table）的页面，抖动更明显

---

## 二、根因分析

### 2.1 浏览器行为链路

```
弹窗打开请求
  ↓
Element Plus 内部调用 useLockscreen() hook
  ↓ (use-lockscreen/index.mjs:46)
body.style.width = `calc(100% - ${scrollBarWidth}px)`  // 减少宽度
  ↓ (popup.scss:44-46)
body 添加 .el-popup-parent--hidden 类
  → CSS: overflow: hidden;                              // 隐藏滚动条
  ↓
【浏览器内核响应】
overflow: hidden → 滚动条消失
  → 内容区域可用宽度增加 ~17px
  → 浏览器自动重新布局（reflow）
  → 子元素（#app → main-content → table-wrapper）全部变宽
  → el-table 检测到容器变化 → 重新计算列宽
  ↓
👀 用户看到：页面/表格"抖动"
```

### 2.2 关键发现

| 发现点 | 详情 |
|--------|------|
| **根本原因** | `overflow: hidden` 导致滚动条消失是**所有问题的根源** |
| **浏览器行为** | 滚动条消失后，浏览器**必然**会调整内容区域宽度（这是内核固有行为） |
| **补偿无效** | 任何事后补偿（padding-right、width:calc）都会触发新的 reflow |
| **结论** | **不能隐藏滚动条**，必须保留它或用其他方式阻止滚动 |

## 三、方案演进历史

### 3.1 方案对比总览

| 版本 | 核心方法 | overflow值 | 滚动条状态 | 结果 |
|------|---------|-----------|----------|------|
| **v1** | padding-right 补偿 | hidden | ❌ 消失 | 🔴 失败：body宽度变化 |
| **v2** | MutationObserver + calc(width) | hidden | ❌ 消失 | 🔴 失败：表格容器变窄 |
| **v3** | 只设overflow:hidden + scrollbar-gutter | hidden | ❌ 消失 | 🔴 失败：浏览器仍加宽内容 |
| **v4** | position:fixed + 事件拦截 | **scroll** | ✅ **保留** | 🟢 **成功** |

### 3.2 各版本详细说明

#### v1: padding-right 补偿方案（失败）

**思路**: 在隐藏滚动条前，先给 body 添加等宽的 padding-right

```typescript
// 错误做法
document.body.style.paddingRight = `${scrollbarWidth}px`  // +17px
document.body.style.overflow = 'hidden'                       // 隐藏滚动条
```

**失败原因**: 
- body 的实际内容区域仍被 padding 挤压
- 或 body.style.width 被外部代码修改为 `calc(100%-17px)`
- 无论哪种方式，子容器的可用宽度都发生了变化

---

#### v2: MutationObserver + 强制锁定（失败）

**思路**: 用 JS 实时拦截并撤销任何对 body 宽度的修改

```typescript
// 错误做法
observer = new MutationObserver(() => {
  if (body.style.width !== '') {
    body.style.removeProperty('width')  // 尝试撤销
  }
})
```

**失败原因**:
- `overflow: hidden` 已生效，滚动条已消失
- 浏览器在 CSS 渲染阶段就已经完成了布局调整
- JS 层的撤销发生在渲染之后，无法阻止视觉上的"跳动"

---

#### v3: 纯粹锁定 + scrollbar-gutter（失败）

**思路**: 只设置 overflow:hidden，不修改任何宽度属性，依赖 CSS `scrollbar-gutter: stable`

```scss
/* 错误做法 */
body {
  scrollbar-gutter: stable;  /* 预留滚动条空间 */
}
```

```typescript
// 错误做法
document.body.style.overflow = 'hidden'  // 只改这一项
```

**失败原因**:
- `scrollbar-gutter: stable` 的作用是**预留空间**，不是**强制显示滚动条**
- 当 `overflow: hidden` 生效时，滚动条仍然会消失
- 浏览器仍然会调整内容区域宽度（即使有 scrollbar-gutter 预留）
- 兼容性问题：Safari 17- 支持，旧版 Safari 不支持

---

#### v4: position:fixed + 保留滚动条（✅ 成功）

**思路**: 不再使用 `overflow:hidden`！改用 `position:fixed` 固定 body，同时保留滚动条并拦截滚动事件。

```typescript
// ✅ 正确做法
body.style.position = 'fixed'
body.style.top = `-${savedScrollTop}px`
body.style.left = `-${savedScrollLeft}px`
body.style.width = '100%'
body.style.overflowY = 'scroll'  // ← 滚动条保留！

// 拦截滚动事件
window.addEventListener('wheel', e => e.preventDefault(), { passive: false })
window.addEventListener('scroll', () => window.scrollTo(savedPos), { passive: false })
```

**成功原因**:
1. **不隐藏滚动条** → 浏览器不会调整内容宽度
2. **position: fixed** → body 固定在当前视口位置，用户无法滚动
3. **事件拦截** → 即使有其他滚动触发源也被阻止
4. **零副作用** → 不改变任何宽度相关属性

## 四、最终实施方案（v4）

### 4.1 架构设计

```
┌─────────────────────────────────────────────────────┐
│                    三层防护体系                      │
├──────────┬──────────────────────────────────────────┤
│ 第一层   │ CSS 防护层                                │
│ (最高优) │ • 禁止 .el-popup-parent--hidden 设置     │
│          │   overflow:hidden                        │
│          │ • scrollbar-gutter: stable 辅助保险      │
├──────────┼──────────────────────────────────────────┤
│ 第二层   │ JS 防御层                                 │
│ (实时)   │ • MutationObserver 监听 body.style 变化   │
│          │ • 检测到 position 被移除 → 立即恢复       │
├──────────┼──────────────────────────────────────────┤
│ 第三层   │ 业务逻辑层                                 │
│ (源头)   │ • :lock-scroll="false" 禁用 EP 原生锁定   │
│          │ • useScrollbarLock(v4) 控制滚动行为       │
└──────────┴──────────────────────────────────────────┘
```

### 4.3 使用方式

在任何弹窗/抽屉组件中使用：

```vue
<script setup lang="ts">
import { useScrollbarLock } from '@/composables/useScrollbarLock'

const props = defineProps<{ modelValue: boolean }>()

const visible = computed({
  get: () => props.modelValue,
  set: (val) => emit('update:modelValue', val),
})

// 一行代码搞定
useScrollbarLock(visible)
</script>

<template>
  <el-dialog
    :model-value="modelValue"
    :lock-scroll="false"  <!-- 禁用 EP 原生锁定 -->
  >
    ...
  </el-dialog>
</template>
```

### 4.4 核心代码

**useScrollbarLock.ts v4 核心函数**:

```typescript
function lockWithScrollbar(): void {
  if (lockCount === 0) {
    // 1. 记录滚动位置
    savedScrollTop = window.scrollY || document.documentElement.scrollTop
    savedScrollLeft = window.scrollX || document.documentElement.scrollLeft

    // 2. 固定 body 到当前位置（关键！不使用 overflow:hidden）
    const body = document.body
    body.style.position = 'fixed'
    body.style.top = `-${savedScrollTop}px`
    body.style.left = `-${savedScrollLeft}px`
    body.style.width = '100%'
    body.style.overflowY = 'scroll'  // 保留滚动条！

    // 3. 拦截所有滚动行为
    window.addEventListener('scroll', forceScrollBack, { passive: false })
    window.addEventListener('wheel', preventDefault, { passive: false })
    document.addEventListener('touchmove', preventDefault, { passive: false })
  }
  lockCount++
}
```

**_base.scss CSS 规则**:

```scss
// 最重要：禁止 Element Plus 设置 overflow: hidden
.el-popup-parent--hidden {
  overflow: visible !important;
  width: auto !important;
  padding-right: 0 !important;

// 双保险
body.el-popup-parent--hidden {
  overflow: visible !important;
  width: auto !important;
  padding-right: 0 !important;
}
```

## 六、经验总结

### 6.1 技术教训

1. **不要与浏览器内核对抗**: `overflow: hidden` 导致滚动条消失是 W3C 标准行为，不要试图"修补"它的副作用
2. **CSS 优先于 JS**: 能用 CSS 解决的问题绝不用 JS（性能、可靠性、时机都更好）
3. **position:fixed 的妙用**: 它可以同时实现"固定位置"和"脱离文档流"，非常适合滚动锁定场景
4. **被动事件监听**: `{ passive: false }` 才能调用 `preventDefault()`，这是现代浏览器的安全限制

### 6.2 调试方法

1. **浏览器实测 > 代码推理**: 多次证明代码分析和实际运行结果有差异，必须实测
2. **Element Plus 源码阅读**: 通过阅读 `use-lockscreen/index.mjs` 和 `popup.scss` 精确定位问题
3. **MutationObserver**: 监听 DOM 变化的强大工具，可用于调试第三方库的行为

### 6.3 可复用性

此方案不仅适用于本项目，也可用于任何使用以下技术栈的项目：
- Vue 2/3 + Element Plus
- React + Ant Design/MUI（类似原理）
- 原生 JavaScript 项目
