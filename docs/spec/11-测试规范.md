- 覆盖API接口端到端流程
- 验证各组件间协作正确
- 确保数据流转完整

### 1.3 功能测试

- 覆盖UI交互验证
- 验证用户操作流程
- 确保界面表现符合预期

### 1.4 对抗性验证

- 覆盖边界情况和异常输入
- 验证系统容错能力
- 确保安全防护有效

## 二、后端测试规范

### 2.1 测试框架

- JUnit 5
- Mockito
- Spring Boot Test

### 2.2 测试目录

```
src/test/java/com/example/demo/
├── controller/     # Controller层测试
├── service/        # Service层测试
├── mapper/         # Mapper层测试
└── common/         # 公共类测试
```

### 2.3 Service层测试

- 使用Mockito Mock外部依赖
- 验证业务逻辑正确性
- 覆盖正常流程和异常分支
- 验证方法调用次数和参数

```java
@ExtendWith(MockitoExtension.class)
class EmployeeServiceTest {

    @Mock
    private EmployeeMapper employeeMapper;

    @InjectMocks
    private EmployeeServiceImpl employeeService;

    @Test
    void test_createEmployee_validInput_success() {
        // given
        EmployeeCreateDTO dto = new EmployeeCreateDTO();
        dto.setName("张三");

        // when
        employeeService.createEmployee(dto);

        // then
        verify(employeeMapper, times(1)).insert(any(Employee.class));
    }
}
```

### 2.4 Controller层测试

- 使用MockMvc模拟HTTP请求
- 验证API契约（请求路径、参数、响应格式）
- 验证权限控制
- 验证参数校验

```java
@WebMvcTest(EmployeeController.class)
class EmployeeControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private EmployeeService employeeService;

    @Test
    void test_getEmployeeById_validId_return200() throws Exception {
        mockMvc.perform(get("/api/v1/employees/{id}", "123")
                .contentType(MediaType.APPLICATION_JSON))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.code").value(0));
    }
}
```

### 2.5 数据库测试

- 使用`@DataJpaTest`注解
- 使用H2内存数据库
- 验证SQL查询正确性
- 验证实体映射关系

### 2.6 测试命名规范

格式：`test_{method}_{scenario}_{expectedResult}`

示例：

- `test_createEmployee_validInput_success`
- `test_createEmployee_duplicateName_throwException`

## 三、前端测试规范

### 3.1 测试框架

- Vitest
- @vue/test-utils

### 3.2 组件测试

- 使用`mount`进行完整渲染测试
- 使用`shallowMount`进行单元隔离测试
- 验证组件渲染输出
- 验证用户交互行为
- 验证事件触发和参数

```typescript
import { mount } from '@vue/test-utils';
import EmployeeForm from '@/components/Employee/EmployeeForm.vue';

describe('EmployeeForm', () => {
  it('should render form fields correctly', () => {
    const wrapper = mount(EmployeeForm);
    expect(wrapper.find('[data-test="name-input"]').exists()).toBe(true);
  });

  it('should emit submit event with form data', async () => {
    const wrapper = mount(EmployeeForm);
    await wrapper.find('[data-test="name-input"]').setValue('张三');
    await wrapper.find('[data-test="submit-btn"]').trigger('click');
    expect(wrapper.emitted('submit')).toBeTruthy();
  });
});
```

### 3.3 Composable测试

- 验证状态变化
- 验证副作用
- 验证返回值

```typescript
import { useEmployeeList } from '@/composables/useEmployeeList';

describe('useEmployeeList', () => {
  it('should load employee list on mount', async () => {
    const { employees, loading, loadEmployees } = useEmployeeList();
    await loadEmployees();
    expect(loading.value).toBe(false);
    expect(employees.value.length).toBeGreaterThan(0);
  });
});
```

### 3.4 Store测试

- 验证状态管理
- 验证异步操作
- 验证状态变更

```typescript
import { useEmployeeStore } from '@/stores/employee';

describe('employee store', () => {
  beforeEach(() => {
    const store = useEmployeeStore();
    store.$reset();
  });

  it('should fetch employees and update state', async () => {
    const store = useEmployeeStore();
    await store.fetchEmployees({ page: 1, size: 10 });
    expect(store.employees.length).toBeGreaterThan(0);
    expect(store.total).toBeGreaterThan(0);
  });
});
```

### 3.5 测试命名规范

格式：`describe('ComponentName')` + `it('should do something')`

示例：

- `describe('EmployeeForm')` + `it('should validate required fields')`
- `describe('EmployeeList')` + `it('should display employee data')`
- `describe('useEmployeeList')` + `it('should handle empty results')`

## 四、API测试规范

### 4.1 测试工具

- Postman
- curl

### 4.2 测试用例覆盖

| 测试类型 | 说明 | 示例 |
|---------|------|------|
| 正常流程 | 验证标准业务流程 | 创建员工，返回201 |
| 边界值 | 验证参数边界 | 分页查询size=0或size=10000 |
| 异常输入 | 验证非法参数处理 | 名称包含特殊字符、ID格式错误 |
| 权限控制 | 验证未授权访问 | 无Token访问、权限不足访问 |

### 4.3 响应验证

- 状态码验证：确认HTTP状态码符合预期
- 响应格式验证：确认响应体符合统一格式
- 数据完整性验证：确认返回数据字段完整且类型正确

### 4.4 Postman测试示例

```
# 正常流程
POST /api/v1/employees
Headers: Authorization: Bearer {token}
Body: { "name": "张三", "phone": "13800138000" }
Expected: 201, { "code": 0, "message": "创建成功", "data": {...} }

# 异常输入
POST /api/v1/employees
Headers: Authorization: Bearer {token}
Body: { "name": "", "phone": "invalid" }
Expected: 422, { "code": 4220, "message": "参数校验失败", "data": null }

# 权限控制
POST /api/v1/employees
Headers: (无Authorization)
Body: { "name": "张三", "phone": "13800138000" }
Expected: 401, { "code": 4001, "message": "未授权", "data": null }
```

## 六、质量门禁

### 6.1 代码覆盖率要求

| 模块 | 最低覆盖率 |
|------|-----------|
| 核心Service层 | >= 70% |
| Controller层 | >= 50% |
| 前端组件 | >= 40% |

### 6.2 构建检查

- 无编译错误
- 无TypeScript类型错误
- 无ESLint错误
- 所有测试通过

### 6.3 门禁执行

每次代码合并前必须通过以下检查：

1. 后端编译：`mvn compile` 通过
2. 后端测试：`mvn test` 通过，覆盖率达标
3. 前端构建：`npm run build` 通过
4. 前端类型检查：无TypeScript类型错误
5. 前端Lint：`npm run lint` 通过
6. 前端测试：`npm run test` 通过，覆盖率达标
