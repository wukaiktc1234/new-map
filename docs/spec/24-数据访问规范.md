# 数据访问规范

> **强制规范** — 本规范为项目数据源管理的最高约束，任何代码变更必须遵守。

## 一、核心原则

### 1.1 唯一数据源原则

- **本项目唯一允许的数据存储为 PostgreSQL 数据库**
- 禁止在代码中引入任何非 PostgreSQL 数据源（包括但不限于 Redis、RabbitMQ、Caffeine、H2、MongoDB、ElasticSearch 等）
- 所有数据持久化需求必须通过 PostgreSQL 数据库实现
- 所有跨服务数据共享必须通过 PostgreSQL 数据库表实现

### 1.2 禁止的数据源类型

| 数据源类型 | 状态 | 说明 |
|-----------|------|------|
| PostgreSQL | **允许**（唯一） | 项目唯一数据源 |
| Redis | **禁止** | 已于 2026-07-14 彻底移除 |
| RabbitMQ | **禁止** | 已于 2026-07-14 彻底移除 |
| Caffeine | **禁止** | 已于 2026-07-14 彻底移除 |
| H2 | **禁止** | 已于 2026-07-14 彻底移除（含测试 scope） |
| MongoDB | **禁止** | 从未引入，禁止未来引入 |
| ElasticSearch | **禁止** | 从未引入，禁止未来引入 |
| 其他 NoSQL | **禁止** | 从未引入，禁止未来引入 |

## 二、数据访问层架构

### 2.1 分层架构

```
Controller → Service接口 → ServiceImpl实现 → Mapper → PostgreSQL
   |              |               |                    |           |
请求路由       业务逻辑       事务管理               数据访问      数据存储
参数校验       消息发布       缓存更新策略           CRUD操作
返回Result    日志记录                              分页查询
```

### 2.2 数据访问路径

- **唯一数据访问路径**：`ServiceImpl → Mapper → PostgreSQL`
- **禁止**在 Controller 中直接注入 Mapper
- **禁止**在 ServiceImpl 中绕过 Mapper 直接使用 JDBC
- **禁止**在 ServiceImpl 中引入任何缓存中间件

### 2.3 依赖注入规范

```java
// ✅ 正确：构造器注入 Mapper
@Service
public class ExampleServiceImpl implements ExampleService {
    private final ExampleMapper exampleMapper;

    public ExampleServiceImpl(ExampleMapper exampleMapper) {
        this.exampleMapper = exampleMapper;
    }
}

// ❌ 错误：注入 Redis
@Service
public class ExampleServiceImpl implements ExampleService {
    private final RedisTemplate<String, Object> redisTemplate; // 禁止
}

// ❌ 错误：字段注入
@Service
public class ExampleServiceImpl implements ExampleService {
    @Autowired
    private ExampleMapper exampleMapper; // 禁止字段注入
}
```

## 三、缓存替代方案

### 3.1 Spring Cache 抽象（允许）

- 允许使用 Spring Cache 抽象（`@Cacheable`、`@CacheEvict`、`@CachePut`）
- 底层实现为 `ConcurrentMapCacheManager`（内存缓存，非 Redis）
- 配置位于 `config/SimpleCacheConfig.java`

```java
// ✅ 正确：使用 Spring Cache 注解
@Cacheable(value = "product", key = "#productId")
public Product getProductById(String productId) {
    return productMapper.selectById(productId);
}

@CacheEvict(value = "product", key = "#product.productId")
public void updateProduct(Product product) {
    productMapper.updateById(product);
}
```

### 3.2 内存缓存（允许，有限制）

- 允许使用 `java.util.concurrent.ConcurrentHashMap` 实现请求级或会话级内存缓存
- **必须**实现 TTL 过期机制和容量上限清理
- **禁止**用于持久化数据存储
- **禁止**替代数据库查询的核心数据路径

```java
// ✅ 正确：内存缓存 + TTL + 容量清理
private final ConcurrentMap<String, TimedEntry<Config>> cache = new ConcurrentHashMap<>();

private static class TimedEntry<T> {
    final T value;
    final long expireAt;
    TimedEntry(T value, long ttlMillis) {
        this.value = value;
        this.expireAt = System.currentTimeMillis() + ttlMillis;
    }
    boolean isExpired() {
        return System.currentTimeMillis() > expireAt;
    }
}

// 超过阈值时清理
if (cache.size() > MAX_CACHE_SIZE) {
    cache.entrySet().removeIf(e -> e.getValue().isExpired());
}
```

### 3.3 禁止的缓存方案

```java
// ❌ 错误：使用 Redis
@Autowired
private RedisTemplate<String, Object> redisTemplate;

// ❌ 错误：使用 Caffeine
private Cache<String, Object> cache = Caffeine.newBuilder().build();

// ❌ 错误：使用 Guava Cache（除非已在 pom.xml 中声明）
```

## 四、消息传递替代方案

### 4.1 Spring ApplicationEvent（允许）

- 允许使用 Spring 的 `ApplicationEventPublisher` 和 `@EventListener`
- 适用于进程内事件通知（同步执行）

```java
// ✅ 正确：使用 Spring ApplicationEvent
@Autowired
private ApplicationEventPublisher eventPublisher;

public void purchaseStockin(Long stockinId) {
    // 业务逻辑
    stockinMapper.updateById(stockin);
    // 发布事件（同步执行）
    eventPublisher.publishEvent(new StockinCompletedEvent(stockinId));
}

@EventListener
public void handleStockinCompleted(StockinCompletedEvent event) {
    // 事件处理逻辑
}
```

### 4.2 直接方法调用（允许）

- 对于强一致性要求的业务逻辑，直接在事务中调用相关 Service 方法
- **禁止**使用消息队列实现异步解耦（已移除 RabbitMQ）

```java
// ✅ 正确：事务内直接调用
@Transactional(rollbackFor = Exception.class)
public void confirmStockin(Long stockinId) {
    stockinMapper.updateStatus(stockinId, STATUS_STOCKED);
    payableService.createForStockin(stockinId); // 直接调用
}
```

### 4.3 禁止的消息方案

```java
// ❌ 错误：使用 RabbitMQ
@Autowired
private RabbitTemplate rabbitTemplate;

// ❌ 错误：使用 @RabbitListener
@RabbitListener(queues = "trace.queue")
public void handleMessage(Message message) { }
```

## 五、分布式锁替代方案

### 5.1 JVM 内锁（允许）

- 使用 `synchronized` 或 `java.util.concurrent.locks.ReentrantLock`
- 适用于单实例部署场景

```java
// ✅ 正确：使用 ReentrantLock
private final ConcurrentMap<String, ReentrantLock> locks = new ConcurrentHashMap<>();

public void updateInventory(String productId) {
    ReentrantLock lock = locks.computeIfAbsent(productId, k -> new ReentrantLock());
    lock.lock();
    try {
        // 业务逻辑
    } finally {
        lock.unlock();
    }
}
```

### 5.2 数据库乐观锁（允许）

- 使用 MyBatis-Plus 的 `@Version` 注解实现乐观锁
- 适用于并发更新场景

```java
// ✅ 正确：数据库乐观锁
@Version
@TableField("version")
private Integer version;
```

### 5.3 禁止的锁方案

```java
// ❌ 错误：使用 Redis 分布式锁
@Autowired
private RedisDistributedLock redisDistributedLock;
```


## 九、违规处理

### 9.1 编译期拦截

- Maven 编译将在依赖缺失时自动失败
- IDE 将标记无法解析的导入为错误

### 9.2 代码审查拦截

- 代码审查时发现违规引用，**必须**拒绝合并
- 发现引入禁止依赖的 PR，**必须**要求回退

### 9.3 定期审计

- 每季度执行一次全项目数据源审计
- 使用以下命令扫描残留引用：

```bash
# 扫描 Redis 残留
grep -rn "RedisTemplate\|StringRedisTemplate\|org.springframework.data.redis" src/main/java/

# 扫描 RabbitMQ 残留
grep -rn "RabbitTemplate\|@RabbitListener\|org.springframework.amqp" src/main/java/

# 扫描 Caffeine 残留
grep -rn "Caffeine\|com.github.benmanes.caffeine" src/main/java/

# 扫描 H2 残留
grep -rn "jdbc:h2\|org.h2" src/main/java/ src/main/resources/
```
