# 技术栈选型

## 一、选型原则

1. **成熟稳定**：优先选择社区活跃、文档完善、经过大规模生产验证的技术
2. **团队适配**：与团队现有技术栈兼容，降低学习成本
3. **性能优先**：满足食品溯源系统对实时性和高可用的要求
4. **可扩展性**：支持未来业务增长和功能扩展
5. **安全合规**：满足食品安全溯源的合规要求

## 五、技术选型风险与应对

| 风险项 | 影响程度 | 应对策略 |
|--------|---------|----------|
| JDK 21虚拟线程生产成熟度 | 中 | 核心业务先使用平台线程验证，逐步迁移虚拟线程 |
| MyBatis Plus与PostgreSQL兼容性 | 低 | 已验证JSONB/数组类型映射，复杂查询使用XML映射 |
| Flyway MySQL到PG迁移 | 中 | 编写PG语法迁移脚本，建立SQL语法差异对照表 |
| Vue3 Composition API学习曲线 | 低 | 团队培训，建立Composable编写规范 |
| Redis单点故障 | 高 | 生产环境配置哨兵模式或集群模式 |
| RabbitMQ消息积压 | 中 | 设置队列长度上限，配置死信队列，监控消费者延迟 |

## 六、技术演进路线

### 短期（1-3个月）
- 完成Flyway迁移脚本从MySQL到PostgreSQL的适配
- 建立前端ESLint+Prettier规范强制检查
- 完成request实例封装和API层标准化

### 中期（3-6个月）
- 引入虚拟线程优化IO密集型接口性能
- 完善Redis集群部署方案
- 建立自动化性能测试流水线

### 长期（6-12个月）
- 评估Spring Boot 3.3+升级路径
- 引入GraphQL支持前端灵活查询
- 探索微服务拆分可能性（如溯源服务独立部署）
