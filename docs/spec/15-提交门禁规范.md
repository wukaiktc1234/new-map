# 食品溯源系统 - 提交门禁规范

> 本文档定义了代码提交门禁的完整工具链配置和使用规范，确保不合规代码无法进入代码仓库。

## 文档版本

| 版本 | 日期 | 说明 |
|------|------|------|
| v1.0 | 2026-04-13 | 初始版本 |

## 第一章 总则

### 1.1 目标

- 从源头杜绝不合规代码进入仓库
- 自动化执行代码质量检查，减少人工审查负担
- 规范化提交信息，便于版本追溯和自动生成变更日志

### 1.2 核心原则【强制】

- **门禁不可绕过**：所有提交必须通过门禁检查
- **快速反馈**：门禁检查应在30秒内完成
- **增量检查**：只检查本次提交涉及的文件，不检查全量代码
- **错误信息可操作**：门禁拦截时必须给出明确的修复建议

### 1.3 门禁层级

```
本地门禁（Husky + lint-staged）→ 远程门禁（CI Pipeline）
     ↓                                ↓
  即时反馈                         二次保障
  开发者自行修复                   阻止不合规合并
```

## 第二章 工具链配置【强制】

### 2.1 依赖安装

```bash
npm install -D husky lint-staged @commitlint/cli @commitlint/config-conventional commitizen cz-git
```

### 2.2 Husky 配置

```bash
npx husky init
```

初始化后生成 `.husky/` 目录，包含 `pre-commit` 和 `commit-msg` 钩子。

#### pre-commit 钩子

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx lint-staged
```

#### commit-msg 钩子

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx --no -- commitlint --edit "$1"
```

### 2.3 lint-staged 配置

在 `package.json` 中添加：

```json
{
  "lint-staged": {
    "*.{js,ts,vue}": [
      "eslint --fix",
      "prettier --write"
    ],
    "*.{css,scss,vue}": [
      "stylelint --fix",
      "prettier --write"
    ],
    "*.{json,md}": [
      "prettier --write"
    ]
  }
}
```

### 2.4 CommitLint 配置

创建 `commitlint.config.cjs`：

```javascript
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', [
      'feat',     // 新功能
      'fix',      // 修复bug
      'docs',     // 文档变更
      'style',    // 代码格式（不影响功能）
      'refactor', // 重构（不是新功能也不是修复）
      'perf',     // 性能优化
      'test',     // 增加测试
      'chore',    // 构建过程或辅助工具变动
      'revert',   // 回退
      'build'     // 构建系统或外部依赖变更
    ]],
    'scope-case': [2, 'always', ['lower-case']],
    'subject-max-length': [2, 'always', 100],
    'body-max-line-length': [0, 'always', Infinity]
  }
};
```

### 2.5 Commitizen 配置

在 `package.json` 中添加：

```json
{
  "scripts": {
    "commit": "cz"
  },
  "config": {
    "commitizen": {
      "path": "node_modules/cz-git"
    }
  }
}
```

### 2.6 Prettier 配置

创建 `.prettierrc.json`：

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "none",
  "printWidth": 100,
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "lf",
  "vueIndentScriptAndStyle": false
}
```

### 2.7 Stylelint 配置

创建 `.stylelintrc.cjs`：

```javascript
module.exports = {
  extends: [
    'stylelint-config-standard-scss',
    'stylelint-config-recess-order'
  ],
  rules: {
    'selector-class-pattern': null,
    'scss/no-global-function-names': null,
    'custom-property-pattern': null,
    'no-descending-specificity': null
  },
  overrides: [
    {
      files: ['**/*.vue'],
      customSyntax: 'postcss-html'
    }
  ]
};
```

## 第三章 提交信息规范【强制】

### 3.1 格式

```
type(scope): subject

[body]

[footer]
```

### 3.2 type 说明

| type | 说明 | 示例 |
|------|------|------|
| feat | 新功能 | feat(hr): 添加员工批量导入功能 |
| fix | 修复bug | fix(finance): 修复报表金额计算精度问题 |
| docs | 文档变更 | docs: 更新API接口文档 |
| style | 代码格式 | style: 统一缩进为2空格 |
| refactor | 重构 | refactor(api): 统一API封装为对象导出式 |
| perf | 性能优化 | perf(table): 虚拟滚动优化大列表渲染 |
| test | 测试 | test(hr): 添加员工管理单元测试 |
| chore | 构建/工具 | chore: 升级Vite到5.4.x |
| revert | 回退 | revert: 回退feat(hr): 添加员工批量导入 |
| build | 构建系统 | build: 优化生产环境打包配置 |

### 3.3 scope 规范

scope 应为模块名称，使用小写：

| scope | 模块 |
|-------|------|
| hr | 人事管理 |
| finance | 财务管理 |
| purchase | 采购管理 |
| warehouse | 仓储管理 |
| order | 订单管理 |
| marketing | 营销管理 |
| product | 产品管理 |
| traceability | 溯源管理 |
| system | 系统设置 |
| security | 安全管理 |
| ui | UI/样式 |
| api | API层 |
| store | 状态管理 |

### 3.4 禁止的提交信息

```
❌ update
❌ fix bug
❌ 修改
❌ wip
❌ test
❌ .
```

## 第四章 门禁检查项【强制】

### 4.1 pre-commit 检查项

| 检查项 | 工具 | 拦截条件 |
|--------|------|---------|
| ESLint规则 | eslint --fix | 存在error级别问题 |
| 代码格式 | prettier --write | 格式不一致 |
| 样式规范 | stylelint --fix | 存在error级别问题 |
| console.log | eslint no-console | 存在console.log/info/debug |
| 直接axios引用 | eslint no-restricted-imports | 存在直接import axios |
| any类型 | eslint @typescript-eslint/no-explicit-any | 存在any类型 |

### 4.2 commit-msg 检查项

| 检查项 | 工具 | 拦截条件 |
|--------|------|---------|
| 提交信息格式 | commitlint | 不符合type(scope): subject格式 |
| type枚举 | commitlint | type不在允许列表中 |
| subject长度 | commitlint | subject超过100字符 |

### 4.3 CI 远程门禁检查项

| 检查项 | 命令 | 拦截条件 |
|--------|------|---------|
| 前端构建 | npm run build | 构建失败 |
| 类型检查 | vue-tsc --noEmit | 存在类型错误 |
| ESLint全量检查 | eslint src/ | 存在error级别问题 |
| 单元测试 | npm run test | 测试失败 |

## 第五章 豁免机制

### 5.1 紧急修复豁免

生产环境紧急修复可临时跳过门禁：

```bash
git commit --no-verify -m "fix(security): 紧急修复XSS漏洞"
```

**要求**：
- 必须在提交信息中说明紧急原因
- 紧急提交后24小时内必须补齐门禁检查
- 每月紧急豁免不超过3次

### 5.2 豁免统计

项目Leader每月审查豁免使用情况，超过3次的团队需说明原因。

## 第六章 常见问题

### Q: lint-staged 检查太慢怎么办？

确保只检查暂存区文件，不要配置全量检查命令。正常情况下应在10秒内完成。

### Q: 如何修复被门禁拦截的提交？

1. 阅读错误信息
2. 根据提示修复代码
3. 重新 `git add` 修复后的文件
4. 重新 `git commit`

### Q: 如何跳过不必要的检查？

不要跳过。如果某条规则不合理，应修改ESLint/CommitLint配置，而非绕过门禁。
