# 部署与运维

## 一、系统要求

### 1.1 运行环境

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 21+ | 后端运行环境 |
| Node.js | >= 18.0.0 | 前端构建环境 |
| npm | >= 9.0.0 | 前端包管理器 |
| PostgreSQL | 18 | 生产数据库 |
| Redis | 7.2.x | 缓存与会话存储 |
| RabbitMQ | 3.12.x | 消息队列 |
| Nginx | 1.24+ | 反向代理与静态文件服务 |

### 1.2 硬件建议

| 环境 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| 开发 | 2核 | 4GB | 20GB |
| 测试 | 4核 | 8GB | 50GB |
| 生产 | 8核+ | 16GB+ | 200GB+ |

### 1.3 操作系统

- 推荐：Ubuntu 22.04 LTS / CentOS 8+
- 支持：Windows Server 2019+ / macOS 12+

## 二、开发环境

### 2.1 后端启动

```bash
# 进入后端目录
cd backend

# 编译项目
mvn clean compile

# 启动后端服务（使用H2内存数据库）
mvn spring-boot:run -DskipTests
```

后端服务地址：`http://localhost:8081/api`

### 2.2 前端启动

```bash
# 进入前端目录
cd frontend

# 安装依赖
npm install

# 启动前端开发服务器
npm run dev
```

前端服务地址：`http://localhost:3000/`

### 2.3 数据库配置

开发环境使用H2内存数据库，应用启动时自动初始化：

- 配置文件：`application-h2.yml`
- 数据初始化：`schema-h2.sql`、`data-h2.sql`
- 控制台访问：`http://localhost:8081/api/h2-console`

### 2.4 开发环境配置要点

```yaml
# application-h2.yml
spring:
  datasource:
    url: jdbc:h2:mem:food_traceability
    driver-class-name: org.h2.Driver
    username: sa
    password:
  h2:
    console:
      enabled: true
      path: /h2-console
  sql:
    init:
      mode: always
      schema-locations: classpath:schema-h2.sql
      data-locations: classpath:data-h2.sql
```

## 四、Nginx配置

### 4.1 基础配置

```nginx
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name example.com;

    # SSL证书配置
    ssl_certificate     /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 前端静态文件服务
    root /var/www/food-traceability/dist;
    index index.html;

    # Gzip压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript;
    gzip_min_length 1024;
    gzip_comp_level 6;

    # 前端路由（History模式）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8081/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
        proxy_send_timeout 60s;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 安全头部
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
}
```

### 4.2 HTTPS配置要点

- 使用TLSv1.2及以上版本
- 禁用弱密码套件
- 启用HSTS头部
- 证书定期更新（建议使用Let's Encrypt自动续期）

|---------|-------------|---------|
| text/html | 默认压缩 | 6 |
| text/css | 1024字节 | 6 |
| application/javascript | 1024字节 | 6 |

## 五、数据库部署

### 5.1 PostgreSQL初始化

```sql
-- 创建数据库和用户
CREATE DATABASE food_traceability
    WITH ENCODING = 'UTF8'
    LC_COLLATE = 'zh_CN.UTF-8'
    LC_CTYPE = 'zh_CN.UTF-8'
    TEMPLATE = template0;

-- 创建应用用户
CREATE USER fts_app WITH PASSWORD '${DB_PASSWORD}';
GRANT ALL PRIVILEGES ON DATABASE food_traceability TO fts_app;

-- 连接到目标数据库
\c food_traceability;

-- 授权schema权限
GRANT ALL ON SCHEMA public TO fts_app;
```

### 5.2 Flyway数据库迁移

```yaml
# application-prod.yml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    baseline-version: 1
    validate-on-migrate: true
```

迁移脚本命名规范：

```
db/migration/
├── V1__init_schema.sql
├── V2__add_employee_table.sql
├── V3__add_trace_tables.sql
└── V4__add_indexes.sql
```

### 5.3 备份策略

| 备份类型 | 频率 | 保留周期 | 存储位置 |
|---------|------|---------|---------|
| 全量备份 | 每日 02:00 | 30天 | 异地存储 |
| WAL归档 | 实时 | 7天 | 本地+异地 |
| 基础备份 | 每周周日 | 90天 | 异地存储 |

全量备份脚本：

```bash
#!/bin/bash
BACKUP_DIR=/backup/postgresql
DATE=$(date +%Y%m%d_%H%M%S)
PGPASSWORD=${DB_PASSWORD} pg_dump \
    -h localhost \
    -U fts_app \
    -d food_traceability \
    -F c \
    -f ${BACKUP_DIR}/full_${DATE}.dump

# 压缩备份文件
gzip ${BACKUP_DIR}/full_${DATE}.dump

# 清理30天前的备份
find ${BACKUP_DIR} -name "*.dump.gz" -mtime +30 -delete
```

WAL归档配置：

```
# postgresql.conf
wal_level = replica
archive_mode = on
archive_command = 'cp %p /backup/postgresql/wal/%f'
```

## 六、Redis部署

### 6.1 持久化配置

```
# redis.conf

# RDB快照配置
save 900 1
save 300 10
save 60 10000
rdbcompression yes
rdbfilename dump.rdb
dir /var/lib/redis

# AOF持久化配置
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec
auto-aof-rewrite-percentage 100
auto-aof-rewrite-min-size 64mb
```

### 6.2 内存策略

```
# redis.conf
maxmemory 4gb
maxmemory-policy allkeys-lru
```

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| `allkeys-lru` | 优先淘汰最近最少使用的键 | 缓存场景（推荐） |
| `volatile-lru` | 淘汰设置了过期时间的最近最少使用的键 | 混合场景 |
| `allkeys-random` | 随机淘汰 | 无明确访问模式 |

## 七、RabbitMQ部署

### 7.1 队列与交换机持久化

```java
/**
 * RabbitMQ配置类
 * 队列和交换机均设置为持久化
 */
@Configuration
public class RabbitMQConfig {

    /**
     * 声明持久化队列
     */
    @Bean
    public Queue traceFoodCreateQueue() {
        return QueueBuilder.durable("trace.food.create")
                .withArgument("x-message-ttl", 86400000)
                .withArgument("x-dead-letter-exchange", "trace.dlx")
                .build();
    }

    /**
     * 声明持久化交换机
     */
    @Bean
    public DirectExchange traceExchange() {
        return ExchangeBuilder.directExchange("trace.exchange")
                .durable(true)
                .build();
    }
}
```

### 7.2 用户权限配置

```bash
# 创建应用用户
rabbitmqctl add_user fts_mq ${RABBITMQ_PASSWORD}

# 设置用户标签
rabbitmqctl set_user_tags fts_mq management

# 授权vhost访问
rabbitmqctl set_permissions -p / fts_mq "trace\." "trace\." "trace\."
```

### 7.3 消息可靠性配置

```yaml
# application-prod.yml
spring:
  rabbitmq:
    host: ${RABBITMQ_HOST:localhost}
    port: ${RABBITMQ_PORT:5672}
    username: ${RABBITMQ_USERNAME}
    password: ${RABBITMQ_PASSWORD}
    publisher-confirm-type: correlated
    publisher-returns: true
    listener:
      simple:
        acknowledge-mode: manual
        prefetch: 10
        retry:
          enabled: true
          max-attempts: 3
          initial-interval: 1000ms
          multiplier: 2.0
          max-interval: 10000ms
```

### 7.4 监控配置

- 启用RabbitMQ Management插件：`rabbitmq-plugins enable rabbitmq_management`
- 监控端口：15672
- 关键指标：队列深度、消息吞吐量、消费者数量、连接数

### 9.1 日志分类

| 日志类型 | 文件名 | 内容 |
|---------|-------|------|
| 应用日志 | `application.log` | 应用运行日志 |
| 查询日志 | `query.log` | 数据库查询日志 |

| 错误日志 | `error.log` | 错误与异常日志 |
| 访问日志 | `access.log` | HTTP请求访问日志 |

### 9.2 日志级别

| 级别 | 说明 | 生产环境使用 |
|------|------|-------------|
| DEBUG | 调试信息 | 否 |
| INFO | 关键业务信息 | 是 |
| WARN | 警告信息 | 是 |
| ERROR | 错误信息 | 是 |

### 9.3 日志配置

```xml
<!-- logback-spring.xml -->
<configuration>
    <property name="LOG_PATH" value="/var/log/food-traceability"/>

    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 应用日志文件 -->
    <appender name="APPLICATION_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/application.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH}/application.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxHistory>30</maxHistory>
            <totalSizeCap>5GB</totalSizeCap>
            <timeBasedFileNamingAndTriggeringPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedFNATP">
                <maxFileSize>200MB</maxFileSize>
            </timeBasedFileNamingAndTriggeringPolicy>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 错误日志文件 -->
    <appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/error.log</file>
        <filter class="ch.qos.logback.classic.filter.LevelFilter">
            <level>ERROR</level>
            <onMatch>ACCEPT</onMatch>
            <onMismatch>DENY</onMismatch>
        </filter>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH}/error.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxHistory>90</maxHistory>
            <totalSizeCap>2GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 生产环境日志级别 -->
    <springProfile name="prod">
        <root level="INFO">
            <appender-ref ref="APPLICATION_FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </root>
    </springProfile>

    <!-- 开发环境日志级别 -->
    <springProfile name="h2">
        <root level="DEBUG">
            <appender-ref ref="CONSOLE"/>
        </root>
    </springProfile>
</configuration>
```

### 9.4 日志轮转策略

| 参数 | 值 | 说明 |
|------|---|------|
| 单文件最大大小 | 200MB | 超过则滚动创建新文件 |
| 最大保留天数 | 30天（普通）/ 90天（错误） | 超过则自动删除 |
| 总大小上限 | 5GB（普通）/ 2GB（错误） | 超过则删除最旧文件 |
| 压缩格式 | gzip | 滚动文件自动压缩 |

## 十、备份与恢复

### 10.1 数据库备份策略

| 备份类型 | 频率 | 保留周期 | 工具 |
|---------|------|---------|------|
| 全量备份 | 每日 02:00 | 30天 | pg_dump |
| WAL归档 | 实时 | 7天 | archive_command |
| 基础备份 | 每周周日 | 90天 | pg_basebackup |

### 10.2 数据库恢复流程

```bash
# 1. 停止应用服务
systemctl stop food-traceability

# 2. 停止PostgreSQL
systemctl stop postgresql

# 3. 恢复全量备份
pg_restore \
    -h localhost \
    -U postgres \
    -d food_traceability \
    -c \
    /backup/postgresql/full_20240101_020000.dump.gz

# 4. 恢复WAL日志（如需时间点恢复）
recovery_target_time = '2024-01-01 12:00:00'

# 5. 启动PostgreSQL
systemctl start postgresql

# 6. 验证数据完整性
psql -h localhost -U fts_app -d food_traceability -c "SELECT count(*) FROM employees;"

# 7. 启动应用服务
systemctl start food-traceability
```

### 10.3 文件备份策略

| 备份内容 | 频率 | 保留周期 | 方式 |
|---------|------|---------|------|
| 应用配置文件 | 每次变更 | 永久 | Git版本控制 |
| 上传文件目录 | 每日 | 30天 | rsync |
| 日志文件 | 每日 | 7天 | logrotate |
| SSL证书 | 每次更新 | 永久 | 安全存储 |

### 10.4 灾难恢复

| 场景 | RTO | RPO | 恢复方案 |
|------|-----|-----|---------|
| 数据库损坏 | 4小时 | 1小时 | 全量备份 + WAL恢复 |
| 服务器故障 | 2小时 | 0 | 主从切换 |
| 数据误删 | 8小时 | 0 | 时间点恢复（PITR） |
| 机房故障 | 24小时 | 1小时 | 异地备份恢复 |

## 十一、安全部署检查清单

### 11.1 网络安全

- [ ] 仅开放必要端口（80/443/8081）
- [ ] 数据库端口（5432）不对外暴露
- [ ] Redis端口（6379）不对外暴露
- [ ] RabbitMQ端口（5672/15672）不对外暴露
- [ ] 配置防火墙规则，限制内网访问

### 11.2 数据传输安全

- [ ] PostgreSQL启用SSL/TLS加密连接
- [ ] Redis启用TLS加密连接
- [ ] RabbitMQ启用TLS加密连接
- [ ] 前端强制HTTPS访问
- [ ] API接口仅通过Nginx反向代理访问

### 11.3 认证与授权

- [ ] JWT密钥长度 >= 64字节，使用安全随机数生成
- [ ] JWT令牌过期时间合理设置（访问令牌30分钟，刷新令牌7天）
- [ ] 数据库应用用户遵循最小权限原则
- [ ] Redis设置密码认证
- [ ] RabbitMQ用户权限按vhost隔离

### 11.4 应用安全

- [ ] CORS严格限制生产域名，禁止使用 `*`
- [ ] 敏感配置使用Jasypt加密存储
- [ ] 禁止在日志中输出敏感信息（密码、令牌等）
- [ ] 启用Spring Security安全头部
- [ ] SQL注入防护（MyBatis Plus参数化查询）
- [ ] XSS防护（输入过滤 + 输出编码）

### 11.5 运维安全

- [ ] 定期更新系统安全补丁
- [ ] 定期轮换数据库密码和API密钥
- [ ] 审计日志记录关键操作
- [ ] 禁止root用户运行应用服务
- [ ] 文件权限最小化（配置文件600，日志目录755）

### 11.6 备份安全

- [ ] 备份文件加密存储
- [ ] 异地备份存储
- [ ] 定期验证备份可恢复性（至少每季度一次）
- [ ] 备份访问权限严格控制
