# 第十一轮：取单窗口——固定尺寸 + 展开核对 + 显式取单

> 反馈两点：① 空载与满载窗口大小差异明显；② 点击行直接取单，无法先看折叠内容，近似订单容易取错（发现→重挂，没发现→付款后客诉）。
> 验证：九套 E2E 共 **163 项断言全绿**。

---

## 一、为什么没有选"全展开"或"点开再取单"

| 方案 | 问题 |
|---|---|
| **全部展开**（你想法一） | 一张挂单 3~8 个菜，12 张就是 40+ 行；一屏放不下 2 张，等于回到"滚着找单"，反而更难对比"哪张才是客人要的" |
| **点行展开 → 再点取单**（你想法二） | 多一次点击；且展开后按钮位置会跳动，收银员容易点到下一张单 |
| **本方案：行体点击 = 展开核对，行尾「取单」按钮 = 一步取单** | 两条路径都只花 1 次点击：无争议的单点按钮直接走；有争议的单点行展开核对全部菜品，再点同一个按钮（按钮位置固定不动） |

关键点：**取单动作与"看"的动作分离**——点行体永远不会取单，所以随便点都不会误操作；而按钮常驻，不需要先展开才能取，避免了"二次操作"。

## 二、改动明细

### 1. 弹窗固定尺寸（解决"忽大忽小"）

```css
body .retrieve-dialog.el-dialog { height: min(690px, 88vh); }  /* 原来只有 max-height */
```
空态与满载实测都是 **690px**（720 高视口都是 619px），不再有尺寸跳变。

### 2. 行体展开：完整明细

点行体 / 按 Enter 展开，显示：
- `挂单 2026-10-28 10:00:00` + `备注：客人取钱`
- 全部菜品两列网格：`菜品名 ×数量 小计金额`（不再只给"前 2 项 +N"）

行高保持 62px（未展开时），一屏仍可见 6 张；展开的那张会撑高，其他行下移，列表整体滚动。

### 3. 取单入口

| 操作 | 行为 |
|---|---|
| 点行体 | 展开 / 收起明细（**不取单**） |
| 点行尾「取单」 | 立即取单（默认描边，悬停/当前行填充主色，避免 6 个实心橙按钮变成色墙） |
| ↑ ↓ | 移动当前行（自动滚入视野） |
| Enter | 展开核对当前行（不会误取单） |
| Shift+Enter | 直接取单（键盘熟练路径） |

保留原有护栏：购物车非空时弹「替换购物车？」确认，并把当前车自动挂起。

### 3.5 其他细节

- 空列表时隐藏键盘提示（之前空态也显示"↑↓ 选择…"很怪）；
- 空态、搜索无结果、有数据三种状态同一高度，切换不跳动；
- 取单按钮 / 行体都保留 ≥ 34px 高、整行可点的大热区（触屏友好）。

## 五、如果仍想"一眼全见"

那需要把弹窗换成**左侧列表 + 右侧明细**的双栏布局（行业协会后台常见），宽 1000px+：左边仍是紧凑行，右边常驻显示选中挂单的全部菜品，取单按钮放右栏。这样"全见"和"不误取"能同时满足，但要多占 40% 宽度，且行数多时右栏要跟着滚动。如果你的收银机是 1440 宽以上，我可以按这版再做一版给你对比。
