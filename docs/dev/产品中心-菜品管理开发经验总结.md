# 产品中心 - 菜品管理开发经验总结

> 面向后续接手开发的智能体/新窗口会话，目标是**避免再次出现不一致**，遵循黄金标准一次做对。

---

## 一、黄金模板：ModernEmployee

任何新页面开发，**第一步永远是研读 demo**：

| 文件 | 路径 | 作用 |
|------|------|------|
| **黄金模板** | `frontend-new/src/views/Demo/ModernEmployee.vue` | 页面布局、组件组合、CSS类名、间距规范的唯一权威参考 |
| **工具栏参考** | `frontend-new/src/views/Demo/components/AdvancedSearchPanel.vue` | 搜索筛选+导入导出的标准工具栏模式 |

**不要**参考 `frontend` 下的旧页面（如 `FoodList.vue`）——它使用了过时的 `StandardPage` 模式。

---

## 二、页面布局五段式结构（强制）

```html
<div class="modern-page">                    <!-- 页面根容器 -->
  <PageHeader>                               <!-- 标题+主操作按钮 -->
  <section class="stats-section">            <!-- 统计卡片网格 -->
  <div class="advanced-search-panel">        <!-- 工具栏（搜索+导入导出） -->
    <div class="toolbar-row">
      <div class="toolbar-left">  ...  </div>
      <div class="toolbar-right"> ...  </div>
  <section class="table-section">            <!-- 表格+分页 -->
  <el-dialog>                                <!-- 编辑弹窗（如有） -->
```

**关键规则**：
- 顶部 `PageHeader` 只放**主操作按钮**（如"新增菜品"），不放导入/导出
- 导入/导出放在 `toolbar-right` 中
- 筛选条件放在 `toolbar-left` 中
- 表格和分页在同一个 `table-section` 中，分页用 `pagination-wrapper` 包裹且靠右对齐
- 统计卡片使用 `<StatCard icon="..." label="..." :value="..." color-type="..." variant="bordered" />`

## 三、组件使用硬规则

| 场景 | ✅ 正确 | ❌ 错误 |
|------|---------|---------|
| 状态字段 | `<StatusTag status="active" />` | `<el-tag>` |
| 分类/部门 | `<StatusTag category="food-hot" label="热菜" />` | `<el-tag>` 或裸 `<span>` |
| 操作列按钮 | `<el-button link type="primary">编辑</el-button>` | `<el-button text>` 或带图标 |
| 表格 | `<DataTable :stripe="..." :hover="..." />` | 直接用 `<el-table>` |
| 颜色值 | `var(--fts-primary)` | `#409EFF` |
| 间距 | `var(--fts-space-4)` | 硬编码 `16px` |
| 字体大小 | `var(--fts-font-size-base)` | 硬编码 `14px` |
| API请求 | `request.get(url, params)` | `axios.get()` 或 `fetch()` |

## 四、DataTable 与 layoutStore 连线（最容易遗漏）

```html
<script setup>
import { useLayoutStore } from '@/stores/layout'
const layoutStore = useLayoutStore()
</script>

<template>
  <DataTable
    :stripe="layoutStore.tableStriped"   <!-- 斑马纹开关 -->
    :hover="layoutStore.tableHover"      <!-- 悬停高亮开关（最容易忘记！） -->
    :border="false"
  />
</template>
```

**不传 `:hover` 的后果**：DataTable 默认 `hover=true`，设置面板的"悬停高亮"开关完全无效。

## 五、设计令牌文件职责

| 文件 | 放什么 | 不放什么 |
|------|--------|----------|
| `_tokens.scss` | `:root` 下所有 CSS 变量定义（浅色模式默认值） | 选择器、组件样式 |
| `_dark-mode.scss` | `html.dark` 下覆盖的变量值 + Element Plus 组件深色覆盖 | 与浅色模式相同的变量（除非值不同） |
| `_base.scss` | 全局样式规则、`html.*` 状态类 | CSS 变量定义 |

**新增 CSS 变量的标准流程**：
1. 在 `_tokens.scss` 的 `:root` 中定义浅色默认值
2. 在 `_dark-mode.scss` 的 `html.dark` 中定义深色覆盖值
3. 在组件中使用 `var(--fts-xxx)` 引用

## 六、StatusTag 分类体系

**分类颜色原则**：分类（category）应当像部门（department）一样使用**统一的品牌色**，不要五花八门。图标本身已经足够区分不同类型，颜色留给状态（status）列表达。

```typescript
// categoryConfig 中的 colorVar
{ department: 'primary', position: 'primary', 'food-hot': 'primary', ... }
// 所有分类 → primary 统一色，图标做区分
```

**图标视觉增强**通过 CSS 变量实现，支持浅色/深色双主题：

| 变量 | 浅色 | 深色 |
|------|------|------|
| `--fts-category-tag-shadow` | 内高光+外阴影 | 微弱内高光+暗阴影 |
| `--fts-category-tag-icon-bg` | 半透明白背景 | 微弱白色背景 |
| `--fts-category-tag-icon-border` | 12% 黑色边框 | 15% 白色边框 |
| `--fts-category-tag-icon-shadow` | 内阴影 | 微弱内高光 |
| `--fts-category-tag-text-shadow` | 文字浮雕高光 | 暗色文字阴影 |

## 七、新增分类图标的标准流程

1. 在 `StatusTag.vue` 的 import 中添加图标组件
2. 在 `CategoryType` 中添加新的类型名
3. 在 `categoryConfig` 中添加映射（`colorVar` 统一用 `'primary'`）
4. 在 `_tokens.scss` 中添加对应的 CSS 变量（如 `--fts-category-xxx-color/bg/border`）
5. 在 `_dark-mode.scss` 中添加深色模式覆盖
6. 在 StatusTag 的 `<style>` 中添加 `&--xxx { }` 样式块
7. 在页面中使用 `<StatusTag category="xxx" :label="..." size="medium" />`

## 八、表格样式增强规范

```scss
.table-section {
  background: var(--fts-bg-card);
  border: 1px solid var(--fts-border-primary);  // 必须用 primary，不用 border-color
  border-top: none;
  border-radius: 0 0 var(--fts-page-radius) var(--fts-page-radius);

  // 表头底部强化分隔
  :deep(.el-table__header-wrapper th) {
    border-bottom: 2px solid var(--fts-border-primary);
  }

  // 行间分隔线强化
  :deep(.el-table__row td) {
    border-bottom: 1px solid var(--fts-border-primary);
  }
}
```

当 `.advanced-search-panel` 和 `.table-section` 上下紧邻时：
- `.advanced-search-panel` 的 `border-bottom` 作为分隔线
- `.table-section` 设置 `border-top: none` 避免双线

## 九、本次会话踩过的坑

| 坑 | 原因 | 教训 |
|----|------|------|
| 工具栏位置不对 | 导入导出放在 PageHeader，不是 toolbar-right | 严格对照 demo 的结构顺序 |
| 表格斑马纹/悬停不生效 | DataTable 只传了 `stripe` 没传 `hover` | DataTable 的所有设置 prop 都要连线 layoutStore |
| `--fts-border-color` 不存在 | 用了未定义的变量名 | 始终从 `_tokens.scss` 确认变量名存在 |
| 分类颜色五花八门 | food-hot/error、food-soup/success 等 | 分类=统一 primary，只有 status 用区分色 |
| 字体变量重复定义 | 历史遗留的 `--fts-font-size-base` 出现两次 | 修改前检查文件是否有重复定义 |
| 页面缩放变量定义在字体变量之后 | CSS `calc()` 引用了后面才定义的变量 | 缩放变量必须放在被引用的变量**前面** |

## 十、新页面开发检查清单

开工前逐条确认：

1. **Demo 研读了没？** —— `ModernEmployee.vue` 的五段式结构看清楚了吗？
2. **组件选对了吗？** —— StatusTag / DataTable / StatCard / PageHeader，不是 el-tag / el-table
3. **DataTable 连线了吗？** —— `stripe`、`hover` 两个 prop 都接了 `layoutStore`？
4. **CSS 变量用了吗？** —— 搜索页面中的 `#` 或固定 `px` 值，替换为 `var(--fts-*)`
5. **深色模式覆盖了吗？** —— 新增的 CSS 变量在 `_dark-mode.scss` 有对应值吗？
6. **禁止事项遵守了吗？** —— `project_rules.md` 第二十六条禁止清单逐条对照
7. **操作列按钮是 `link` 类型吗？** —— `<el-button link>`，不是 `<el-button text>`
8. **分类标签用了 `size="medium"` 吗？** —— 统一使用 medium 尺寸
9. **表格列宽用了 `minWidth` 而非 `width` 吗？** —— 保证弹性分布
10. **数字列用了 `font-variant-numeric: tabular-nums` 吗？** —— 保证等宽数字对齐
