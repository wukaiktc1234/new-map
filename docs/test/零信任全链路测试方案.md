> **数据库决策**：全程使用 PostgreSQL 替代 H2 内存数据库，确保数据持久化、SQL 方言 100% 兼容，真实反映生产环境行为

## 一、测试策略总览

### 1.1 测试目标

1. **数据完整性验证**：确保各业务流的数据在流转过程中不丢失、不错乱
2. **财务逻辑一致性**：验证收入-成本-利润的勾稽关系正确
3. **边界与异常处理**：测试系统在极端/异常输入下的行为
4. **并发安全性**：验证 CAS 锁、乐观锁在并发场景下的有效性
5. **数据权限隔离**：验证不同角色/门店的数据隔离正确性

### 1.2 测试原则

| 原则        | 说明                          |
| --------- | --------------------------- |
| **零信任**   | 不信任任何前置条件，每一步都独立验证结果        |
| **破坏性优先** | 优先构造异常场景（库存不足、金额不匹配、状态冲突）   |
| **财务审计级** | 每个涉及资金/成本的环节，验证借贷平衡和勾稽关系    |
| **端到端闭环** | 每个业务流必须完成正向 → 逆向 → 数据核对的全过程 |

### 1.3 测试环境

| 项目              | 配置                                                      |
| --------------- | ------------------------------------------------------- |
| 后端服务            | <http://localhost:8081/api>                             |
| 前端服务            | <http://localhost:3000>                                 |
| 数据库             | **PostgreSQL 18**（`localhost:5432`，`food_traceability`） |
| 缓存              | 禁用（`spring.cache.type=none`）                            |
| 消息队列            | 禁用                                                      |
| 测试账号            | admin / Admin\@123（超级管理员，全部权限）                          |
| postgerSQL数据库密码 | 123456                                                  |

> **数据库选择说明**：使用 PostgreSQL 而非 H2 内存数据库，原因：
>
> 1. 数据持久化，支持跨会话验证和增量测试
> 2. 100% SQL 兼容性，避免 H2 兼容模式下的方言差异
> 3. 真实反映生产环境性能特征

## 二、执行顺序与依赖关系

### 2.1 执行顺序

```
阶段1：基础数据准备（产品中心）
  ↓
阶段2：客户数据（会员管理）
  ↓
阶段3：固定资产（资产管理）
  ↓
阶段4：门店运营数据（门店运营）
  ↓
阶段5：追溯数据（溯源管理）
  ↓
阶段6：辅助管理（运营中心/人事/设备/系统管理）
  ↓
阶段7：全链路回归（数据一致性验证）
```

### 2.2 模块依赖矩阵

| 模块   | 依赖的前置数据 | 提供的数据       |
| ---- | ------- | ----------- |
| 产品中心 | 无       | 菜品、分类、配方、定价 |
| 会员管理 | 无       | 会员等级、积分、余额  |
| 资产管理 | 分类数据    | 资产台账、折旧、处置  |
| 门店运营 | 门店数据    | 桌台、排班、日结    |
| 溯源管理 | 产品+采购数据 | 追溯码、追溯链     |
| 运营中心 | 全模块数据   | 经营看板、分析报表   |
| 人事管理 | 部门数据    | 员工、薪酬、考勤    |
| 设备管理 | 门店数据    | 设备台账、维修     |
| 系统管理 | 无       | 用户、角色、权限    |
