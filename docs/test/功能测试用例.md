# 食品溯源系统管理端 - 功能测试用例

> **文档版本**：v1.0
> **文档日期**：2026-07-01
> **测试范围**：管理端 12 大业务域 + 系统管理 + 跨模块数据流转
> **适用环境**：开发环境（H2 内存数据库，MODE=PostgreSQL 兼容模式）

---

## 一、测试概述

### 1.1 测试目标

验证食品溯源系统管理端各业务模块功能是否符合需求规格，确保 UI 交互、业务流程、数据流转的完整性与正确性，为生产环境商用上线提供质量保障。

### 1.2 测试环境

| 项目 | 配置 |
|------|------|
| 后端服务 | http://localhost:8081/api |
| 前端服务 | http://localhost:3000 |
| 数据库 | H2 内存数据库（MODE=PostgreSQL 兼容模式） |
| 缓存 | Redis（本地默认配置） |
| 消息队列 | RabbitMQ（本地默认配置） |
| 浏览器 | Chrome 90+（主测浏览器） |

### 1.3 测试账号

| 角色 | 账号 | 密码 | 权限范围 |
|------|------|------|---------|
| 超级管理员 | admin | Admin@123 | 全部 96 权限码 |
| 店长 | store_manager | Store@123 | 门店范围业务权限 |
| 财务主管 | finance_director | Finance@123 | 财务中心权限 |
| 人事主管 | hr_director | HR@123 | 人事管理权限 |
| 普通员工 | employee | Emp@123 | 基础查询权限 |

### 1.4 优先级定义

| 优先级 | 含义 | 适用场景 |
|--------|------|---------|
| P0 | 核心用例 | 阻塞业务流程的核心功能，必须通过 |
| P1 | 重要用例 | 影响业务完整性的重要功能，应通过 |
| P2 | 一般用例 | 边界值、异常输入、辅助功能，建议通过 |

### 1.5 用例编号规则

`TC-{MODULE}-{NNN}`，其中 MODULE 为模块缩写：
- LOGIN 登录认证 | PRODUCT 产品中心 | PURCHASE 采购管理 | WAREHOUSE 仓储管理
- FINANCE 财务中心 | HR 人事管理 | TRACE 食品追溯 | OPERATIONS 运营中心
- STORE 门店管理 | MEMBER 会员管理 | ORDER 订单管理 | DEVICE 设备管理
- SEAL 电子签章 | SYSTEM 系统管理 | CROSS 跨模块流转

### 1.6 缺陷严重程度

| 级别 | 含义 | 示例 |
|------|------|------|
| Critical | 阻塞主流程，无绕过方案 | 登录失败、订单创建报错、数据丢失 |
| High | 功能不可用但有绕过方案 | 列表查询失败、导出报错、状态显示错误 |
| Medium | 部分功能异常 | 校验提示不准、样式错乱、性能较慢 |
| Low | 体验问题 | 文案错误、对齐偏差、提示不友好 |
