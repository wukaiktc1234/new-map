# 食品溯源系统管理端 - 安全测试方案

> **文档版本**：v1.0
> **文档日期**：2026-07-01
> **测试范围**：管理端认证授权、数据安全、输入验证、会话管理、审计日志
> **适用环境**：开发环境（H2）+ 生产环境模拟

---

## 一、测试概述

### 1.1 测试目标

验证食品溯源系统管理端的安全防护能力，发现潜在安全漏洞，确保系统满足数据保护、权限控制、审计追溯等安全要求，为生产环境商用上线提供安全保障，符合食品安全溯源行业的合规要求。

|------|------|
| 后端服务 | http://localhost:8081/api |

| 测试账号 | admin / Admin@123（超级管理员） |
| 数据库 | H2 内存（开发）/ PostgreSQL 18（生产模拟） |

## 二、认证安全测试

### TC-SEC-AUTH-001 JWT Token 安全性验证

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 测试目标 | 验证 JWT Token 的安全性 |
| 前置条件 | 已登录获取 token |
| 操作步骤 | 1. 登录获取 token<br>2. 解析 token 查看 payload（含 userId、roleId、exp）<br>3. 验证 token 签名算法（HS256/RS256）<br>4. 篡改 token payload 后使用<br>5. 使用过期 token |
| 预期结果 | 1. token 含 exp 声明，有效期 30 分钟<br>2. 签名算法非 "none"<br>3. 篡改 token 后签名校验失败，返回 401<br>4. 过期 token 返回 401，提示重新登录<br>5. token 不包含敏感信息（密码、身份证号） |

### TC-SEC-AUTH-002 Refresh Token 机制验证

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 测试目标 | 验证 Refresh Token 安全机制 |
| 前置条件 | 已登录 |
| 操作步骤 | 1. 等待 access token 过期<br>2. 使用 refresh token 刷新<br>3. 验证新 token 与旧 token 不同<br>4. 重复使用已刷新的 refresh token<br>5. 篡改 refresh token |
| 预期结果 | 1. 刷新成功返回新 access token<br>2. 新 token 与旧 token 签名不同<br>3. 旧 refresh token 失效（一次性使用）<br>4. 篡改 refresh token 返回 401<br>5. refresh token 有效期 7 天 |

### TC-SEC-AUTH-003 暴力破解防护

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 测试目标 | 验证账号锁定机制 |
| 前置条件 | admin 账号存在 |
| 操作步骤 | 1. 使用错误密码连续登录 5 次<br>2. 第 6 次使用正确密码<br>3. 等待 15 分钟后再次尝试 |
| 预期结果 | 1. 连续 5 次失败后账号锁定<br>2. 锁定后正确密码也无法登录<br>3. 锁定 15 分钟后自动解锁<br>4. 登录日志记录失败尝试<br>5. 同一 IP 多账号失败触发 IP 限制 |

### TC-SEC-AUTH-004 密码强度策略

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 测试目标 | 验证密码复杂度要求 |
| 前置条件 | 修改密码功能可用 |
| 操作步骤 | 1. 尝试设置密码：123（纯数字）<br>2. 尝试设置密码：password（纯字母）<br>3. 尝试设置密码：&lt;redacted&gt;（常见组合）<br>4. 尝试设置密码：Admin@123（合规）<br>5. 尝试设置密码与账号相同 |
| 预期结果 | 1. 密码长度 < 8 位：拒绝<br>2. 无大小写混合：拒绝<br>3. 无特殊字符：拒绝<br>4. 常见弱密码：拒绝<br>5. 与账号相同：拒绝<br>6. 合规密码：接受 |

### TC-SEC-AUTH-005 密码加密存储

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 测试目标 | 验证密码不以明文存储 |
| 前置条件 | 数据库访问权限 |
| 操作步骤 | 1. 查询 users 表 password 字段<br>2. 比对存储值与原密码<br>3. 验证哈希算法（BCrypt/Argon2） |
| 预期结果 | 1. password 字段为哈希值，非明文<br>2. 同一密码哈希值不同（盐值随机）<br>3. 使用 BCrypt 或更强算法<br>4. 哈希成本 >= 10 |

### TC-SEC-AUTH-006 多因素认证（MFA）

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 测试目标 | 验证 MFA 机制（如启用） |
| 前置条件 | MFA 已配置 |
| 操作步骤 | 1. 用户登录账号密码<br>2. 系统要求输入验证码<br>3. 输入正确验证码<br>4. 重新登录输入错误验证码 |
| 预期结果 | 1. 账号密码正确后进入二次验证<br>2. 验证码 6 位数字，5 分钟有效<br>3. 正确验证码登录成功<br>4. 错误验证码登录失败<br>5. 验证码错误 5 次锁定 |

### TC-SEC-AUTH-007 验证码机制

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 测试目标 | 验证登录验证码防护 |
| 前置条件 | 登录页验证码功能启用 |
| 操作步骤 | 1. 多次失败登录后是否要求验证码<br>2. 验证码是否一次性<br>3. 验证码是否可重放 |
| 预期结果 | 1. 多次失败后强制验证码<br>2. 验证码使用后立即失效<br>3. 验证码不可重放<br>4. 验证码图片可识别 |

## 十一、安全测试执行流程

### 11.1 测试准备

1. **环境准备**
   - 搭建隔离测试环境
   - 准备测试数据（脱敏）
   - 安装安全测试工具

2. **授权获取**
   - 获得书面测试授权
   - 明确测试范围与时间
   - 通知相关团队

3. **基线扫描**
   - 自动化漏洞扫描
   - 识别明显问题

### 11.2 测试执行

1. **认证授权测试**
   - 逐项执行认证测试用例
   - 验证权限模型
   - 测试越权场景

2. **注入测试**
   - SQL 注入测试
   - XSS 测试
   - 命令注入测试

3. **数据安全测试**
   - 敏感数据扫描
   - 传输加密验证
   - 存储加密验证

4. **渗透测试**
   - 模拟攻击者视角
   - 链式利用漏洞
   - 验证影响范围

### 11.3 结果分析

1. **漏洞分级**
   - Critical：立即修复
   - High：48 小时内修复
   - Medium：一周内修复
   - Low：迭代修复

2. **修复验证**
   - 修复后回归测试
   - 验证修复彻底性
   - 检查无引入新问题

根据项目待修复问题清单（PENDING_ISSUES_BACKLOG.md）和管理端产品审视报告，以下安全问题需重点关注：

### 13.1 已知问题

| 问题 | 风险等级 | 状态 | 修复建议 |
|------|---------|------|---------|

| 运营中心权限过滤失效（STORE_MANAGER 可见全部门店） | High | 待修复 | 接入当前用户 storeId 过滤数据 |

| 14 个 @Deprecated 硬件 Controller | Medium | 待处理 | 下沉为 DeviceDriver 实现 |

### 13.2 安全加固建议

1. **认证加固**
   - 启用 MFA（针对管理员）
   - 密码定期强制更换
   - 登录异常告警

2. **授权加固**
   - 完成所有接口 @PreAuthorize 注解
   - 数据隔离统一通过拦截器实现
   - 权限变更实时生效

3. **数据加固**
   - 敏感字段统一加密
   - 日志统一脱敏
   - 数据库连接加密

4. **审计加固**
   - 关键操作强制审计
   - 日志独立存储
   - 日志防篡改（区块链/数字签名）
