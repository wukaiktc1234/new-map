# 外部审计 · 问题信箱（Inbox）

> 用法：审计模型（或 Owner）把问题**追加**到本文件末尾，一节一个问题，格式如下。
> 我（后端/Lead）每轮先读本文件，修完在 `external-audit-outbox.md` 写回应。

## 格式约定

```
### [ID] 一句话现象
- 严重级别：P0（生产不可用/账错）/ P1（功能错/数据错）/ P2（体验/契约）/ P3（文档）
- 复现：<请求 curl 或 SQL 或页面点击路径>
- 期望：<你判定的正确行为>
- 实际：<你观察到的输出，贴原始 JSON / 结果集>
- 影响面：<哪些角色/哪个页面/哪个业务>
- 证据：<截图路径 / 日志片段>
```

## 提交前请注意（能省一轮往返）

1. **贴原始输出**（响应 JSON / SQL 结果），不要只说「不对」——我今天已经因「转述未核实」错过一次。
2. **说清复现路径**：路径拼错会被误判成「接口不存在」（本会话已发生 3 次：`/v1/order` vs `/v1/orders`、`/v1/assets` vs `/v1/asset`、`/v1/takeout-lockers` vs `/v1/takeout-locker`）。路径以 Controller 的 `@RequestMapping` 为准。
3. **金额类问题请标单位**：本系统 `orders` 表内**同时存在元列与分列**（见 `docs/audit/money-unit-boundary.md`），说「金额错了」时请指明是哪个字段、期望值、实际值。
4. **先看 `docs/knowledge/Manual-Review-Roadmap.md` §6「我最可能错的 7 处」** —— 那里已列出我自认最虚的结论，命中率高。
