## 1. 签名画板（ReceivingMobile 收货签名）

### 1.1 环境
- 设备：真机平板/一体机（横屏），建议同时用一台手机窄屏做回归。
- 账号：具备收货权限的门店账号（store_id=1）。
- 后端：`http://<host>:8081/api`，前端 `frontend` dev 或打包 H5。
- 准备：一张「待确认」的收货单（`receipt_confirmations`），或按 1.4 用历史单走「补签」。

### 1.2 步骤与预期

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开收货移动端页面 `/store-ops/receiving-mobile`（菜单「收货确认）」 | 页面正常渲染，无白屏/无 console error |
| 2 | 点「签名」→ 弹出签名区（竖屏为底部面板，横屏为全屏覆盖层） | 覆盖层出现后**画布占满可写区域**，提示语「请在此处签名」可见 |
| 3 | 用手指/触控笔连续签名 3~5 笔 | 线条跟手、无断线、无偏移；画布不被页面滚动带走（`touch-action` 生效） |
| 4 | 点「清空」再签一次 | 画布清空无残影；重签正常 |
| 5 | 点「完成/确定」 | 请求 `POST /v1/receipt-confirmations/{id}/signatures`，返回 `code=0`；页面回到主表单并提示成功 |
| 6 | 刷新页面 / 重新进入该单 | 已签名状态保留（`GET .../signatures` 能回读），缩略图/签名图可见 |
| 7 | 库里核验：`SELECT confirmation_id, signer_name, length(signature_image) FROM receipt_confirmation_signatures WHERE confirmation_id='<id>';` | 有行、图片 base64 长度 > 1000 字符（1x1 假图会明显偏小） |
| 8 | 断开后端（停 8081 或断网）后点「完成」 | **必须显式报错**（如「保存失败，请重试」），不得静默成功、不得白屏；重连后可重试成功 |
| 9 | 旋转屏幕（竖→横→竖）后再签 | 画布尺寸自适应，签名坐标不偏移（历史 bug：横屏坐标错位） |
| 10 | 空签名直接提交 | 前端拦截或后端返回业务错误码（不能落一条空图记录） |

### 1.3 判据
- 第 5/6/7 条全过 = 签名**落库可用**；第 8 条过 = **失败不吞单**；第 9 条过 = **横屏无坐标缺陷**。
- 任一不过 → 记录设备型号 + 浏览器内核版本 + 截图，回到开发。

### 1.4 补签场景（历史确认单签名缺失）
1) 找一张已确认但无签名的历史单；2) 页面走「补签」入口重新进入签字流程；3) 重复 1.2 的 3~7 步；4) 预期：原记录不被覆盖成空，新增签名行可追溯（谁在什么时候补的）。

## 2. 扫码桥

### 2.A 若采用「扫码枪键盘模拟」（当前代码唯一可支撑的形态）
| # | 操作 | 预期 |
|---|---|---|
| 1 | 把光标置于 POS 商品/托盘/订单搜索输入框 | 输入框获得焦点（有可见焦点态） |
| 2 | 扫商品条码（如 `FD260925001`） | 条码字符完整进入输入框，**不丢首位/不多回车**；自动触发查询或加入购物车 |
| 3 | 连续快速扫 5 个不同码 | 5 次都命中，无串码、无漏扫；列表数量正确 |
| 4 | 扫一个库中不存在的码 | 明确提示「未找到」，不写脏数据 |
| 5 | 中文/特殊字符键盘输入与扫码混用 | 扫码内容不被输入法截断 |
判据：2/3/4 全过 = 扫码枪链路可用。

### 2.B 若产品要求原生扫码桥（安卓 WebView / JSSDK / 自定义 scheme）
**当前仓库无实现**，验收前需先确认：
1) 载体与接口契约（谁调谁、回调怎么回、超时/取消怎么表示）；
2) 权限（相机权限、扫码 SDK 版本）；
3) 失败兜底（扫码取消/相机被占用/无权限时的 UI）。
确认后可沿用 2.A 的 1~5 条作为功能判据，并补三条真机专项：
- 冷启动首次扫码（授权弹窗路径）；
- 后台切回后扫码（相机释放/重连）；
- 弱光/反光条码（识别率与重试提示）。

## 3. 离线暂存重传

**当前仓库无实现**（无本地队列、无重传器、无离线同步端点）。若 Owner 确认该能力在版本范围内且已在某分支实现，按下列判据验收：

| # | 场景 | 预期 |
|---|---|---|
| 1 | 断网（飞行模式）下 POS 下单 | 明确提示「离线，已暂存」；单号本地生成且不重复；**不能出现"假成功"** |
| 2 | 断网期间连续下 3 单 | 3 条都进本地队列，顺序可查（列表可见待重传条数与时间） |
| 3 | 恢复网络 | 自动按序重传；每条返回 `code=0`；UI 待重传数归零 |
| 4 | 重传幂等 | 同一条重复触发（手动点「重试」+ 自动重传并发）**只落一单**（后端幂等键：`idempotency_key`） |
| 5 | 重传过程中断网/杀进程 | 重启后队列不丢，可继续重传；不出现半条脏单（支付成功但明细缺失） |
| 6 | 长时间离线（>24h）后再上网 | 有明确策略（全部重传 / 提示过期作废），不能静默丢弃 |
| 7 | 离线期间的价格/库存 | 以本地快照下单，重传时若价格已变 → 明确冲突提示，不静默改价 |
判据：1/3/4/5 为**红线**（假成功、重复落单、丢单），任一不过即判 FAIL。
