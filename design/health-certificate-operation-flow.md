## 详细操作说明

### 门店端健康证操作

1. **新增健康证**
   - 员工或管理员在门店端新增健康证信息
   - 初始状态：草稿 (draft)
   - 填写字段：员工姓名、健康证号、发证日期、有效期、发证机构等

2. **编辑健康证**
   - 仅允许编辑草稿状态的健康证
   - 可修改所有健康证信息
   - 保存后仍为草稿状态

3. **提交审核**
   - 仅允许提交草稿状态的健康证
   - 提交后状态变为：待审核 (pending)
   - 自动同步至人事系统

4. **审核健康证**
   - 仅允许审核待审核状态的健康证
   - 审核通过：状态变为已通过 (approved)
   - 审核拒绝：状态变为已拒绝 (rejected)，需填写拒绝原因

5. **申请报销**
   - 仅允许为已通过审核的健康证申请报销
   - 填写报销金额、事由等信息
   - 提交后自动同步至财务系统
   - 报销状态：待审核 (pending)

6. **删除健康证**
   - 仅允许删除草稿状态的健康证
   - 管理员可删除任何状态的健康证
   - 删除后数据进入回收站或永久删除

### 人事端健康证操作

1. **新增健康证**
   - HR或管理员在人事端新增健康证
   - 初始状态：草稿 (draft)
   - 可直接为员工创建健康证

2. **编辑健康证**
   - 仅允许编辑草稿状态的健康证
   - 可修改所有健康证信息

3. **提交审核**
   - 仅允许提交草稿状态的健康证
   - 提交后状态变为：待审核 (pending)

4. **审核健康证**
   - 仅HR专员和管理员可审核
   - 审核通过：状态变为已通过 (approved)
   - 审核拒绝：状态变为已拒绝 (rejected)

5. **申请报销**
   - 仅允许为已通过审核的健康证申请报销
   - 填写报销信息并提交
   - 自动同步至财务系统

6. **删除健康证**
   - 仅允许删除草稿状态的健康证
   - 管理员可删除任何状态的健康证
   - 支持批量删除和单个删除

### 健康证状态转换图

```
草稿 (draft) → 提交 → 待审核 (pending)
待审核 (pending) → 审核通过 → 已通过 (approved)
待审核 (pending) → 审核拒绝 → 已拒绝 (rejected)
已拒绝 (rejected) → 编辑 → 草稿 (draft)
已通过 (approved) → 申请报销 → 报销待审核 (pending)
报销待审核 (pending) → 财务审核通过 → 报销已通过 (approved)
报销待审核 (pending) → 财务审核拒绝 → 报销已拒绝 (rejected)
报销已通过 (approved) → 财务支付 → 报销已支付 (paid)
```

### 系统交互关系

1. **门店端 ↔ 人事系统**
   - 门店端提交的健康证自动同步至人事系统
   - 人事系统的审核结果自动同步至门店端

2. **人事系统 ↔ 财务系统**
   - 健康证报销申请自动同步至财务系统
   - 财务系统的报销审核结果自动同步至人事系统
   - 财务系统的支付状态自动同步至人事系统

3. **门店端 ↔ 财务系统**
   - 门店端提交的报销申请通过人事系统间接同步至财务系统
   - 财务系统的报销结果通过人事系统间接同步至门店端

## 关键业务规则

1. **健康证有效期管理**
   - 系统自动计算健康证剩余天数
   - 到期前30天自动发送提醒
   - 到期后状态自动变更为已过期

2. **报销规则**
   - 只有已通过审核的健康证才能申请报销
   - 报销金额需填写发票信息
   - 报销申请自动流转至财务系统

3. **数据同步规则**
   - 健康证数据实时同步至人事系统
   - 报销数据实时同步至财务系统
   - 数据变更记录操作日志

4. **安全规则**
   - 敏感数据加密存储
   - 操作日志完整记录
   - 定期数据备份
   - 权限最小化原则
