## 二、用户登录详细流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant Frontend as 前端<br/>Login.vue
    participant API as API层<br/>auth.ts
    participant Store as Pinia Store<br/>auth.ts
    participant Controller as 后端控制器<br/>AuthController
    participant Service as 认证服务<br/>AuthServiceImpl
    participant UserService as 用户服务<br/>UserService
    participant DB as 数据库<br/>MySQL
    participant JWT as JWT工具<br/>JwtUtils
    participant Redis as Redis缓存
    participant Security as Spring Security

    User->>Frontend: 输入用户名和密码
    Frontend->>Store: 调用login方法
    Store->>API: 发送POST /v1/auth/login
    API->>Controller: 传递LoginRequest
    Controller->>Service: 调用login方法

    Service->>UserService: 根据用户名查询用户
    UserService->>DB: SELECT * FROM users WHERE username = ?
    DB-->>UserService: 返回用户信息
    UserService-->>Service: 返回User对象

    alt 用户不存在
        Service-->>Controller: 抛出BusinessException "用户不存在"
        Controller-->>API: 返回401错误
        API-->>Frontend: 显示错误信息
        Frontend-->>User: 提示"用户不存在"
    else 用户存在
        Service->>Service: 检查用户状态
        alt 用户状态为禁用
            Service-->>Controller: 抛出BusinessException "用户账号已禁用"
            Controller-->>API: 返回401错误
            API-->>Frontend: 显示错误信息
            Frontend-->>User: 提示"账号已禁用"
        else 用户状态正常
            Service->>Service: 验证密码
            Note over Service: 使用BCrypt验证密码
            alt 密码错误
                Service->>Service: 增加密码错误次数
                Service->>DB: 更新密码错误次数和最后错误时间
                alt 密码错误次数 >= 5
                    Service->>DB: 锁定用户账号
                    Service-->>Controller: 抛出BusinessException "账号已锁定"
                else 密码错误次数 < 5
                    Service-->>Controller: 抛出BusinessException "密码错误"
                end
                Controller-->>API: 返回401错误
                API-->>Frontend: 显示错误信息
                Frontend-->>User: 提示"密码错误"或"账号已锁定"
            else 密码正确
                Service->>Service: 重置密码错误次数
                Service->>DB: 更新最后登录时间和IP
                Service->>Service: 解析用户角色
                Note over Service: 从JSON字段解析角色列表
                Service->>JWT: 生成JWT令牌
                JWT->>JWT: 创建令牌载荷<br/>包含userId, username, roles, permissions
                JWT->>JWT: 使用HS512算法签名
                JWT-->>Service: 返回JWT令牌
                Service->>JWT: 生成刷新令牌
                JWT-->>Service: 返回刷新令牌
                Service->>Redis: 缓存用户信息
                Service-->>Controller: 返回LoginResponse<br/>包含token, refreshToken, userInfo
                Controller-->>API: 返回200 OK
                API-->>Store: 保存token和userInfo
                Store->>Store: 存储到localStorage
                Store->>Store: 初始化用户信息
                Store-->>Frontend: 返回登录成功
                Frontend->>Frontend: 跳转到首页
                Frontend-->>User: 登录成功
            end
        end
    end
```

## 三、JWT令牌认证流程

```mermaid
sequenceDiagram
    participant Frontend as 前端
    participant API as API层<br/>request.ts
    participant Filter as JWT过滤器<br/>JwtAuthenticationFilter
    participant Security as Spring Security<br/>SecurityConfig
    participant JWT as JWT工具<br/>JwtUtils
    participant Redis as Redis缓存
    participant Controller as 业务控制器
    participant Aspect as 数据权限切面<br/>DataPermissionAspect
    participant DB as 数据库

    Frontend->>API: 发送API请求<br/>携带Authorization: Bearer {token}
    API->>Filter: 请求到达过滤器链

    Filter->>Filter: 提取JWT令牌
    alt 没有令牌
        Filter->>Security: 放行到Spring Security
        Security-->>Frontend: 返回401 Unauthorized
    else 有令牌
        Filter->>JWT: 验证令牌有效性
        JWT->>JWT: 检查令牌格式
        JWT->>JWT: 验证签名
        JWT->>JWT: 检查过期时间

        alt 令牌无效或过期
            Filter-->>Frontend: 返回401 Unauthorized
        else 令牌有效
            JWT->>Redis: 检查令牌是否在黑名单
            alt 令牌在黑名单
                Filter-->>Frontend: 返回401 Unauthorized
            else 令牌不在黑名单
                JWT->>JWT: 解析令牌载荷
                JWT-->>Filter: 返回用户信息<br/>userId, username, roles, permissions
                Filter->>Security: 创建认证对象
                Security->>Security: 设置安全上下文
                Security-->>Controller: 继续请求处理

                Controller->>Aspect: 执行业务方法
                Aspect->>Aspect: 获取当前用户信息
                Aspect->>Aspect: 检查用户角色
                alt 用户是管理员
                    Note over Aspect: 管理员可以访问所有数据
                    Aspect->>DB: 执行查询（无过滤条件）
                else 用户是普通用户
                    Aspect->>Aspect: 添加数据过滤条件
                    Note over Aspect: 根据storeId, departmentId<br/>添加WHERE条件
                    Aspect->>DB: 执行查询（带过滤条件）
                end
                DB-->>Controller: 返回查询结果
                Controller-->>Frontend: 返回业务数据
            end
        end
    end
```

## 五、数据权限过滤详细流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant Controller as 业务控制器
    participant Service as 业务服务
    participant Aspect as 数据权限切面<br/>DataPermissionAspect
    participant Security as Spring Security
    participant UserService as 用户服务
    participant RoleService as 角色服务
    participant DB as 数据库

    User->>Controller: 发起业务请求
    Controller->>Service: 调用业务方法
    Service->>Aspect: 拦截select/list/page方法

    Aspect->>Security: 获取当前认证信息
    Security-->>Aspect: 返回Authentication对象

    alt 未认证或匿名用户
        Aspect->>Service: 不进行数据过滤
        Service->>DB: 执行查询（无过滤）
    else 已认证用户
        Aspect->>Aspect: 提取用户名
        Aspect->>UserService: 查询用户信息
        UserService->>DB: SELECT * FROM users WHERE username = ?
        DB-->>UserService: 返回用户信息
        UserService-->>Aspect: 返回User对象

        Aspect->>Aspect: 解析用户角色JSON
        Aspect->>RoleService: 查询角色信息
        RoleService->>DB: SELECT * FROM roles WHERE id IN (?)
        DB-->>RoleService: 返回角色列表
        RoleService-->>Aspect: 返回角色对象

        Aspect->>Aspect: 检查是否为管理员
        alt 角色代码为'admin'
            Note over Aspect: 管理员可以访问所有数据
            Aspect->>Service: 不添加过滤条件
            Service->>DB: 执行查询（无过滤）
        else 普通用户
            Aspect->>Aspect: 获取storeId和departmentId
            Aspect->>Aspect: 判断实体类型

            alt 门店相关实体<br/>Store, Inventory, Order等
                Aspect->>Aspect: 添加storeId过滤条件
                Note over Aspect: WHERE store_id = ?
            else 部门相关实体<br/>User, Department, Employee等
                Aspect->>Aspect: 添加departmentId过滤条件
                Note over Aspect: WHERE department_id = ?
            else 用户相关实体<br/>且为普通用户
                Aspect->>Aspect: 添加userId过滤条件
                Note over Aspect: WHERE user_id = ?
            end

            Aspect->>Service: 返回带过滤条件的QueryWrapper
            Service->>DB: 执行查询（带过滤条件）
        end
    end

    DB-->>Service: 返回查询结果
    Service-->>Controller: 返回业务数据
    Controller-->>User: 返回响应
```

## 七、密码修改流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant Frontend as 前端
    participant API as API层<br/>auth.ts
    participant Controller as 后端控制器<br/>AuthController
    participant Service as 认证服务<br/>AuthServiceImpl
    participant UserService as 用户服务<br/>UserService
    participant PasswordUtil as 密码工具<br/>PasswordUtils
    participant DB as 数据库<br/>MySQL

    User->>Frontend: 输入旧密码和新密码
    Frontend->>API: 发送PUT /v1/auth/password
    API->>Controller: 传递ChangePasswordRequest
    Controller->>Service: 调用changePassword方法

    Service->>Service: 验证新密码一致性
    alt 两次密码不一致
        Service-->>Controller: 抛出异常"两次输入的密码不一致"
        Controller-->>API: 返回400错误
        API-->>Frontend: 显示错误信息
    else 密码一致
        Service->>PasswordUtil: 验证密码强度
        alt 密码强度不足
            Service-->>Controller: 抛出异常"密码强度不足"
            Controller-->>API: 返回400错误
            API-->>Frontend: 显示错误信息
        else 密码强度符合要求
            Service->>UserService: 查询用户信息
            UserService->>DB: SELECT * FROM users WHERE id = ?
            DB-->>UserService: 返回用户信息
            UserService-->>Service: 返回User对象

            Service->>PasswordUtil: 验证旧密码
            PasswordUtil->>PasswordUtil: BCrypt.matches(oldPassword, hashedPassword)
            alt 旧密码错误
                Service-->>Controller: 抛出异常"旧密码错误"
                Controller-->>API: 返回400错误
                API-->>Frontend: 显示错误信息
            else 旧密码正确
                Service->>PasswordUtil: 加密新密码
                PasswordUtil->>PasswordUtil: BCrypt.hashpw(newPassword)
                PasswordUtil-->>Service: 返回加密后的密码

                Service->>UserService: 更新用户密码
                UserService->>DB: UPDATE users SET password = ?, last_password_change_time = ? WHERE id = ?
                DB-->>UserService: 返回成功
                UserService-->>Service: 返回成功

                Service->>Service: 将所有JWT令牌加入黑名单
                Service->>Service: 强制用户重新登录
                Service-->>Controller: 返回成功
                Controller-->>API: 返回200 OK
                API-->>Frontend: 显示"密码修改成功，请重新登录"
                Frontend->>Frontend: 清除token并跳转到登录页
                Frontend-->>User: 提示重新登录
            end
        end
    end
```

```mermaid
sequenceDiagram

    participant API as API层<br/>auth.ts
    participant Controller as 后端控制器<br/>AuthController
    participant Service as 认证服务<br/>AuthServiceImpl
    participant UserService as 用户服务<br/>UserService
    participant ResetLogService as 密码重置日志服务<br/>PasswordResetLogService
    participant DB as 数据库<br/>MySQL
    participant Redis as Redis缓存
    participant Email as 邮件服务

    User->>Frontend: 点击"忘记密码"
    Frontend-->>User: 显示忘记密码页面（第一步：身份验证）

    User->>Frontend: 输入注册邮箱
    Frontend->>API: POST /v1/auth/verify-user
    API->>Controller: 验证用户是否存在
    Controller->>Service: findByEmail(email)
    Service->>DB: SELECT * FROM users WHERE email = ?
    DB-->>Service: 返回用户信息
    
    alt 邮箱未注册
        Service-->>Controller: 抛出BusinessException "该邮箱未注册"
        Controller-->>API: 返回404错误
        API-->>Frontend: 提示"该邮箱未注册"
    else 邮箱已注册
        Service-->>Controller: 返回用户存在
        Controller-->>API: 返回成功
        API-->>Frontend: 显示"身份验证通过"

        User->>Frontend: 点击"获取验证码"
        Frontend->>API: POST /v1/auth/forgot-password/send-code
        API->>Controller: 发送重置密码验证码
        Controller->>Service: sendVerificationCode(request)
        Service->>Redis: SET reset:code:{userId} {code} EX 300
        Service->>Email: 发送验证码邮件
        Email-->>Service: 发送成功
        Service->>ResetLogService: logSendCode(userId, "EMAIL", clientIp, deviceType, true)
```
