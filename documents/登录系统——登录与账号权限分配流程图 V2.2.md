## 十九、人事管理与权限中心联动设计（新增）

### 19.1 设计背景

为了解决权限中心与人事管理中组织管理的功能重叠问题，实现员工入职到系统账号创建的自动化流程，设计了人事管理与权限中心的联动机制。

### 19.2 核心设计理念

```
┌─────────────────────────────────────────────────────────────┐
│                    联动设计核心原则                          │
├─────────────────────────────────────────────────────────────┤
│ 1. 员工编号作为唯一标识，永久不变                             │
│ 2. 预设用户名基于姓名生成，员工可修改                         │
│ 3. 邀请码绑定员工档案，确保一一对应                           │
│ 4. 注册时自动关联档案，无需人工匹配                           │
│ 5. 支持新旧系统兼容，平滑过渡                                 │
└─────────────────────────────────────────────────────────────┘
```

### 19.3 员工编号生成规则

**格式**：`EMP` + `年份(4位)` + `序号(4位)`

**示例**：
- `EMP2024001` - 2024年第1位入职员工
- `EMP2024002` - 2024年第2位入职员工
- `EMP2025015` - 2025年第15位入职员工

**生成逻辑**：
```java
1. 获取当前年份（如2024）
2. 查询当年最大序号的员工编号
3. 新序号 = 最大序号 + 1
4. 格式化为4位，不足补0
5. 组合成完整员工编号
```

**特点**：
- ✅ 唯一性：每年从0001开始，不会重复
- ✅ 永久性：员工离职后编号保留，不复用
- ✅ 可读性：包含年份信息，便于识别
- ✅ 安全性：不依赖手机号，避免手机号变更风险

### 19.4 预设用户名生成规则

**规则**：`姓名拼音首字母` + `序号(3位)`

**示例**：
- 张三 → `zs001`
- 张三（重名）→ `zs002`
- 李四 → `ls001`
- 王五 → `ww001`

**生成逻辑**：
```java
1. 获取姓名拼音首字母（张三 → zs）
2. 查询该前缀当前最大序号
3. 新序号 = 最大序号 + 1
4. 格式化为3位，不足补0
5. 检查是否与现有用户冲突
6. 如冲突，递增序号直到不冲突
```

**特点**：
- ✅ 易记性：基于姓名，容易记忆
- ✅ 唯一性：自动处理重名情况
- ✅ 灵活性：员工注册时可修改
- ✅ 安全性：不暴露员工真实信息

### 19.5 完整联动流程

```mermaid
sequenceDiagram
    participant HR as HR/管理员
    participant Archive as 入职档案系统
    participant CodeGen as 编号生成器
    participant Invite as 邀请码系统
    participant Email as 邮件系统
    participant Employee as 员工
    participant Auth as 认证系统
    participant User as 用户系统
    
    %% 第一步：创建入职档案
    HR->>Archive: 1. 创建入职档案
    HR->>Archive: 输入：姓名、部门、职位、邮箱等
    Archive->>CodeGen: 请求生成员工编号
    CodeGen-->>Archive: 返回：EMP2024001
    Archive->>CodeGen: 请求生成预设用户名
    CodeGen-->>Archive: 返回：zs001
    Archive->>Archive: 保存档案信息
    Archive-->>HR: 返回档案（含员工编号、预设用户名）
    
    %% 第二步：生成邀请码
    HR->>Invite: 2. 生成邀请码
    Invite->>Archive: 获取档案信息
    Archive-->>Invite: 返回档案（EMP2024001, zs001）
    Invite->>Invite: 生成唯一邀请码
    Invite->>Invite: 绑定员工编号和预设用户名
    Invite->>Archive: 更新档案的邀请码ID
    Invite-->>HR: 返回邀请码记录
    
    %% 第三步：发送邀请
    HR->>Email: 3. 发送邀请邮件
    Email->>Employee: 发送邮件（含邀请码、预设用户名）
    Email-->>HR: 发送成功
    
    %% 第四步：员工注册
    Employee->>Auth: 4. 点击邀请链接
    Auth->>Invite: 验证邀请码
    Invite-->>Auth: 返回档案信息
    Auth->>Employee: 显示预设用户名（可修改）
    Employee->>Auth: 输入：用户名、密码、确认密码
    Auth->>User: 创建系统用户
```

```java
public String generateEmployeeCode() {
    int currentYear = LocalDate.now().getYear();
    String yearPrefix = "EMP" + currentYear;
    
    // 查询当年最大序号
    QueryWrapper<OnboardingArchive> wrapper = new QueryWrapper<>();
    wrapper.likeRight("employee_code", yearPrefix)
           .orderByDesc("employee_code")
           .last("LIMIT 1");
    
    OnboardingArchive lastArchive = archiveMapper.selectOne(wrapper);
    int nextSeq = 1;
    
    if (lastArchive != null && lastArchive.getEmployeeCode() != null) {
        String code = lastArchive.getEmployeeCode();
        String seqStr = code.substring(code.length() - 4);
        nextSeq = Integer.parseInt(seqStr) + 1;
    }

}
```

```java
public String generatePresetUsername(String name) {
    // 获取姓名拼音首字母
    String prefix = getPinyinInitials(name);
    
    // 查询该前缀当前最大序号
    QueryWrapper<OnboardingArchive> wrapper = new QueryWrapper<>();
    wrapper.likeRight("preset_username", prefix)
           .orderByDesc("preset_username")
           .last("LIMIT 1");
    
    OnboardingArchive lastArchive = archiveMapper.selectOne(wrapper);
    int nextSeq = 1;
    
    if (lastArchive != null && lastArchive.getPresetUsername() != null) {
        String username = lastArchive.getPresetUsername();
        String numStr = username.replaceAll("[^0-9]", "");
        if (!numStr.isEmpty()) {
            nextSeq = Integer.parseInt(numStr) + 1;
        }
    }
    
    String presetUsername = String.format("%s%03d", prefix, nextSeq);
    
    // 检查是否与现有用户冲突
    if (isUsernameExists(presetUsername)) {
        while (isUsernameExists(presetUsername)) {
            nextSeq++;
            presetUsername = String.format("%s%03d", prefix, nextSeq);
        }
    }
    
    return presetUsername;
}
```

### 19.8 特殊情况处理

| 场景 | 处理方式 | 说明 |
|------|----------|------|
| **员工复职** | 使用原员工编号，重新生成邀请码 | 保留历史记录 |
| **用户名被占用** | 自动递增序号 | 如zs001被占，尝试zs002 |
| **员工想改用户名** | 注册时允许修改预设用户名 | 提供灵活性 |
| **邀请码过期** | HR可重新生成，员工编号不变 | 不影响档案 |
| **手机号变更** | 只更新档案和用户信息，不影响登录 | 用户名不变 |
| **部门调动** | 更新档案和用户信息，员工编号不变 | 保持连续性 |
