### 1.2 关键差距分析

| 维度 | 现状 | 目标 | 差距等级 |
|------|------|------|----------|
| **写入性能** | 同步写入DB（阻塞业务线程） | 异步队列+批量写入 | **高** |
| **表结构** | 缺少user_agent/business_key/operator_type等关键字段 | 增强版审计日志表 | **高** |
| **脱敏规则** | 有工具类但未在AOP中集成 | 自动识别敏感字段并脱敏 | **高** |
| **查询能力** | 基础分页查询 | 多条件组合筛选+权限隔离 | **中** |
| **导出功能** | 仅有用户数据导出示例 | 审计日志CSV/Excel导出 | **中** |
| **归档清理** | 无 | 定时归档+可配置保留周期 | **高** |
| **权限控制** | 无 | 管理员全量/普通用户仅本人 | **高** |
| **双表冗余** | audit_log与sys_operation_logs功能重叠 | 统一为一套审计日志体系 | **中** |

### 1.3 架构决策：统一审计日志 vs 双表并存

**推荐方案**: **统一增强 `sys_operation_logs` 表作为主审计日志表**

理由：
- `sys_operation_logs` 字段更完整（含business_id, user_agent, response_data）
- 避免维护两套相似逻辑造成的混乱
- 将 `audit_log` 表标记为deprecated，新代码统一使用增强后的主表
- 旧数据通过迁移脚本合并

## 二、数据库设计

### 2.1 增强版审计日志表 DDL

```sql
-- =====================================================
-- 审计日志表（增强版）- 统一审计日志主表
-- 替代原audit_log和sys_operation_logs的功能重叠问题
-- =====================================================

CREATE TABLE IF NOT EXISTS `sys_audit_log` (
    -- 主键
    `log_id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '日志主键ID',

    -- 操作主体信息
    `operator_type`   VARCHAR(20)  NOT NULL DEFAULT 'USER' COMMENT '操作人类型: USER-系统用户, SYSTEM-系统任务, API-接口调用',
    `operator_id`     VARCHAR(64)  DEFAULT NULL            COMMENT '操作人ID（用户ID或系统标识）',
    `operator_name`   VARCHAR(100) DEFAULT NULL            COMMENT '操作人名称（用户名或系统名称）',
    `department_id`   BIGINT       DEFAULT NULL            COMMENT '操作人部门ID',
    `department_name` VARCHAR(100) DEFAULT NULL            COMMENT '操作人部门名称',

    -- 操作信息
    `operation_type`  VARCHAR(30)  NOT NULL                COMMENT '操作类型: CREATE/UPDATE/DELETE/QUERY/LOGIN/LOGOUT/EXPORT/IMPORT/APPROVE/REJECT/OTHER',
    `module`          VARCHAR(50)  NOT NULL                COMMENT '所属模块: USER/ROLE/PERMISSION/ORDER/PURCHASE/INVENTORY/FINANCE/PRODUCT/SYSTEM等',
    `sub_module`      VARCHAR(50)  DEFAULT NULL            COMMENT '子模块（可选，如ORDER.CREATE, PURCHASE.STOCKIN）',
    `operation_desc`  VARCHAR(200) DEFAULT NULL            COMMENT '操作描述（人工可读，如"创建采购订单PO-20260403001"）',
    `business_key`    VARCHAR(100) DEFAULT NULL            COMMENT '业务键（如订单号、产品ID等）',
    `business_id`     VARCHAR(64)  DEFAULT NULL            COMMENT '业务实体ID（关联的业务记录ID）',

    -- 请求信息
    `request_url`     VARCHAR(500) DEFAULT NULL            COMMENT '请求URL路径',
    `request_method`  VARCHAR(10)  DEFAULT NULL            COMMENT 'HTTP方法: GET/POST/PUT/DELETE/PATCH',
    `request_params`  TEXT         DEFAULT NULL            COMMENT '请求参数（JSON格式，敏感字段已脱敏）',
    `response_data`   TEXT         DEFAULT NULL            COMMENT '响应数据摘要（JSON格式，仅记录关键信息）',
    `response_status` VARCHAR(20)  DEFAULT NULL            COMMENT '响应状态: SUCCESS/FAILED/PARTIAL',
    `error_message`   TEXT         DEFAULT NULL            COMMENT '错误信息（异常时的堆栈摘要）',
    `error_code`      VARCHAR(50)  DEFAULT NULL            COMMENT '错误码',

    -- 客户端信息
    `ip_address`      VARCHAR(50)  DEFAULT NULL            COMMENT '客户端IP地址',
    `ip_location`     VARCHAR(100) DEFAULT NULL            COMMENT 'IP地理位置（可选，需IP库支持）',
    `user_agent`      VARCHAR(500) DEFAULT NULL            COMMENT 'User-Agent字符串',
    `device_type`     VARCHAR(20)  DEFAULT NULL            COMMENT '设备类型: PC/MOBILE/TABLET/API/UNKNOWN',
    `browser_info`    VARCHAR(200) DEFAULT NULL            COMMENT '浏览器信息（解析后）',
    `session_id`      VARCHAR(64)  DEFAULT NULL            COMMENT '会话ID（用于追踪同一会话的操作序列）',

    -- 执行信息
    `execution_time`  BIGINT       DEFAULT 0               COMMENT '执行耗时（毫秒）',
    `affected_rows`   INT          DEFAULT 0               COMMENT '影响行数（写操作有效）',

    -- 敏感操作标记
    `sensitive_flag`  TINYINT(1)   NOT NULL DEFAULT 0      COMMENT '是否为敏感操作: 0-否, 1-是',
    `risk_level`      VARCHAR(10)  DEFAULT 'LOW'            COMMENT '风险等级: LOW/MEDIUM/HIGH/CRITICAL',
    `approval_flag`   TINYINT(1)   NOT NULL DEFAULT 0      COMMENT '是否需要审批: 0-否, 1-是',

    -- 时间戳
    `create_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
    `update_time`     DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（用于修正场景）',

    -- 软删除
    `deleted`         TINYINT(1)   NOT NULL DEFAULT 0      COMMENT '逻辑删除: 0-未删除, 1-已删除',

    PRIMARY KEY (`log_id`),

    -- 核心查询索引
    INDEX `idx_operator_id` (`operator_id`),
    INDEX `idx_operation_type` (`operation_type`),
    INDEX `idx_module` (`module`),
    INDEX `idx_business_key` (`business_key`),
    INDEX `idx_business_id` (`business_id`),
    INDEX `idx_create_time` (`create_time`),
    INDEX `idx_ip_address` (`ip_address`),
    INDEX `idx_response_status` (`response_status`),
    INDEX `idx_sensitive_flag` (`sensitive_flag`),
    INDEX `idx_risk_level` (`risk_level`),

    -- 组合索引（高频查询场景）
    INDEX `idx_operator_time` (`operator_id`, `create_time`),
    INDEX `idx_module_type` (`module`, `operation_type`),
    INDEX `idx_module_time` (`module`, `create_time`),
    INDEX `idx_sensitive_time` (`sensitive_flag`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='统一审计日志表';

-- =====================================================
-- 审计日志归档表（用于存储历史数据）
-- =====================================================

CREATE TABLE IF NOT EXISTS `sys_audit_log_archive` (
    `log_id`          BIGINT       NOT NULL                COMMENT '原日志主键ID',
    `archive_batch_no` VARCHAR(32) NOT NULL                COMMENT '归档批次号',
    `archive_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '归档时间',
    `log_data`        LONGBLOB     NOT NULL                COMMENT '完整日志数据（JSON格式）',
    `original_table`  VARCHAR(50)  DEFAULT 'sys_audit_log' COMMENT '来源表名',
    PRIMARY KEY (`log_id`, `archive_batch_no`),
    INDEX `idx_archive_batch` (`archive_batch_no`),
    INDEX `idx_archive_time` (`archive_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='审计日志归档表';
```

### 2.2 索引设计说明

| 索引名称 | 字段 | 用途 | 查询频率 |
|----------|------|------|----------|
| idx_operator_id | operator_id | 按操作人查询（普通用户查自己） | 高 |
| idx_operation_type | operation_type | 按操作类型统计/筛选 | 中 |
| idx_module | module | 按模块维度分析 | 中 |
| idx_business_key | business_key | 按业务单号追溯 | 中 |
| idx_business_id | business_id | 按业务实体ID关联查询 | 中 |
| idx_create_time | create_time | 时间范围查询（核心索引） | **极高** |
| idx_ip_address | ip_address | 安全审计/IP溯源 | 低 |
| idx_response_status | response_status | 成功率统计/失败排查 | 中 |
| idx_sensitive_flag | sensitive_flag | 敏感操作专项审计 | 中 |
| idx_risk_level | risk_level | 风险分级查看 | 低 |
| **idx_operator_time** | operator_id + create_time | 用户操作时间线（复合查询） | **高** |
| **idx_module_type** | module + operation_type | 模块内操作分类统计 | **高** |
| **idx_module_time** | module + create_time | 模块操作趋势分析 | **高** |
| **idx_sensitive_time** | sensitive_flag + create_time | 敏感操作时间分布 | 中 |

```java
@Aspect
@Component
@Slf4j
public class SysAuditLogAspect {

    @Autowired
    private AuditLogAsyncWriter asyncWriter;

    @Autowired
    private ObjectMapper objectMapper;

    /**
     * 切入点：所有标注了@SysAuditLog的方法
     */
    @Around("@annotation(sysAuditLog)")
    public Object around(ProceedingJoinPoint point, SysAuditLog sysAuditLog) throws Throwable {
        // 1. 构建审计日志实体
        SysAuditLog logEntity = buildLogEntity(point, sysAuditLog);

        long startTime = System.currentTimeMillis();
        Object result = null;
        try {
            // 2. 执行目标方法
            result = point.proceed();

            // 3. 设置成功状态
            logEntity.setResponseStatus(AuditResponseStatus.SUCCESS.getCode());
            logEntity.setExecutionTime(System.currentTimeMillis() - startTime);

            // 4. 如果需要记录响应数据
            if (sysAuditLog.recordResponse()) {
                logEntity.setResponseData(truncateResponse(result));
            }

            return result;
        } catch (Exception e) {
            // 5. 设置失败状态
            logEntity.setResponseStatus(AuditResponseStatus.FAILED.getCode());
            logEntity.setErrorMessage(e.getMessage());
            logEntity.setExecutionTime(System.currentTimeMillis() - startTime);

            if (sysAuditLog.recordStackTrace()) {
                logEntity.setErrorMessage(getStackTrace(e));
            }

            throw e;
        } finally {
            // 6. 异步写入（不阻塞主业务）
            asyncWriter.write(logEntity);
        }
    }
}
```

### 5.4 异步写入策略

#### 技术选型：内存缓冲区 + 定时批量刷盘

```java
/**
 * 审计日志异步写入服务
 *
 * 设计思路:
 * 1. 使用内存中的BlockingQueue作为缓冲区
 * 2. 单独的写入线程定期从队列取出数据批量插入数据库
 * 3. 应用关闭时确保缓冲区数据全部落盘
 * 4. 写入失败时本地重试，超过次数后写入死信队列/文件
 */
@Service
@Slf4j
public class AuditLogAsyncWriter implements DisposableBean, SmartLifecycle {

    /** 缓冲区队列 */
    private final BlockingQueue<SysAuditLog> bufferQueue;

    /** 批量写入大小 */
    private final int batchSize;

    /** 最大缓冲区容量（防OOM） */
    private final int maxBufferSize;

    /** 写入线程 */
    private volatile Thread writerThread;

    /** 运行标志 */
    private volatile boolean running = false;

    /** 当前批次累积 */
    private final List<SysAuditLog> currentBatch;

    /** 上次刷新时间 */
    private volatile long lastFlushTime;

    /** 最大刷新间隔(ms)，即使未达到batchSize也强制刷新 */
    private final long maxFlushInterval;

    @Autowired
    private SysAuditLogMapper auditLogMapper;

    @Autowired
    private AuditLogFailedRecordService failedRecordService;

    /**
     * 初始化异步写入器
     */
    @PostConstruct
    public void init() {
        this.running = true;
        this.writerThread = new Thread(this::writeLoop, "audit-log-writer");
        this.writerThread.setDaemon(true);  // 守护线程，不阻止JVM退出
        this.writerThread.start();
        log.info("审计日志异步写入器已启动, batchSize={}, maxFlushInterval={}ms",
                 batchSize, maxFlushInterval);
    }

    /**
     * 写入循环（后台线程执行）
     */
    private void writeLoop() {
        while (running || !bufferQueue.isEmpty()) {
            try {
                // 1. 从队列取数据（带超时）
                SysAuditLog log = bufferQueue.poll(maxFlushInterval, TimeUnit.MILLISECONDS);

                if (log != null) {
                    currentBatch.add(log);
                }

                // 2. 判断是否需要刷新
                boolean shouldFlush = currentBatch.size() >= batchSize ||
                                      (System.currentTimeMillis() - lastFlushTime) >= maxFlushInterval ||
                                      (!running && !currentBatch.isEmpty());

                if (shouldFlush && !currentBatch.isEmpty()) {
                    flush();
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            } catch (Exception e) {
                log.error("审计日志写入循环异常: {}", e.getMessage(), e);
            }
        }

        // 3. 最后一次刷新
        if (!currentBatch.isEmpty()) {
            flush();
        }
    }

    /**
     * 批量刷新到数据库
     */
    private synchronized void flush() {
        if (currentBatch.isEmpty()) return;

        List<SysAuditLog> batchToWrite = new ArrayList<>(currentBatch);
        currentBatch.clear();
        lastFlushTime = System.currentTimeMillis();

        try {
            // 使用MyBatis Plus的saveBatch进行批量插入
            int inserted = /* 批量插入逻辑 */;
            log.debug("审计日志批量写入完成: {}条", batchToWrite.size());
        } catch (Exception e) {
            log.error("审计日志批量写入失败: {}条, 错误: {}", batchToWrite.size(), e.getMessage());

            // 写入失败处理：记录到失败表/文件
            for (SysAuditLog failedLog : batchToWrite) {
                failedRecordService.saveFailedRecord(failedLog, e.getMessage());
            }
        }
    }

    /**
     * 外部调用：写入一条日志到缓冲区
     */
    public void write(SysAuditLog log) {
        if (bufferQueue.size() >= maxBufferSize) {
            log.warn("审计日志缓冲区已满({}), 丢弃最新日志: {}",
                     maxBufferSize, log.getOperationDesc());
            // 可选：同步写入或丢弃
            return;
        }
        bufferQueue.offer(log);
    }

    /**
     * 应用关闭时确保所有数据落盘
     */
    @Override
    public void destroy() {
        this.running = false;
        if (writerThread != null) {
            writerThread.interrupt();
            try {
                writerThread.join(5000);  // 等待最多5秒
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        // 最终刷新
        flush();
        log.info("审计日志异步写入器已停止");
    }
}
```

### 6.1 归档任务 (AuditLogArchiveTask)

```java
@Component
@Slf4j
public class AuditLogArchiveTask {

    @Value("${audit-log.retention.hot-days:180}")
    private int hotRetentionDays;

    @Autowired
    private SysAuditLogMapper auditLogMapper;

    @Autowired
    private SysAuditLogArchiveMapper archiveMapper;

    @Autowired
    private JdbcTemplate jdbcTemplate;

    /**
     * 每天凌晨2点执行归档
     * 将超过hotRetention天的数据迁移到归档表
     */
    @Scheduled(cron = "${audit-log.retention.archive-cron:0 0 2 * * ?}")
    @Transactional(rollbackFor = Exception.class)
    public void archiveExpiredLogs() {
        log.info("========== 开始审计日志归档任务 ==========");

        LocalDateTime cutoffDate = LocalDateTime.now().minusDays(hotRetentionDays);
        String batchNo = generateBatchNo();

        try {
            // 1. 查询待归档的数据总量
            Long totalToArchive = countLogsBefore(cutoffDate);
            if (totalToArchive == 0) {
                log.info("没有需要归档的数据");
                return;
            }
            log.info("待归档数据总量: {}条, 截止日期: {}", totalToArchive, cutoffDate);

            // 2. 分批归档（每批1000条，避免长事务）
            int batchSize = 1000;
            int archivedCount = 0;
            int batchNum = 0;

            while (true) {
                batchNum++;
                List<SysAuditLog> batch = queryBatchBefore(cutoffDate, batchSize);

                if (batch.isEmpty()) break;

                // 3. 写入归档表
                for (SysAuditLog log : batch) {
                    SysAuditLogArchive archive = convertToArchive(log, batchNo);
                    archiveMapper.insert(archive);
                }

                // 4. 从原表删除（物理删除，因为已归档）
                List<Long> ids = batch.stream().map(SysAuditLog::getLogId).collect(Collectors.toList());
                deleteByIds(ids);

                archivedCount += batch.size();
                log.info("第{}批次归档完成: {}条, 累计: {}条", batchNum, batch.size(), archivedCount);

                // 避免长时间占用事务
                if (batchNum % 10 == 0) {
                    log.info("归档进度: {}/{}", archivedCount, totalToArchive);
                }
            }

            log.info("========== 审计日志归档完成: 共归档{}条, 批次号:{} ==========",
                     archivedCount, batchNo);

            // 5. 发送归档通知（可选）
            sendArchiveNotification(batchNo, archivedCount, totalToArchive);

        } catch (Exception e) {
            log.error("审计日志归档任务失败: {}", e.getMessage(), e);
            throw new RuntimeException("归档任务执行失败", e);
        }
    }

    /**
     * 生成归档批次号
     * 格式: ARCH_YYYYMMDD_HHmmss_SSSS
     */
    private String generateBatchNo() {
        return String.format("ARCH_%s_%s",
                LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE),
                LocalTime.now().format(DateTimeFormatter.ofPattern("HHmmss_SSS")));
    }
}
```

### 6.2 清理任务 (AuditLogCleanupTask)

```java
@Component
@Slf4j
public class AuditLogCleanupTask {

    @Value("${audit-log.retention.archive-days:730}")
    private int archiveRetentionDays;

    @Autowired
    private JdbcTemplate jdbcTemplate;

    /**
     * 每天凌晨3点执行清理
     * 删除超过archiveRetention天的归档数据
     *
     * 安全机制:
     * 1. 先备份再删除
     * 2. 分批删除，每批不超过5000条
     * 3. 删除前记录详细日志
     * 4. 删除后验证数据一致性
     */
    @Scheduled(cron = "${audit-log.retention.cleanup-cron:0 0 3 * * ?}")
    public void cleanupArchivedLogs() {
        log.info("========== 开始审计日志清理任务 ==========");

        LocalDateTime cutoffDate = LocalDateTime.now().minusDays(archiveRetentionDays);

        try {
            // 1. 统计待清理数据量
            Long totalToDelete = countArchivedLogsBefore(cutoffDate);
            if (totalToDelete == 0) {
                log.info("没有需要清理的超期归档数据");
                return;
            }

            log.info("待清理归档数据总量: {}条, 截止日期: {}", totalToDelete, cutoffDate);

            // 2. 先备份（可选：备份到文件或云存储）
            String backupFile = backupBeforeDelete(cutoffDate);
            log.info("备份文件: {}", backupFile);

            // 3. 分批删除
            int batchSize = 5000;
            int deletedCount = 0;
            int batchNum = 0;

            while (true) {
                batchNum++;
                int deleted = deleteArchivedBatch(cutoffDate, batchSize);
                if (deleted == 0) break;

                deletedCount += deleted;
                log.info("第{}批次清理完成: {}条, 累计: {}条", batchNum, deleted, deletedCount);

                // 每10批次输出进度
                if (batchNum % 10 == 0) {
                    log.info("清理进度: {}/{}", deletedCount, totalToDelete);
                }
            }

            // 4. 验证清理结果
            Long remaining = countArchivedLogsBefore(cutoffDate);
            if (remaining > 0) {
                log.warn("清理后仍有{}条超期数据未删除", remaining);
            }

            log.info("========== 审计日志清理完成: 共清理{}条, 备份文件:{} ==========",
                     deletedCount, backupFile);

            // 5. 发送清理报告
            sendCleanupReport(deletedCount, totalToDelete, backupFile);

        } catch (Exception e) {
            log.error("审计日志清理任务失败: {}", e.getMessage(), e);
            // 不抛出异常，避免影响后续定时任务
        }
    }

    /**
     * 清理前备份数据
     */
    private String backupBeforeDelete(LocalDateTime cutoffDate) {
        String timestamp = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMdd_HHmmss"));
        String backupDir = "./backup/audit-log/";
        String backupFile = backupDir + "audit_log_cleanup_" + timestamp + ".sql";

        // 使用mysqldump或SELECT INTO OUTFILE备份
        // 这里简化为记录日志
        log.info("执行清理前备份: 截止日期={}, 备份文件={}", cutoffDate, backupFile);

        return backupFile;
    }
}
```

## 九、风险点与应对措施

### 9.1 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| **异步写入丢数据** | 审计日志缺失，合规风险 | 中 | 1. 应用关闭时强制flush<br>2. 写入失败写入失败记录表<br>3. 定期校验日志完整性 |
| **缓冲区OOM** | 内存溢出导致应用崩溃 | 低 | 1. 设置最大缓冲区容量<br>2. 满时丢弃新日志并告警<br>3. 监控JVM内存 |
| **大量数据查询慢** | 审计页面卡顿 | 中 | 1. 合理设计索引<br>2. 强制时间范围查询（最多查6个月）<br>3. 考虑读写分离 |
| **脱敏误伤正常数据** | 业务数据被错误脱敏 | 低 | 1. 精确的正则匹配<br>2. 白名单机制<br>3. 可配置开关 |
| **归档任务锁冲突** | 多实例同时归档导致重复 | 低 | 1. 使用分布式锁（Redis）<br>2. 或单实例部署定时任务 |
| **MyBatis Plus批量插入性能** | 大批量写入慢 | 低 | 1. 使用rewriteBatchedStatements<br>2. 自定义批量插入SQL |

### 9.2 业务风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| **合规要求变化** | 审计内容不符合新规 | 低 | 1. 设计灵活的字段结构<br>2. 使用JSON存储扩展字段<br>3. 定期审视合规要求 |
| **数据量暴增** | 存储成本上升 | 中 | 1. 动态调整保留周期<br>2. 归档到低成本存储（OSS）<br>3. 数据压缩 |
| **性能影响主业务** | 系统整体变慢 | 低 | 1. 异步写入完全解耦<br>2. 监控写入线程资源<br>3. 降级开关 |

### 9.3 运维风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| **定时任务执行失败** | 数据堆积 | 中 | 1. 任务失败重试机制<br>2. 执行结果通知（邮件/钉钉）<br>3. 监控任务状态 |
| **误删重要日志** | 无法追溯 | 低 | 1. 清理前强制备份<br>2. 保留周期可配置<br>3. 清理操作需二次确认 |
| **配置错误** | 功能异常 | 低 | 1. 配置项有默认值<br>2. 启动时校验配置<br>3. 配置变更通知 |

```java
@RestController

    private final UserService userService;

    @PostMapping
    @SysAuditLog(
        operationType = "CREATE",
        module = "USER",
        desc = "创建用户: #{#dto.username}",
        businessKey = "#{#dto.username}",
        businessId = "#result.data.id",  // 从返回值中取
        sensitive = true,
        riskLevel = "MEDIUM"
    )
    public Result<User> createUser(@Valid @RequestBody UserCreateDTO dto) {
        return Result.success(userService.createUser(dto));
    }

    @PutMapping("/{id}")
    @SysAuditLog(
        operationType = "UPDATE",
        module = "USER",
        desc = "修改用户: #{#id}",
        businessId = "#{#id}"
    )
    public Result<User> updateUser(@PathVariable Long id, @RequestBody UserUpdateDTO dto) {
        return Result.success(userService.updateUser(id, dto));
    }

    @DeleteMapping("/{id}")
    @SysAuditLog(
        operationType = "DELETE",
        module = "USER",
        desc = "删除用户: #{#id}",
        businessId = "#{#id}",
        sensitive = true,
        riskLevel = "HIGH"
    )
    public Result<Void> deleteUser(@PathVariable Long id) {
        userService.deleteUser(id);
        return Result.success();
    }
}
```
