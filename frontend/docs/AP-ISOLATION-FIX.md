# AP隔离配置指南 - 解决访客无法访问H5服务器的问题

## 问题描述

**现象**：
- 访客WiFi的手机无法访问 `http://192.168.0.106:3003/`
- 显示"服务器已停止响应"或超时
- 扫描二维码也无法打开页面

**原因**：
- AP隔离功能阻止了所有跨设备通信
- 包括访客设备 → 有线网络设备的访问
- H5服务器运行在有线连接的店员电脑上，因此被阻断

**目标**：
- 保持AP隔离的安全性（防止设备互访）
- 同时允许访客设备访问特定的H5服务端口

---

## 解决方案（按推荐顺序）

### 方案1：启用"允许访问局域网"（最佳 ⭐⭐⭐⭐⭐）

大多数现代路由器在AP隔离之外，还有独立的"局域网访问权限"开关。

#### TP-Link 路由器：

```
位置：访客网络 → 高级设置

找到类似选项：
□ 允许访问局域网（或"允许访问内网"）

操作：
✅ 勾选此选项
✅ 保存并重启访客网络（或等待自动生效）

效果：
- 访客设备可以访问有线网络上的服务（如H5服务器）
- 访客设备之间仍然不能互访（保持安全性）
```

#### 小米/Redmi 路由器：

```
位置：常用设置 → WiFi设置 → 访客WiFi → 高级设置

选项名称可能有：
• "允许访问局域网"
• "可访问内网"
• "局域网访问权限"

操作：
✅ 开启该选项
```

#### 华为路由器：

```
位置：Wi-Fi设置 → 访客网络 → 更多设置

查找：
• "允许访问家庭网络"
• "内网访问权限"

操作：
✅ 切换为开启状态
```

#### ASUS华硕路由器：

```
位置：无线网络 → 专业设置 → Isolation

注意：华硕可能有多个层级：
1. Client Isolation (AP隔离) - 控制设备间互访
2. Intranet Access (内网访问) - 控制是否能访问LAN

操作：
✅ 保持 Client Isolation = Enable (防互访)
✅ 设置 Intranet Access = Enable (允许访问H5服务)
```

---

### 方案2：使用"仅隔离无线客户端"模式（次优 ⭐⭐⭐⭐）

部分路由器支持更精细的AP隔离模式：

```
传统AP隔离（当前可能的状态）：
[访客A] ──❌──→ [访客B]
[访客A] ──❌──→ [有线设备C]  ← 这是我们不想要的！

精细AP隔离（理想状态）：
[访客A] ──❌──→ [访客B]      ← 防止互扫 ✅
[访客A] ──✅──→ [有线设备C]   ← 允许访问服务 ✅

如何实现：
在路由器中寻找模式选择：
○ 完全隔离模式（Full Isolation） ← 当前可能的模式
● 无线隔离模式（Wireless Only） ← 需要切换到这个
```

**适用路由器型号**：
- OpenWrt/LEDE 系统
- 高端家用路由器（TP-Link XDR系列、小米AX6000等）
- 企业级路由器（基本都有此功能）

---

### 方案3：DMZ主机或端口转发（技术方案 ⭐⭐⭐）

如果路由器不支持上述细粒度控制，可以使用端口转发：

#### 步骤1：将H5服务器设置为DMZ主机

```
路由器设置路径（以TP-Link为例）：
转发规则 → DMZ主机

操作：
1. 启用DMZ主机功能
2. DMZ主机IP地址填写：192.168.0.106（店员电脑IP）
3. 保存

效果：
所有来自访客网络的请求都会被转发到店员电脑

风险：
⚠️ 店员电脑的所有端口都对访客开放
⚠️ 需要确保电脑防火墙已正确配置
```

#### 步骤2：或者仅转发特定端口（更安全）

```
路由器设置路径：
转发规则 → 端口映射 / 虚拟服务器

添加规则：
- 外部端口：3003
- 内部IP地址：192.168.0.106
- 内部端口：3003
- 协议：TCP
- 来源：访客网络（如有选项）

效果：
仅开放3003端口给访客网络
其他端口保持封闭
```

---

### 方案4：双网卡桥接方案（物理隔离 + 服务可用 ⭐⭐⭐⭐⭐）

如果以上软件方案都不可行，可以考虑硬件方案：

```
当前架构（有问题）：
[互联网] → [路由器] → [店员电脑(:3003)]
                      ↘ [访客WiFi]

改进架构（推荐）：
[互联网] → [主路由器] → [店员电脑(主网卡)] → 内网服务
                  ↓
           [副路由器/热点] → [访客WiFi]
                  ↑
        店员电脑的WiFi网卡连接到此网络
        并共享主网卡的网络连接

具体步骤：
1. 店员电脑开启移动热点（命名为"门店招聘专用"）
   - 密码简单易输入（如：12345678）
   
2. 在Windows中设置热点属性：
   - 设置 → 网络和Internet → 移动热点
   - 编辑 → 开启"允许其他设备使用此Internet连接"

3. 将H5服务器绑定到所有接口（当前已经是0.0.0.0）

效果：
✅ 求职者连接"门店招聘专用"WiFi
✅ 可以直接访问H5服务器
✅ 与主网络物理隔离（真正的VLAN级别）
✅ 不依赖路由器AP隔离功能

成本：¥0（仅需一台有WiFi的电脑）
```

## 🧪 测试验证流程

### 测试1：检查连通性基础

```bash
# 在店员电脑上打开命令提示符（CMD），执行：

# 1. 确认本机IP地址
ipconfig
# 找到无线网卡和有线网卡的IPv4地址

# 2. 确认H5服务器正在监听
netstat -an | findstr ":3003"
# 应该显示：TCP    0.0.0.0:3003    0.0.0.0:0    LISTENING

# 3. 从本地测试服务器是否正常
curl http://localhost:3003/
# 应该返回伪装页面的HTML内容
```

### 测试2：从访客网络测试

```bash
# 手机连接访客WiFi后：

# 方法1：浏览器直接访问
http://192.168.0.106:3003/

# 方法2：如果浏览器不行，尝试ping
# （需要终端模拟器App，如Termux）
ping 192.168.0.106

# 方法3：使用在线工具
# 手机浏览器访问：http://192.168.0.106:3003/api/token/list
# 应该返回JSON数据或错误信息（不是超时）
```

### 测试3：对比测试（关键！）

```
实验设计：
场景A：手机连接【主WiFi】（非访客网络）
场景B：手机连接【访客WiFi】

分别访问：http://192.168.0.106:3003/

预期结果：
场景A：✅ 能访问（说明服务器正常）
场景B：❌ 不能访问（说明是AP隔离导致）

结论：
如果场景A成功但场景B失败 → 确认是AP隔离问题
如果两个都失败 → 可能是其他问题（防火墙、IP错误等）
```

## 🚨 应急解决方案（立即可用）

如果需要立即让招聘系统工作，**临时禁用AP隔离**：

```
操作步骤：
1. 登录路由器管理界面
2. 找到访客网络设置
3. 关闭"AP隔离"或"客户端隔离"开关
4. 保存设置
5. 让求职者的手机重新连接访客WiFi
6. 再次测试扫码

优点：
✅ 立即可用（1分钟搞定）
✅ 所有功能恢复正常

缺点/风险：
⚠️ 访客设备之间可以互访（安全性降低）
⚠️ 如果同一时间有多位求职者，他们理论上可以看到彼此的设备

缓解措施：
• Token有时效性（30分钟），降低长期风险
• URL混淆已实施，不易被发现是招聘系统
• 建议仅在营业高峰期临时关闭，非高峰期重新开启

建议：
📝 作为临时方案使用，同时购买或寻找支持细粒度控制的方案
```
