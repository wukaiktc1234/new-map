## 1. el-dialog 内 el-select / el-date-picker 下拉菜单滚动漂移

**日期**: 2026-06-16
**状态**: 已解决
**影响范围**: 采购合同、电子合同等所有使用 dialog 内表单的模块

### 问题描述

在 `el-dialog` 弹窗内的 `el-select`、`el-date-picker` 等弹出组件，当用户上下滚动对话框内容时：
- 下拉面板脱离触发元素，位置偏移（偏移量随滚动距离增大）
- 下拉面板不断重新计算/修正位置，产生抖动
- 表单内容越长，现象越明显

### 根因分析（4轮迭代）

#### 第1轮尝试：添加 `teleported="false"` — 失败

**思路**: 让 popper 保留在 dialog DOM 树内，不 teleport 到 body。

**结果**: 出现抖动。因为全局 `fixed-popper.ts` 插件强制注入 `strategy: 'fixed'`，而 popper 在 `.el-dialog__body`（overflow-y:auto）内部却用 fixed 定位——矛盾。

#### 第2轮尝试：添加 `append-to-body` + 移除 teleported=false — 失败

**思路**: 参考 StoreCertificate.vue、BomManagement.vue 等已正常工作的 dialog，它们都有 `append-to-body`。

**结果**: 下拉面板仍然偏移一整行（截图证据）。说明 `strategy: 'fixed'` 在跨 DOM 边界追踪滚动容器内元素时不可靠。

#### 第3轮尝试：`teleported="false"` + 显式 `popper-options="{ strategy: 'absolute' }"` — 失败

**思路**: 双重覆盖——既不 teleport 又强制 absolute。

**结果**: 用户反馈"没有效果"。推测全局插件通过 `h()` 函数包装注入的 `popperOptions` 可能与组件显式传入的合并存在优先级或时序问题。

#### 第4轮：修改全局插件 + CSS 定位上下文 — **成功**

**关键发现**: 对比员工端项目 (`employee-frontend`) 的请假申请页面：

| 维度 | 员工端 (正常) | 管理端 (异常) |
|------|:---:|:---:|
| fixed-popper 插件 | **无** | **有** (强制 strategy=**fixed**) |
| 容器类型 | PageContainer 全屏页面 | el-dialog 弹窗 |
| LeaveForm 用法 | 仅 `teleported="false"` | — |
| 实际 strategy | `absolute` (EP原生默认) | 被插件改为 `fixed` |

**根本原因**: 全局 `fixed-popper.ts` 插件无条件将所有组件的 Popper 策略设为 `'fixed'`。但 `strategy: 'fixed'` 与 dialog 内部滚动容器天然不兼容。

### 最终方案

修改了 3 个文件：

#### 1. `src/plugins/fixed-popper.ts` — 插件智能化

根据 `teleported` 属性自动选择定位策略：
- `teleported=true`（默认）→ `strategy: 'fixed'` → popper 在 body 层级
- `teleported=false` → `strategy: 'absolute'` → popper 在滚动容器内

```typescript
const isTeleported = attrs.teleported !== false && attrs['teleported'] !== false
const baseOptions = isTeleported ? FIXED_POPPER_OPTIONS : ABSOLUTE_POPPER_OPTIONS
```

#### 2. `src/styles/global/_element-overrides.scss` — CSS 定位上下文

```scss
.el-dialog__body {
  overflow-y: auto;
  overflow-x: hidden;           // 防止水平滚动条
  position: relative;           // 为 absolute popper 提供 offset parent
  flex: 1;
  min-height: 0;

  // 细滚动条样式
  scrollbar-width: thin;
  &::-webkit-scrollbar { width: 6px; height: 0; }
}
```

#### 3. 业务组件 — 仅需 `teleported="false"`

```html
<el-select v-model="form.xxx" :teleported="false">...</el-select>
<el-date-picker v-model="form.date" :teleported="false" />
```

### 经验教训

1. **全局插件的无条件覆盖是隐患**: 当全局插件强制修改组件行为时，特定场景（如 dialog 内滚动）会产生隐蔽的兼容性问题
2. **参考正常工作的实现比猜测更有效**: 对比员工端项目直接揭示了根本差异
3. **Popper.js 的两种策略各有适用场景**:
   - `fixed`: 适用于 popper 在 body 层级的场景（dialog 外、全屏页面）
   - `absolute`: 适用于 popper 在滚动容器内的场景（dialog 内、带 overflow 的区域）
4. **`position: relative` 是 absolute 定位的必要条件**: 给滚动容器加 `position: relative` 确保 popper 有正确的 offset parent

### 适用规范

当在 `el-dialog` 中使用以下组件时，必须设置 `:teleported="false"`:
- `el-select`
- `el-date-picker`
- `el-time-picker`
- `el-cascader`
- 其他基于 Popper.js 的弹出组件

## 2. el-dialog 内容溢出导致水平+垂直滚动条同时显示

**日期**: 2026-06-16
**状态**: 已解决
**关联**: 上文第1条的附带修复

### 问题描述

新建采购合同对话框（原 width=800px）内容较多时，同时出现水平滚动条和垂直滚动条，视觉效果差。

### 解决方案

1. **对话框宽度调整**: 采购合同从 `800px` 加宽到 `900px`
2. **CSS 全局处理**: `.el-dialog__body` 添加 `overflow-x: hidden` + 细滚动条样式
3. **垂直滚动条美化**: 6px 宽度 + 半透明 + hover 时加深

### 经验教训

- 对话框宽度应考虑 `label-width` + `gutter` + 内容实际宽度，两列布局建议 >= 860px
- 全局 CSS 应统一处理 dialog body 的 overflow 行为，而非逐个组件修复
