# Skill: 工作结束检查清单

> 触发条件：每次完成一个功能/修复一批BUG后，在工作结束前执行

## 强制执行项（每次必做）

### 1. 编译验证
```bash
# 后端
cd p:\my-new-project\backend && mvn compile -q
# 确认: BUILD SUCCESS, 0 errors

# 前端
cd p:\my-new-project\frontend && npm run build
# 确认: done in XXs, 0 errors
```

### 2. 服务状态确认
```bash
netstat -ano | findstr "8081"  # 后端
netstat -ano | findstr "3000"  # 前端
# 确认两个端口都在 LISTENING
```

### 3. 功能冒烟测试
```
根据本次工作内容选择:
- [ ] 登录功能正常 (admin/admin123 可获取 token)
- [ ] 相关页面可打开无 404
- [ ] CRUD 操作无报错
- [ ] 菜单显示正确
```

### 4. 进度文档更新
```
编辑: PROJECT_PROGRESS.md
- 更新"已完成工作": 勾选本次完成的任务
- 更新"当前状态": 服务状态和已验证功能
- 更新"版本历史": 新增版本条目 (vX.Y.Z)
- 如有新待办: 添加到对应优先级列表
- 如有新债务: 添加到技术债务清单
```

### 5. 代码质量自检
```
快速检查:
- [ ] 无 console.log 调试代码残留 (前端)
- [ ] 无 TODO/FIXME 未处理的硬编码
- [ ] 新增代码遵循项目命名规范
- [ ] 敏感信息未提交 (密码/key/token)
- [ ] 文件长度在限制内 (Vue<1000, TS<800)
```

## 可选执行项（视情况）

### 6. 日志检查
```bash
# 检查后端日志是否有持续报错
# 关注: ERROR, Exception, scheduled_task (应不再报错)
```

### 7. 性能关注
```
- [ ] 本次改动是否引入 N+1 查询?
- [ ] 大列表是否有分页?
- [ ] 缓存策略是否合理?
```

### 8. 安全检查
```
- [ ] 新增接口是否有权限控制?
- [ ] 用户输入是否有校验?
- [ ] SQL 是否有注入风险? (使用参数化查询)
```

## 工作结束声明模板

完成以上检查后，向用户汇报:

```
## ✅ 工作完成汇报

### 本次完成内容
1. ...
2. ...

### 验证结果
- 后端编译: ✅ BUILD SUCCESS
- 前端编译: ✅ 0 errors
- 服务状态: ✅ 8081 + 3000 均正常
- 功能测试: ✅ [具体测试结果]

### 版本更新
- v{next}: {简要描述}

### 后续建议
- [P0/P1/P2 待办事项]
```
