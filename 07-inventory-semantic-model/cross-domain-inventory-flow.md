## 4. 统一 Inventory Truth 分析

### 4.1 Inventory Truth 定义

```
Inventory Truth = 所有业务链使用的统一库存真相

包含：
1. 数量真相：当前库存数量
2. 成本真相：当前库存成本
3. 位置真相：库存所在位置
4. 状态真相：库存可用状态
5. 历史真相：库存变动历史
```

### 4.2 各业务链对 Inventory Truth 的依赖

| 业务链 | 读取Inventory Truth | 写入Inventory Truth | 关键操作 |
|--------|---------------------|---------------------|----------|
| 采购链 | 查询库存数量、成本 | 更新库存数量、成本 | 采购入库、领料出库 |
| 销售链 | 查询库存数量 | 更新库存数量 | 销售出库、配方消耗 |
| 调拨链 | 查询库存数量、成本 | 更新库存数量、成本 | 调拨出库、调拨入库 |

### 4.3 Inventory Truth 一致性挑战

#### 4.3.1 数据一致性挑战

```
挑战1: 并发更新
- 采购链和销售链同时操作同一物料库存
- 可能导致库存数量不一致

挑战2: 成本不一致
- 仓库库存成本与门店库存成本不一致
- 调拨过程中成本转换不准确

挑战3: 状态不一致
- 库存可用状态与实际可用状态不一致
- 预留库存与实际预留不一致
```

#### 4.3.2 业务一致性挑战

```
挑战1: 时序问题
- 采购入库和销售出库的时序处理
- 调拨在途的时间窗口处理

挑战2: 边界问题
- 库存数量为0时的处理
- 负库存的处理
- 小数库存的处理

挑战3: 异常处理
- 采购退货的处理
- 销售退货的处理
- 损耗的处理
```

## 5. 统一 Inventory Truth 模型

### 5.1 Inventory Truth 数据模型

```
inventory_truth (库存真相表)
├── material_id (物料ID)
├── location_type (位置类型：warehouse/store)
├── location_id (位置ID)
├── quantity (数量)
├── uom_id (单位ID)
├── unit_cost (单位成本)
├── total_cost (总成本)
├── available_quantity (可用数量)
├── reserved_quantity (预留数量)
├── status (状态：available/reserved/locked)
├── last_updated (最后更新时间)
├── version (版本号)
└── business_date (业务日期)
```

### 5.2 Inventory Truth 更新规则

```
规则1: 原子更新
- 所有库存变动都是原子操作
- 要么全部成功，要么全部失败

规则2: 版本控制
- 每次更新都增加版本号
- 防止并发更新冲突

规则3: 事务日志
- 所有库存变动都记录事务日志
- 支持追溯和审计

规则4: 一致性检查
- 定期检查库存数据一致性
- 发现不一致立即修复
```

## 7. Inventory Truth 一致性保障机制

### 7.1 数据一致性保障

```
机制1: 事务管理
- 所有库存操作都在事务中执行
- 支持事务回滚和恢复
- 保证数据一致性

机制2: 锁机制
- 并发操作时加锁
- 防止数据冲突
- 保证操作顺序

机制3: 版本控制
- 每次更新都记录版本
- 检测并发冲突
- 支持乐观锁
```

### 7.2 业务一致性保障

```
机制1: 业务规则校验
- 库存数量不能为负
- 调拨数量不能超过可用数量
- 消耗数量不能超过库存数量

机制2: 状态管理
- 库存状态明确
- 状态转换规则明确
- 状态变更记录完整

机制3: 异常处理
- 异常情况有明确处理流程
- 异常数据有修复机制
- 异常日志完整
```

## 8. 当前系统问题分析

### 8.1 数据模型问题

```
问题1: 库存表分离
- inventory (仓库库存) 和 store_inventory (门店库存) 分离
- 导致库存真相分散
- 调拨过程复杂

问题2: 成本字段分散
- inventory.unit_cost, total_cost
- store_inventory.unit_cost, total_cost
- 成本一致性难以保障

问题3: 事务记录不完整
- inventory_transactions 只记录调拨
- 缺少完整的库存变动记录
- 追溯困难
```

```
问题1: 采购链不完整
- 采购入库后缺少领料出库流程
- 配方消耗与库存更新不联动
- 成本计算不准确

问题2: 销售链不完整
- 销售出库与库存更新不实时
- 配方消耗与库存更新不联动

问题3: 调拨链不完整
- 调拨在途管理不完善

## 11. 总结

### 11.1 核心原则

1. **统一真相原则**：所有业务链使用同一 Inventory Truth
2. **原子更新原则**：所有库存变动都是原子操作
3. **成本守恒原则**：总成本在流转过程中保持不变
4. **完整追溯原则**：所有库存变动都有完整记录

### 11.2 关键挑战

1. **数据一致性**：确保不同位置、不同时间的库存数据一致
2. **业务一致性**：确保不同业务链的库存操作一致
3. **性能挑战**：在保证一致性的同时保证性能
4. **复杂性挑战**：业务逻辑复杂，需要仔细设计

### 11.3 成功标准

1. **数据准确**：库存数据100%准确
2. **成本准确**：成本计算100%准确
3. **实时性**：库存更新实时性达到业务要求
4. **可追溯**：所有库存变动都可追溯
