# 批次/保质期分析 (Phase 15 - Batch/Lot/Expiry Analysis)

## 核心问题：批次和保质期的语义定位

> 当前业务是否需要 Batch、Lot、Expiry Date、Production Date、Supplier Batch？
> 它们属于 Inventory Fact 的属性还是独立关系？

**关键约束**：
- 不要因为"以后可能需要"就强行加入核心模型
- 必须从业务需求角度分析
- 特别针对：生鲜、饮料、调味品、预包装商品

## 2. 术语定义

### 2.1 Batch vs Lot vs Supplier Batch

| 术语 | 定义 | 用途 | 示例 |
|------|------|------|------|
| **Batch (批次)** | 同一时间、同一来源、同一质量的物料集合 | 追踪物料的来源和质量 | 20260910-001 |
| **Lot (批号)** | 同一生产批次的物料集合 | 追踪生产过程 | L20260910 |
| **Supplier Batch (供应商批次)** | 供应商提供的批次号 | 追踪供应商 | SB-20260910 |

**关键区分**：
- **Batch** 是通用概念，指同一批物料
- **Lot** 通常指生产批号
- **Supplier Batch** 是供应商提供的批次号

### 2.2 Expiry vs Production Date vs Shelf Life

| 术语 | 定义 | 用途 | 示例 |
|------|------|------|------|
| **Production Date (生产日期)** | 物料生产的日期 | 计算过期日期 | 2026-09-01 |
| **Expiry Date (过期日期)** | 物料过期的日期 | 判断是否过期 | 2026-12-01 |
| **Shelf Life (保质期天数)** | 物料的保质期天数 | 计算过期日期 | 90 天 |

**关系**：
- Expiry Date = Production Date + Shelf Life
- 或: Expiry Date 直接记录

## 5. 批次/保质期属于 Inventory Fact 还是独立关系？

### 5.1 分析框架

| 概念 | 是否 Inventory Fact 的属性 | 是否独立关系 | 理由 |
|------|---------------------------|--------------|------|
| **Batch** | ✅ 是 | ❌ 否 | 批次是库存的维度，不是独立实体 |
| **Production Date** | ✅ 是 | ❌ 否 | 生产日期是库存的属性 |
| **Expiry Date** | ✅ 是 | ❌ 否 | 过期日期是库存的属性 |
| **Shelf Life** | ❌ 否 | ❌ 否 | 保质期是物料属性，不是库存属性 |
| **Supplier Batch** | ⚠️ 视业务 | ⚠️ 视业务 | 可能是采购订单的属性 |

### 5.2 批次作为 Inventory Fact 的属性

```
┌─────────────────────────────────────────────────────────────────┐
│                     Batch 作为 Inventory Fact 属性              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Inventory Fact = Material × Location × Batch → Quantity        │
│                                                                 │
│  示例:                                                           │
│  ├── 可乐330ml × 中央仓 × 20260910-001 → 100 瓶               │
│  ├── 可乐330ml × 中央仓 × 20260901-002 → 50 瓶                │
│  └── 可乐330ml × 门店A × 20260910-001 → 20 瓶                 │
│                                                                 │
│  关键特性:                                                       │
│  ├── 批次是库存的维度，不是独立实体                             │
│  ├── 同一批次的物料可能在不同位置                               │
│  ├── 批次信息随库存变动而变动                                   │
│  └── 批次是 Inventory Fact 的属性                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 批次作为独立关系

```
┌─────────────────────────────────────────────────────────────────┐
│                     Batch 作为独立关系                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Batch (独立实体)                                                │
│  ├── batch_id (PK)                                              │
│  ├── batch_no                                                   │
│  ├── production_date                                            │
│  ├── expiry_date                                                │
│  ├── supplier_id                                                │
│  └── ...                                                        │
│                                                                 │
│  Inventory Fact                                                  │
│  ├── material_id                                                │
│  ├── location_id                                                │
│  ├── batch_id (FK → Batch)                                     │
│  └── quantity                                                   │
│                                                                 │
│  问题:                                                           │
│  ├── 增加查询复杂度 (需要 JOIN)                                 │
│  ├── 批次信息可能冗余                                           │
│  └── 餐饮场景下，批次通常不需要独立管理                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.4 推荐方案

| 方案 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| **方案 A: 作为 Inventory Fact 属性** | 餐饮 ERP | 简单、直观、查询快 | 批次信息可能冗余 |
| **方案 B: 作为独立关系** | 复杂供应链 | 灵活、可扩展 | 复杂、查询慢 |

**推荐方案 A**：餐饮 ERP 场景下，批次作为 Inventory Fact 的属性更合适。

## 9. 结论

### 9.1 核心结论

| 结论 | 说明 |
|------|------|
| **Batch 是 Inventory Fact 的属性** | 批次是库存的维度，不是独立实体 |
| **Production Date 是 Inventory Fact 的属性** | 生产日期是库存的属性 |
| **Expiry Date 是 Inventory Fact 的属性** | 过期日期是库存的属性 |
| **Shelf Life 是物料属性** | 保质期天数是物料的属性，不是库存的属性 |
| **不需要 Batch 作为独立关系** | 餐饮场景下，批次不需要独立管理 |

### 9.2 餐饮场景建议

| 建议 | 说明 |
|------|------|
| **保持当前实现** | inventory 表的 batch_no, production_date, expiry_date 已满足需求 |
| **根据物料类别决定必填性** | 生鲜类必填，其他类别可选 |
| **不需要 Supplier Batch** | 餐饮场景下，供应商批次号通常不需要 |
| **不需要 Batch 作为独立关系** | 餐饮场景下，批次不需要独立管理 |

### 9.3 迁移路径

**短期（保持现状）**：
- 承认当前系统的 batch_no, production_date, expiry_date 已满足需求
- 根据物料类别决定字段的必填性

**中期（优化查询）**：
- 新增过期预警功能
- 新增 FIFO 排序功能

**长期（可选扩展）**：
- 如果业务需要，新增 Supplier Batch 字段
- 如果业务需要，新增 Batch 作为独立关系
