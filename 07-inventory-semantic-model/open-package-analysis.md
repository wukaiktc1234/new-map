# 拆包分析 (Phase 16 - Open Package Analysis)

## 核心问题：拆包是否需要独立的语义模型

> 整箱采购 → 开箱 → 单瓶库存 → 部分使用
> 是否需要 Packaging State、Open Quantity、Opened Package？
> 这是核心库存语义，还是未来可选能力？

**关键约束**：
- 不要因为"以后可能需要"就强行加入核心模型
- 必须从业务需求角度分析
- 分析这是核心库存语义，还是未来可选能力

## 4. 拆包语义的归属分析

### 4.1 拆包属于 Inventory Fact 的属性还是独立关系？

| 概念 | 是否 Inventory Fact 的属性 | 是否独立关系 | 理由 |
|------|---------------------------|--------------|------|
| **Packaging Unit** | ❌ 否 | ❌ 否 | 包装单位是物料属性，不是库存属性 |
| **Packaging Relationship** | ❌ 否 | ⚠️ 视业务 | 包装关系可能是物料属性，也可能是独立关系 |
| **Open Package** | ❌ 否 | ⚠️ 视业务 | 拆包操作可能是 Movement，也可能是独立操作 |

## 5. 推荐的拆包模型

### 5.1 核心原则

| 原则 | 说明 |
|------|------|
| **Packaging Unit 是物料属性** | 包装单位是物料的属性，不是库存属性 |
| **Packaging Relationship 可选** | 包装关系根据业务复杂度决定是否需要 |
| **Open Package 是 Movement** | 拆包操作是库存变动，通过流水记录 |
| **Partial Use 是 Movement Result** | 部分使用是库存变动的结果，不存储为状态 |

### 5.2 推荐的拆包模型

```
┌─────────────────────────────────────────────────────────────────┐
│                  推荐的拆包模型                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  物料属性 (Material Attribute)                                  │
│  ├── unit_of_measure: 基本单位 (瓶、个、包)                    │
│  ├── packaging_unit: 包装单位 (箱、包)                         │
│  └── package_conversion: 包装转换系数 (1箱=12瓶)               │
│                                                                 │
│  Inventory Fact                                                 │
│  ├── material_id: 物料ID                                       │
│  ├── location_id: 位置ID                                       │
│  ├── quantity: 库存数量 (基本单位)                             │
│  └── batch_no: 批次号 (可选)                                   │
│                                                                 │
│  Movement (拆包操作)                                            │
│  ├── movement_type: OPEN_PACKAGE                               │
│  ├── source_unit: 大包装单位                                   │
│  ├── source_quantity: 大包装数量                               │
│  ├── target_unit: 小包装单位                                   │
│  └── target_quantity: 小包装数量                               │
│                                                                 │
│  Movement Result (部分使用)                                     │
│  ├── movement_type: SALE / CONSUMPTION                         │
│  └── quantity: 使用数量 (基本单位)                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 数据模型建议

```sql
-- 物料表扩展

-- 示例数据
```

## 6. 餐饮 ERP 场景下的拆包方案

### 6.1 简单方案 (推荐)

```
┌─────────────────────────────────────────────────────────────────┐
│                     简单方案 (推荐)                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  核心思想:                                                       │
│  ├── 库存数量使用基本单位 (瓶、个、包)                         │
│  ├── 包装关系作为物料属性存储                                  │

│                                                                 │
│  缺点:                                                           │
│  ├── 无法追踪拆包过程                                           │
│  ├── 无法追踪部分使用                                           │
│  └── 无法支持复杂的包装管理                                     │
│                                                                 │
│  适用场景:                                                       │
│  ├── 餐饮 ERP (大部分场景)                                     │

│  └── 简单的进销存系统                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 8. 结论

### 8.1 核心结论

| 结论 | 说明 |
|------|------|
| **Packaging Unit 是物料属性** | 包装单位是物料的属性，不是库存属性 |
| **Packaging Relationship 可选** | 包装关系根据业务复杂度决定是否需要 |
| **Open Package 是 Movement** | 拆包操作是库存变动，通过流水记录 |
| **Partial Use 是 Movement Result** | 部分使用是库存变动的结果，不存储为状态 |
| **Packaging State 不需要** | 餐饮场景下，不需要存储包装状态 |
| **Open Quantity 不需要** | 餐饮场景下，不需要存储拆包数量 |
| **Opened Package 不需要** | 餐饮场景下，不需要存储已拆包信息 |

### 8.2 餐饮场景建议

| 建议 | 说明 |
|------|------|
| **使用简单方案** | 餐饮场景下，简单方案已满足需求 |
| **库存数量使用基本单位** | 库存数量使用瓶、个、包等基本单位 |
| **包装关系作为物料属性** | 包装转换系数作为物料属性存储 |
| **拆包操作通过 Movement 记录** | 拆包操作作为 Movement 记录流水 |
| **不存储 Packaging State** | 不需要存储包装状态 |
| **不存储 Open Quantity** | 不需要存储拆包数量 |
| **不存储 Opened Package** | 不需要存储已拆包信息 |

### 8.3 迁移路径

**短期（保持现状）**：
- 承认当前系统无拆包支持
- 通过应用层手动转换包装单位

**中期（引入简单方案）**：
- 新增 packaging_unit、package_conversion 字段
- 新增 OPEN_PACKAGE Movement 类型
- 库存数量统一使用基本单位

**长期（可选扩展）**：
- 如果业务需要，引入复杂方案
- 支持多单位库存管理
- 追踪拆包过程和部分使用
